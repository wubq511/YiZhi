# 整课历史恢复

顶栏「整课历史恢复」从实际正式历史中选择时间点、提交前后和知识单元范围。它是独立的恢复路径；单元旧版取回、编辑器 Undo、独立备份各使用自己的入口。确认前显示必要一致范围、前后内容差异、固定来源版本和有效草稿数量。

布局和掌握状态均默认不选。显式选择时只恢复所选单元的这两类状态；个人笔记、图形、阅读现场、学习对话与新导入资料保持当前记录。旧数据库尚未记录的历史用户状态明确拒绝恢复，可改为只恢复课程内容。布局一致组涉及的邻居不自动选中该邻居后来独立的正文或个人状态。

恢复使用现有对象历史构造目标投影，不执行旧命令，也不创建周期性整课数据库副本。当前内容、恢复前状态和本次前后差异进入正式历史；恢复本身可继续作为历史时间点查看。只有涉及实际受支持对象的范围可恢复；尚未整合的 `unit:`、`graph:`、`theme:` 生命周期对象会使整个组明确失败，不能静默略过。

正文、所选用户状态、新单元修订、课程 generation、旧任务资格撤销、草稿退休引用、正式历史、事件和操作回执在同一 SQLite 事务内提交。session、编辑保护、实验堆和计时器在 COMMIT 后切换。应用重建整套画板输入通道；新 B 编辑器通过 `UnitInputHandle.ready()` 等待真实挂载。旧 session 的正文、草稿、笔记、布局、来源和运行现场保存不能进入新代际。

旧任务必须核对实际执行结果，再明确继续并重读新内容。旧工具回执、executor 终态和已发送 delivery 的迟到结果仍按原 task/attempt/generation 记录；这些事实不恢复旧写资格。旧事件游标、操作身份、来源目录及固定资源不会倒退。

恢复前最新有效正文/公式草稿以原 `drafts` 行保留，通过独立入口只读查看。新代际的活动草稿列表排除它们，不能自动晋升旧输入。个人内容仍按原身份保留。

结果未知或执行中断后，UI 保留原 operationId 和最小 permit，先查询结果，再由用户明确重试。`course_restore_requests` 在正文事务之前持久绑定操作 ID 的 digest、generation 和时间；失败、进程死亡或重开均不能更换范围，也不能将 ID 用于另一个写域。成功回执在 `cg_candidates`，正式差异在 `cg_history`；重复应用返回原结果，课程只前进一次。

公共接口是 `CourseService.courseRestore.preview/apply/query/drafts`，类型见 `src/course-restore-api.ts`。历史清理消费者须保留原操作去重事实、`course_sessions` 路由、`retired_drafts` 指向的原输入及依据、仍可恢复的 `restore_timeline` 对象历史，以及被当前内容/个人原语境引用的来源。它们不构成另一套通用版本控制系统。

回归在 `tests/course-restore.test.ts` 和 `tests/course-restore.spec.ts`，使用一次性课程。Core 覆盖真实 SQLite 最终历史写入故障、COMMIT 前后独立进程 SIGKILL/重开、原 ID 重试和真实 parser 迟到结果。Electron UI 覆盖未完成 MathLive 草稿、失败/重启/显式重试、实际 B Worker 延迟与旧通道回调、新键盘输入及真实宿主协议 turn 中断。协议 fixture 不是真实模型执行器验收；物理 IME、完整课程与打包不在这些测试声明内。
