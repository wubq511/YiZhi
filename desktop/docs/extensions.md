# One offline course extension

T13 delivers only the authored `parity-lab` package: three declared input bits (1.0.0), a compatible state schema adding the population count (1.1.0), and a four-input incompatible definition (2.0.0). It does not accept user URLs, arbitrary script paths, npm dependencies or arbitrary programs. The reading entry is “奇偶校验扩展实验” in the first independent course unit. It is separate course content; the original reading payload and editor are preserved.

`src/extensions-api.ts` is the public CourseService boundary. `open/read/act` are available to the trusted application renderer through checked main-frame IPC. `resource` and `recoverExtensionRenderers` are host-only. Generated frames receive neither this preload nor a command port to Core, Agent, filesystem or SQL.

## Saved package and scene

Every prebuilt manifest explicitly records package/interface/input/state versions, ordered input names, editable fields, entry, whole-manifest content digest, per-resource SHA256/length/media type, license and migration sources. HTML, CSS, browser Worker, frame controller and MIT license are published as complete immutable resources, fsynced before SQLite references are registered. The course-owned manifest is in `extension_packages`; no browser cache or original installation path is needed to read a registered package. Each resource is checked again before serving. `generate.py` is a build-time authoring helper, never invoked at runtime. There are no third-party package dependencies in these extension bytes.

`extension_scene` separates the current definition, pending definition, actually adopted definition/instance/generation, latest input intent and complete confirmed model scene. The scene is exactly inputs, step, simulation time, seed, parity output, and (only for state schemas 2/3) population count. No DOM, heap, timer deadline or thread stack is saved. New input persists before its browser computation is accepted; it immediately advances revision and invalidates an old step or migration. Confirmation requires the exact instance, generation, definition and revision and the latest declared inputs. Fields/ranges, finite output oracle, complete step/time and seed are checked in Core without executing package code.

`extension_operations` stores immutable request digests and original receipts. Scene, common `save_events` event and receipt commit together under the actual FULL SQLite transaction. Failed writes never change the live confirmed scene; exact retries preserve identity. Shared operation identities cannot be stolen across editor, command groups, sources, parsing, Agent, built-ins and extensions. Old receipts can be queried by exact retry but cannot relabel a newer scene. Installed manifests/resources, current and pending definitions, and versions referenced by receipts are retention/backup roots; this ticket adds no unsafe shared-resource garbage collection.

## Execution, checks and pause

A different-origin `yizhi-extension://package` frame uses `sandbox="allow-scripts allow-same-origin"`. Same-origin access is allowed only within that extension origin so its dedicated browser Worker can load; it is never the application's origin. CSP allows only its registered scripts/Worker/styles, with no connect, frame, object, form or media sources. The host denies new windows and non-package child navigation. The protocol on the same Electron session serves only registered bounded filenames, current course session and the three versions, with no path translation or remote fetch. Every reply checks exact WindowProxy source, origin, random request, instance, definition and runtime generation.

The application control layer calls initialize, one bounded step, pause, resume, snapshot and dispose; the finite browser Worker performs the generated algorithm. No code executes in the trusted Node Core. Each step advances exactly 250 simulated ms and one step, with no wall-clock catch-up. Size messages obey the same identity/source checks and clamp intrinsic frame heights to 105–480 world pixels; the existing ReadingSurface ResizeObserver incorporates them into local measurements without replacing the active editor DOM. Actual camera intersection, active unit/zoom and document visibility stop issuance, await in-flight completion/discard, and confirm pause. Explicit background choice is required for offscreen running. Normal close drains pending input and complete pause. This package has no animation, audio, media or independent simulation timers.

Before a new definition becomes usable, the trusted renderer executes every finite minterm in the actual sandbox Worker, compares the outputs to an independent literal parity truth table, and verifies nonzero-step pause/snapshot/resume plus the declared compatible migration. Core checks that finite report and each confirmed learning result. Hash/schema validity alone cannot enable the package. Incomplete or failed checks retain a needs-check scene with no usable output.

The responsive frame controller can terminate an unanswered browser Worker; the application removes that frame and reports “暂停未完成”. The student's recovery action revokes generation and constructs a new runtime from the latest confirmation. Saved input intent remains available. Destroyed or migrated instances cannot publish into the replacement.

## Definition changes and renderer failure

The two update controls are explicitly labeled as the course's prebuilt definition demonstrations. They exercise the same CourseService definition contract; they are not a general package installer or a claim of real Agent modification execution. A definition is saved independently. During a pointer/key operation no instance switches. After the operation, a separate hidden target frame restores/migrates a copy. The Core rechecks revision/input/gesture/definition eligibility and atomically commits the new version reference and scene before the application replaces the old frame. Concurrent input invalidates that copy. Failed/incompatible migration keeps the old scene and old version label, asking only whether to restart explicitly. Reopening preserves both the adopted version and pending conflict.

The host handles native `unresponsive` and has an independent application-menu “恢复无响应窗口” entry. After the student chooses recovery it revokes all old extension identities, forcefully terminates the unusable renderer and recreates the learning window with its previous bounds in a new process. Core, actual Agent runtime/draining and parser tool ownership stay with the host. Already persisted editor content/drafts and extension snapshots reload through their normal boundaries. This cannot recover input that never reached a durable draft confirmation.

Relevant primary APIs: [Electron webContents](https://www.electronjs.org/docs/latest/api/web-contents), [Electron protocol](https://www.electronjs.org/docs/latest/api/protocol), [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe), [Worker terminate](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate). iframe/sandbox do not promise separate CPU processes. The recovery test uses Chromium's documented [site isolation test opt-out](https://www.chromium.org/Home/chromium-security/site-isolation/) to reproduce a shared-renderer failure; production does not set that switch. The recovery fixture runs an actual Electron child without Playwright/CDP attachment, so its native hang monitor remains enabled. A real infinite generated DOM loop causes the native unresponsive event; no synthetic event is emitted.
