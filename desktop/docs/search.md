# Offline search

`CourseService.search` / the restricted `window.yizhi.search` bridge expose `query`, `status`, `rebuild` and `locate`. These run in the incumbent shared Core Worker and course SQLite connection. No network, executor or semantic model is needed.

The four scopes project the actual authority: `units` plus delivered immutable sample bodies, `personal_notes`, `agent_messages`, and registered immutable source originals via `Sources.page`. The current shared `readUnit` resolver is reused. Catalog-only units are reported as unavailable; catalog source metadata is not presented as readable originals. Unknown/retained JSON, question metadata not rendered by the reader, composer drafts and tool recovery dumps are excluded. Known fields use the same actual reader disclosure path, including exercise answers and hints. Aliases are visible with the unit header.

`version` records the formal unit revision plus body digest (immutable sample digest where no mutable row exists), actual note version, saved message content/state digest, or original resource SHA-256. Every hit includes its entity, field, block/disclosures or note/conversation/message identity; original hits also carry source/version/PDF page and exact PDF.js projection convention/digest/extractor. `text`, `quote`, `start` and `end` describe the unchanged projection in Unicode code points. Matching preserves case, spaces, superscripts and operators: no compatibility, case, punctuation or algebraic normalization. Words of at least three code points use quoted parameterized FTS5 trigram queries; short words and punctuation/symbol queries use literal matching. Search never generates an explanation or creates a personal note/source citation.

`search_entities`, `search_documents` and `search_fts` are disposable derived data. SQLite triggers mark the affected entity dirty and advance its epoch in the **same authoritative transaction**, for insert/update/delete. Old epochs cannot appear through the index. A fresh database backfills identity rows only; opening a course never rebuilds all text. Each rebuild request accepts 1–8 entities (default 4), and at most one original page per source per batch. PDF reads yield outside the ordered save queue; close drains pending reads. Concurrent rebuild batches are rejected explicitly. Renderer background work yields between batches and leaves search/input enabled.

A query supplements indexed results with at most 16 pending entities, at most 262144 code points, and at most two unindexed original pages. It deduplicates projections, caps results at 50 (API maximum 100), reports truncation and **incomplete coverage**, and rechecks authorities after asynchronous original reads. It does not promise to scan every pending object before indexing. Pending, failed index writes, unavailable catalog bodies, unreadable originals, no-text pages and checked-range no-hit are separate states. Index write failure leaves the authority directly searchable. One bad original cannot fail the other scopes. The existing exact-hash source repair followed by retry/rebuild restores search. No OCR is implied.

`locate` re-derives the actual authority projection and rejects changed versions/ranges. The renderer checks its displayed field again, expands the real material/answer path and highlights the actual block/field. Formula offsets remain offsets in the exact LaTeX search projection; they are never passed off as MathLive model positions. Note and message results open their actual editor/conversation; source results use an ephemeral reader highlight at the immutable original page without manufacturing a citation. Before opening search, the UI captures the reading camera, disclosures, native selection/focus, panel identities and scroll state. “返回搜索前位置” restores that scene; input save failures remain barriers.

Validation: `tests/search.test.ts` runs against the real public CourseService/Worker/SQLite in both external Node and embedded Electron. `tests/search.spec.ts` exercises the actual preload/host IPC, offline reader, notes, durable messages, originals, narrow focus isolation and return navigation. UI runs must use the integration's native UI serialization wrapper. Tests use disposable course directories; no original course or personal database is written.
