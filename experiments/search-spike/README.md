# 中文与公式检索实验

2026-10-27。结论：**FTS5 默认分词不能直接替换当前字面子串搜索。** 在本次指定查询中，trigram 加短词回退保持相同命中集合；是否用于正式索引仍需比较资料全文、长对话、更新一致性和成本。

## 输入与方法

- 读取既有 [fixture.json](../architecture-spike/fixture.json)，含 84 个真实知识单元及 1,215 个正文块；没有重新读取权威知识文件或个人数据库。
- 每单元的导出元数据与每正文块 payload 分别形成文档，使用 Python `casefold()` 统一字面大小写。84 单元为 1,299 个文档；重复到 500 单元后为 7,732 个文档。500 场景不是 500 个不同知识单元。
- 基线是同一投影中的 Python 字面子串包含，符合现有搜索的主要匹配语义，但没有复制正式服务的全部范围、排序和结果去重。
- SQLite 分别建立 external-content 的 unicode61、trigram 索引，参数化传入带引号的字面查询；组合方案对短于 3 个 Unicode 字符的查询用 `instr` 子串回退。
- 17 条查询覆盖单字、二字、长词、器件及别名、英文、公式片段和无结果项；比较完整文档 ID 集合。另删除并重建 trigram 索引，检查结果一致。

## 实际结果

本机 Python 3.14.6、SQLite 3.53.3、macOS 27.0.1 arm64。两个规模的差异查询数相同：

| 方案 | 与字面子串基线不同的查询数／17 | 结论 |
| --- | ---: | --- |
| unicode61 | 13 | 中文词片段有漏召回；公式符号丢失可产生额外命中 |
| trigram | 6 | 六条一字／二字查询均无命中 |
| trigram＋短词回退 | 0 | 本次指定查询的命中集合全部一致 |
| 删除并重建 trigram 索引 | 0 | 重建前后本次查询结果全部一致 |

以下为 84 单元场景中的**文档命中数**，不是知识单元数量：

| 查询 | 子串 | unicode61 | trigram | 加短词回退 |
| --- | ---: | ---: | ---: | ---: |
| 门 | 295 | 4 | 0 | 295 |
| 进位 | 142 | 15 | 0 | 142 |
| 与门 | 87 | 15 | 0 | 87 |
| 卡诺图 | 55 | 4 | 55 | 55 |
| 74LS138 | 10 | 10 | 10 | 10 |
| MUX | 41 | 39 | 41 | 41 |
| A+B | 102 | 294 | 102 | 102 |
| A⊕B | 21 | 294 | 21 | 21 |

`A+B` 与 `A⊕B` 的差异说明，公式中的符号具有实际检索意义；不能仅用英文单词或文档数量验收替换后的索引。原始逐项结果、fixture 与脚本 SHA-256 在 [results.json](results.json)。

## 复现与边界

从项目根目录运行：

```sh
python3 -B docs/复习工具调研/04-演示/search-spike/probe.py
```

需要 Python 链接的 SQLite 支持 FTS5 与 trigram；脚本不安装依赖。全部实验数据库位于临时目录，正常和异常退出均由上下文清理；只保留脚本和结果文件。

本次没有评估排序相关性、词法分词、同义词／错别字、全部 Unicode 边界、资料全文或个人对话；没有保存延迟、并发修改、耐久性或跨平台性能结论。索引恢复仅验证由完整来源表重建，不能代替实时增量维护和版本定位验证。

依据：[SQLite FTS5](https://sqlite.org/fts5.html#tokenizers)、[trigram 行为](https://sqlite.org/fts5.html#the_trigram_tokenizer)、[external-content 索引](https://sqlite.org/fts5.html#external_content_tables)。总体取舍见[后端存储方案调研](../../docs/research/architecture/后端存储方案调研.md)。
