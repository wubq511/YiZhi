## 算法与取舍

1. 预测量只作未挂载时的估计。动态 article 自然增高，`ResizeObserver` 读取 border box，按帧合并反馈，更新 React Flow 外壳高度与裁剪范围。卸载正文时保留最近测量，壳体不缩回摘要高度。
2. 基线与阅读投影分别保存。按基线 y 排序，仅水平区间相交的前序对象施加向下约束，间隔 40 个画布像素；不改变列坐标、不重新生成知识顺序。收起从当前基线重新计算，不恢复旧快照。
3. 拖动以拖动前投影为参照，只把实际手势位移合入当前基线，不把展开产生的临时位移固化。拖动期间暂停投影提交、积累测量，松手后解算。**按住拖动时可能暂时重叠；本次验证手势控制权及释放后的无重叠，不保证拖动期间无重叠。**
4. observer 回调不直接写布局，下一帧才更新外壳；自然 article 的高度不依赖外壳高度。尺寸取整并忽略不足 1px 的变化，防止测量—写入反馈循环。
5. 相机统一处理用户操作与布局补偿。输入／选文／点击记住实际 DOM 阅读位置，投影后补偿屏幕坐标差，保留缩放。导航使旧锚点失效；离屏正文挂载反馈新高度前，锚定可见目标标题。后到的用户 wheel／pointer 使过期补偿失效；补偿不会重新获得 Agent 跟随权。

最小实现每次仍扫描 500 个基线对象，最坏 O(n²)，只写尺寸／投影确有变化的节点。“局部”表示碰撞约束和位移影响范围，**不表示已有空间索引或仅遍历局部节点**。同列冲突链可能传播很远，本轮确实移动了 59 个邻居。

### 负载如何保证有效

- 500 个合成对象、`managed`、`dynamic=1`；仍由 84 个真实单元复制生成。
- 独立 `setInterval(50ms)` 向既有 `probe.emit` 发送真实首段文本补丁。每两次更新增加一次原段落重复数，每次也修改序号；没有把更新节奏绑到可能变慢的 rAF。包含既有 localStorage 写入和增量呈现成本，不是孤立解算函数微基准。
- rAF 持续调用既有 `probe.setViewport`：x=95±110px、y=35±75px、zoom=.7±.025，以局部正弦轨迹连续移动，不做跨图跳转。最大相邻相机位移仅 5.30px。
- 1.2／2.6／4.1／5.8 秒对同一份既有材料执行原生 `HTMLSummaryElement.click()`，实际展开／收起完整内容。四次反馈均测到约 ±458.91px 的自然高度变化。这里是 DOM 原生激活，不伪称物理鼠标点击。
- 每帧及每次更新监测同一正文／段落的连接与 DOM 身份，250ms 采样核对真实矩形与视口交集；整个负载始终挂载、在视口内，身份违规为 0，140 个补丁均实际进入目标段落。
- 直接使用现有 probe 的 rAF／longtask 统计；额外保存 250ms DOM／高度／计数时间线、每次补丁的时间与耗时、原生展开事件和原始 longtask 记录。不启用 CPU tracing，不在计时期间执行全图两两碰撞检查。采样开销包含在结果中。

### 对 100ms 最大间隔的判断

这次存在一处 100ms 的 rAF 回调空档，不能把 P95=16.7ms 写成“全程无卡顿”。同时，独立更新定时器的最大间隔只有 52.5ms，两个 longtask 观察均为 0，同步 emit 和相机回调的最大值也远小于 100ms。这些证据**不支持直接归因为一次 O(n²) JavaScript 解算持续独占主线程 100ms**；rAF 的调度、渲染管线或宿主调度等原因没有被此次记录区分，具体空档时刻和调用栈亦未采集，不能擅自归因给某一层。

本轮未见持续帧间隔恶化或 ≥50ms 主线程长任务，且实际约 20Hz 更新和真实尺寸投影都发生了；但单次 7 秒、headless、单机结果不足以证明物理输入流畅，也不足以证明该 O(n²) 算法可扩展或已经达到产品验收。保留此异常作为后续候选比较的证据，没有设置新的硬 FPS 门槛，也没有为追求数字继续修改或无限优化 source。本次没有足够证据仅凭这一空档否决算法，同样没有证据免除后续规模与实机比较。

## 遇到的失败与修正

- 首次脚本裸读尚未创建的 probe，出现 `ReferenceError`；改用 `window.probe?.ready` 等待。
- 首次拖动失败时，手柄实际在 y≈9,200px，继续增长后到 y≈12,784px，没有接到真实拖动。离屏更新先保存内容，返回才挂载反馈新高度，按旧估计定位的邻居被挤出视口。导航清除旧锚点，并在反馈前锚定可见目标后，最终按住手柄在增长期间保持 y=292px。
- 最初把拖动后的绝对投影写成基线，带入临时位移，收起检查有约 58px 偏离。改为基于拖动前投影只合入手势位移，最终真实 DOM 与最新基线一致。
- 首次延迟图片取错子目录，生成 `source-pages/undefined`，404／解码失败。改为递归取真实原页文件，最终请求和 decode 成功，没有忽略错误。
- 双对象展开最初前一份正文已按裁剪规则卸载；直接缩放还曾把目标移出视野。改为保持目标世界位置的缩放和定位，.3 下真实同时挂载、展开两份正文并通过检查。
- 跨列检查曾把 567px 鼠标轨迹直接当成 810px 世界位移；React Flow 拖动启动阈值／事件采样使实际位移约 751.43px。最终检查真实 DOM 到达相邻列范围、释放后无重叠，并报告真实坐标，不伪报精确 810px。

以上失败已修正，没有把已失败路径移入“未验证”掩盖。

## 剩余边界

- 固定 680px 宽度、按基线 y 排序、仅向下让位。未证明主题／分组语义、任意自由布局、动态宽度、循环约束、障碍物绕行或全局最优。横跨两列会约束两列，极端增长可能传播整条链。
- 按帧收敛与补偿不保证每个中间帧都无重叠或完全无闪动；按住拖动期间优先保留手势控制。没有真实显示器录像或跨设备流畅度验收；新增 7 秒并发场景仅覆盖本机 500 managed 负载，不构成 O(n²) 渐进复杂度或更大规模的性能证明。
- 未挂载／未见过的正文仍用估计；离屏更新不预挂载全量正文。已覆盖返回时的反馈和导航稳定性，不表示能提前精确知道未知离屏高度。
- 仅验证当前 DOM 生命周期的阅读锚点；未实现跨结构改写的持久语义锚点、批注区间迁移、关系线绕行。React Flow 更新端点不等于线路已专项验收。
- 未接入真实 Agent、CourseService、SSE、正式提交冲突、服务端学生同块编辑保护或崩溃恢复。本地草稿不等于正式存储耐久性；手动布局基线仅在本次页面会话保存，未承诺跨刷新恢复。
- 原生中文 IME、复杂公式编辑光标、真实鼠标／触控板手感、Safari／Firefox、窄屏、任意生成实验均不在本轮覆盖范围。延迟资源只代表此次真实原页和嵌套分式案例。
