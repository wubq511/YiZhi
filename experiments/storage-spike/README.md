# SQLite 权威内容与不可变资源：隔离存储实验

2026-10-27。**本范围最终 136 条断言通过，支持继续优先验证 B（统一 SQLite 权威数据＋外置不可变资源），不构成正式选型、迁移或生产验收。** Python 标准库 `sqlite3` 只是实验工具，不据此选择正式后端语言。没有 A 的同条件实现与实测，不声称 B 比 A 快。

本次仅新增本目录文件，没有导入正式 Service、启动正式 Agent、调用模型、读取个人数据库或真实对话，也没有安装数据库服务。独立桌面、当前 macOS 打磨、后续 Windows 必做的产品前提不变。窗口关闭与程序退出的生命周期由桌面协调层负责，本实验只验证持久化门禁，不把进程故障模拟当作桌面生命周期验收。

## 最小 schema 与提交边界

`units.body` 保存真实单元的完整 JSON 形状，包括嵌套 `reading.blocks/children`、`payload`、引用、coverage 和单元内关系。SQL `revision` 是本实验提交账本版本，fixture 原有 `reading.revision` 原样作为内容字段保留；这不是最终双版本 API 设计。

| 表 | 职责与关联 |
| --- | --- |
| `meta` | 稳定课程 ID、schema 版本、课程 generation |
| `units`、`revisions` | 当前权威单元；不可变历史全文，按 `(unit,revision)` 关联，初始修订无 operation |
| `drafts` | 编辑会话、单元/块、输入 seq、epoch、基线 hash、输入原文、active；未完成公式也可保存 |
| `notes` | 独立笔记 ID、原块、原修订、原语境；外键到原修订，不自动跳到新正文 |
| `layouts`、`messages` | 独立布局基线；合成对话按 UTF-8 字节偏移追加，拒绝错误偏移 |
| `tasks`、`attempts` | 当前 attempt、任务状态、持久提交资格、attempt 状态和已提交组计数 |
| `read_sets` | 记录实际读取的块 hash 与草稿会话/seq/epoch/active；绑定 task/attempt；成功时关联 operation |
| `resources`、`resource_uses` | SHA-256、相对路径、长度；引用绑定内容修订，旧修订的资源引用可保留 |
| `operations`、`history` | 唯一 operation ID、规范化完整请求 hash、请求/回执；持久游标及修订变化关联 |

`BEGIN IMMEDIATE` 内先查 operation，再核对 generation、当前 attempt 资格、readSet 和学生草稿，随后一起写正文、修订、草稿/笔记、资源登记/引用、attempt 提交状态、readSet 使用记录、history 和回执，最后 `COMMIT`。不依靠进程内锁排序。提交成功才返回 `saved=true`；`kind=draft` 与 `kind=group` 分开表达，草稿确认不冒充正文已更新。拒绝命令回滚，不留业务回执，也不把错误伪装成已保存。

同 operation、相同规范请求返回原回执，即使 attempt 已停止/完成；同 ID 不同 payload 拒绝。这里保证业务提交去重，不保证外部执行 exactly-once。readToken 是适配器生成的持久读取记录，不从 Agent 自称的读取列表推断完整依赖；本实验没有 Agent，测试驱动明确列出输入。

不可变资源由合成 UTF-8 字节生成，先写独占临时文件、`flush/fsync`，通过硬链接独占发布为摘要文件，再同步资源目录并核验实际字节，之后才登记 SQL 引用。已有摘要文件不覆写。**文件与 SQLite 不是同一个原子事务**：文件完成而 SQL 未提交时允许孤儿，反向顺序不允许。本薄适配器为方便注入，把资源准备放在已取得的 SQL 写锁期间；正式实现应在短登记事务前准备大文件，不能照搬此处锁时长。

## 数据范围与真实故障结果

只读取现有 `architecture-spike/fixture.json` 的 84 个真实单元形状，包含 1,215 个递归块。扩展至 500 个完整单元副本时，保留首批身份，其后给单元/块/关系 ID 加稳定批次后缀，递归重写精确 ID 引用；末尾不足一批的依赖仍可指向原始单元，实际检查所有内嵌关系端点存在。它是体量负载，不是 500 个不同知识主题，也没有重新验证学科内容。

**fixture 内的真实 `sourceRefs` 与 `/source-pages/...` 路径只作为内容字段保留，未读取真实图片/PDF字节，也未打包这些真实素材。** “无引用缺件”断言只覆盖本实验实际登记的合成不可变产物。目录迁移和开放交换通过不等于真实课程全部课件、证据与组件已可移植。

同一个包含两块正文改动、草稿、个人笔记、资源、任务完成和 readSet 关联的命令，在以下三个注入点分别运行 `os._exit(73)` 和父进程 `Popen.kill()`，共六个真实异常退出子进程。每次重开都运行 SQLite integrity/foreign-key 检查、当前正文与修订匹配检查、history/receipt 一一对应检查、登记资源字节与摘要检查。

| 注入点 | 实际观测与断言 |
| --- | --- |
| `before_commit`：全部 SQL 写入后、COMMIT 前 | 所有 SQL 表与运行前快照完全相同；无 saved 回执；完整文件留下一个显式孤儿 |
| `after_commit`：COMMIT 返回后、回执发出前 | 正文/草稿/笔记/修订/任务完成资格/readSet/资源引用/history/receipt 共同存在；客户端没有收到 saved；相同 operation 重试取回原回执且不改任何表 |
| `after_resource_publish_before_register`：文件完成后、任何资源登记前 | 已发布文件存在；所有 SQL 变更回滚；没有登记引用或假 saved；留下一个可识别孤儿 |

每次异常退出后，**先不重开原库，把包含 WAL 的整个临时课程复制到另一目录**；核验原目录后删除原目录，再从新路径恢复，比较所有逻辑表的快照相同。这样没有用一次正常关闭偷偷替代异常退出后的恢复材料复制。孤儿文件保留在临时课程中接受检查，最后随实验目录清理；未实现生产垃圾回收。

## 并发、依赖与个人输入

实际覆盖的合同（每次拒绝还比较全表快照，确保没有暗中改动）：

- Agent 读取 A/B 后只提交 A；学生先改依赖 B：旧 readSet 拒绝，不能靠只保护写入块蒙混通过。
- 学生有效草稿已保存但正文未提交：正文 hash 不变，草稿回执准确；草稿使旧 token 失效；重新读取后仍有 active 草稿也拒绝覆盖。同单元独立 B 的提交可通过，A 的输入保留。输入 seq 相同但内容不同的迟到操作被拒绝；未完成的公式输入可保留。
- 同 operation 重复得到原回执且不新增任何事实；同 ID 不同 payload 明确拒绝。
- 停止后 continue 创建新 attempt；旧 attempt 的新操作仍拒绝，新 attempt 可提交；错误 generation 拒绝。没有因继续而复活旧资格。

停止/提交测试使用两个真实进程和两个 SQLite 连接。第一个进程在 `before_commit` 持有写事务；第二个进程进入实际写锁等待后释放第一进程，记录单调时间证明确实有重叠，并核验第二进程在第一进程 commit 后才取得锁。没有预设“同时”到底谁应该赢。

| 实际顺序 | 结果 |
| --- | --- |
| 停止先占写锁 | 停止提交成功；后续组因 `attempt_ineligible` 拒绝，无正文变更和伪提交回执 |
| 内容组先占写锁 | 正文先提交并保留；停止随后生效；旧 saved 回执可补取；新 operation 再提交拒绝 |

两组第二进程实际锁等待约 67.95/68.53 ms，包含实验人为持锁约 50 ms 和调度，并非正常保存耗时或吞吐指标。这是两个受控竞争顺序，不是随机长时间并发压力测试。

## 目录复制与开放交换

另一份带个人笔记、活动与保留草稿、布局、追加消息、任务、历史、回执和合成资源的 84 单元课程，先显式停止任务、检查 `wal_checkpoint(TRUNCATE)` 返回非 busy，再完整复制并删除原目录。从新目录重开后逐表比较，包括稳定 ID、完整内容和关联，结果一致。

再导出为版本化的 `storage-spike-exchange-1` JSON 表记录和相对摘要资源文件，导入到空库，重新比较所有表。导入检查格式、资源相对路径、长度、SHA-256 与外键；不使用 pickle 或 SQLite 原始页充当开放交换。实际 JSON 3,051,768 bytes，恢复 84 个单元、85 个修订、2 个草稿、1 个个人笔记、1 个布局、1 条消息、1 个任务/attempt、1 份 readSet、5 个操作/history 及合成资源引用。笔记经原修订找到的原块与原语境完全一致。

这只是实验格式：表记录中的正文仍是 JSON 字符串，没有确定生产领域交换 schema、未知版本兼容、恶意/超大导入和中途失败恢复协议；也没有验证跨正式版本升级。导入测试没有中途退出注入，不能因成功往返推定生产导入已具备故障安全。

## 有界真实混合保存负载

实际调用 SQLite 事务，不是估算函数耗时：500 个真实结构单元副本，单个连接连续执行 240 次保存，无思考时间；草稿、布局、合成对话追加、正式内容小组提交各 60 次。每次正式组包含两个单元的块改动。对话共追加 112,473 UTF-8 bytes，不反复重写整段对话。没有真实模型调用、UI 或 IPC，也没有把资源文件发布加入这条负载。

下表是本机本轮单条有界负载，单位 ms。确认区间从命令调用开始至 FULL 提交与回执构造完成，包括请求规范化、适配器校验/写入、正文组的单元 JSON 解析/序列化及可能的 SQLite 自动 checkpoint；**不包括桌面输入调度、IPC、前端呈现和外置资源 fsync**。P50 用中位数，P95 用最近秩 `ceil(0.95*n)`。未设臆造体验阈值。

| 保存类型 | 数量 | P50 | P95 | max |
| --- | ---: | ---: | ---: | ---: |
| 草稿 | 60 | 0.0802 | 0.1531 | 0.3162 |
| 布局 | 60 | 0.0711 | 0.1575 | 5.3353 |
| 追加对话 | 60 | 0.0856 | 0.2663 | 2.5132 |
| 正式内容小组 | 60 | 0.8387 | 1.6866 | 2.6916 |
| 全部 | 240 | 0.0890 | 1.2105 | 5.3353 |

240/240 确认成功、错误 0，实际检查 60 个草稿、60 个布局、120 个新修订、240 个回执以及完整追加偏移。负载墙钟约 0.0912 s、进程 CPU 约 0.0803 s，逐操作数据和每 24 次 DB/WAL 采样保留在 JSON。这里的请求字节是 264,950，不是物理磁盘写入量；未测磁盘写放大、RSS 或每次 fsync 耗时。

| 时点 | DB bytes | WAL bytes |
| --- | ---: | ---: |
| 500 单元初始化后 | 17,506,304 | 0 |
| 240 次保存后、连接仍开着 | 20,361,216 | 4,128,272 |
| 显式成功 checkpoint 后 | 20,582,400 | 0 |

活跃时 DB 增长 2,854,912 bytes，WAL 文件增长 4,128,272 bytes；checkpoint 后 DB 净增长 3,076,096 bytes。WAL 的文件长度不是累计写入字节；每 24 次采样最大值也不代表瞬时高水位。DB 初始同时包含当前正文和初始修订；实验每次正文修改追加完整单元历史，同时操作表保存请求，因此**历史占用仍明显，不能推导长对话/多年历史成本已解决**。两种方案都需要决定语义增量、快照与保留策略。

## 影响选型的实际限制与未覆盖边界

统一事务已经能表达并实际保持本次内容/个人内容/账本合同，不必为正文与 SQLite 再造跨权威存储协调。这支持 B 的一致性方向，但 A 也可能用另一套协议满足合同；这里没有 A 适配器，更没有性能优劣结论。

正式实现仍须补齐以下边界，本次不顺手建设生产管线：

- **桌面生命周期和启动核对**：没有界面进程、后台执行器、真实 Agent、任务租约、外部结果未知核对。重开只读取/检查，没有启动任务，也没有把遗留 `running` 自动转换为 interrupted；关闭学习界面继续、退出程序先撤销资格再终止执行的真实协调尚未验收。停止时保留已提交内容的 SQL 顺序已验证。
- **完整内容与编辑合同**：只修改 payload；没有块插入/移动/拆合/删除、语义校验器、证据支持校验、候选发布流水线、结构读取门禁、学生正式内容 CAS、多编辑会话仲裁或选择性撤回。readSet 的块内部 hash 不等同完整父级/相邻结构版本。错误 generation 的门禁已测，整课恢复提高 generation 尚未实现。
- **真实资料、资源与备份**：未读取或迁移真实来源资源；合成资源仅证明发布/登记顺序。未实现垃圾回收、备份持有资源、在线一致备份、损坏恢复、磁盘满/权限错误、缺失资源后的产品降级。生产导入需先持久准备资源并保证失败清理，不能照搬此处只用于正常往返的导入路径。
- **规模和等待**：性能路径用学生小组提交，不含 Agent readSet/attempt 查询；没有长历史、大二进制、长期读者、持续多写者、队列/重试政策或搜索负载。5 秒 busy timeout 只是实验设置，不是桌面体验设计；不能把约 4 MB 的本次 WAL 长度说成长期有界。
- **Windows**：脚本用标准库 `subprocess`，在顶层清理前关闭全部已登记连接；资源仅使用相对 SHA-256 路径，未依赖原课程绝对路径。Windows 分支跳过 POSIX 目录 fsync，硬链接发布、文件占用、同步语义和异常删除仍须在目标文件系统实测。当前只有 macOS 实际结果，没有把 Windows 算作通过，也没有据 Python 选择正式技术栈。

已通过的范围到此停止扩展；这些产物是后续架构决策的可复查证据，不是正式系统已完成验收的声明。
