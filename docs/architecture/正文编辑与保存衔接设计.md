# 正文编辑与保存衔接设计

2026-10-27 随[系统设计定稿](系统设计定稿.md)整体确认的实施合同。承接已确认的连续编辑、同处输入保护、自动保存、当前会话撤销，以及 Electron／TS＋Worker／SQLite 组合。现有接入和验收边界见[桌面应用说明](../../desktop/README.md)；本文维护设计与证据，不把字段名当作已发布接口，也不新增逐块采纳步骤。

## 结论与尚缺证据

设计要求一个真实知识单元完整走通“输入 → 草稿保留 → 正式提交 → 回执 → 撤销／重开”，同时允许 Agent 更新独立部分。编辑器负责文档内的编辑，课程核心负责持久事实与冲突；双方通过稳定对象和明确的输入进度衔接。

下表保留 2026-10-27 设计时的证据边界；“尚不能证明”只针对列出的隔离研究与实验，不表示对应桌面功能至今未实现。

| 已有依据 | 支持什么 | 尚不能证明什么 |
| --- | --- | --- |
| [编辑事务机制核查](../research/topics/编辑事务与并发现场机制核查.md) | 有范围位置与局部历史映射机制；不必因外部修改清空整个单元的 Undo | MathLive、自定义块、中文输入法与实际保存同时工作 |
| [核心承载实验](../../experiments/core-placement-spike/README.md) | 真实 Node SQLite 短事务、重复操作、回滚和重开；Worker 承载可行 | 连续编辑中较新草稿不会被较早提交清掉、回执不会误报最新输入已保存 |

## 编辑器路线已确定

[正文编辑器候选核查](../research/topics/正文编辑器候选核查.md)比较了直接 ProseMirror、基于它的 Tiptap 开源核心和 Lexical。Robert 已选择 **Tiptap 开源核心＋ProseMirror 范围事务／history＋自定义 MathLive NodeView**，决定见[ADR-0006](../adr/0006-tiptap-prosemirror-mathlive.md)；直接 ProseMirror 保留为已比较方案。下述保存连接须由应用组合验收证明，不能把选型已定当作组合已经通过。

选择依据是所需 ID 扩展、自定义内容入口与范围历史机制可以组合复用，代价是仍需理解 ProseMirror、控制扩展的追加事务，并自行实现公式与核心的衔接。按需引入用得到的扩展，不用厂商 AI、云协作或 Pro 产品替代本产品的课程核心。[Tiptap 与 ProseMirror 的关系](https://tiptap.dev/docs/editor/core-concepts/prosemirror)、[开源 UndoRedo 实现](https://github.com/ueberdosis/tiptap/blob/b27c87410511b6e2e6714fa023ebd8efd8929ce5/packages/extensions/src/undo-redo/undo-redo.ts)

Lexical 默认历史保存并恢复 EditorState 快照。由固定源码可推知：仅跳过 Agent 更新入栈，后续 Undo 仍可能恢复到没有该更新的旧状态，因此它不是当前最直接的路径；这不代表 Lexical 无法定制满足要求，也不是运行实验结论。实际候选还要锁定相互兼容的包版本，不能把研究时各上游 HEAD 直接拼成依赖组合。[Lexical history 固定源码](https://github.com/facebook/lexical/blob/7bc4baaba215b9d2a4edca81493e22c226c50a46/packages/lexical-history/src/index.ts)

## 一套课程内容，多个有明确用途的状态

| 状态 | 保存什么 | 谁决定其含义 |
| --- | --- | --- |
| 正式课程内容 | 稳定块身份、类型、版本化载荷、子结构与引用；按对象保存实际变化 | 课程内容模型与核心校验 |
| 活动编辑文档 | 当前单元的可编辑投影、选区、位置映射及即时 Undo | 正文编辑器；只有正在编辑的范围需要实例 |
| 最新可恢复草稿 | 尚未被正式版本完整吸收的输入、依据、输入序号及必要结构信息 | 编辑适配与课程核心共同确认；不是第二份可独立修改的正式正文 |

正文格式要有明确的 schema 版本、允许类型和转换规则。选定编辑器后，可以在明确字段内使用其适合的 JSON 结构；没有必要为了“未来能换库”再发明一套通用编辑语言。另一方面，DOM、HTML、编辑器运行时 node key、React Flow 场景都不能自行成为课程知识身份。

同一 B 连续编辑不等于把公式、表格、收纳中的题解和复杂实验都变成纯文本。编辑文档必须保留这些内容的结构位置与稳定身份；普通文本支持跨段操作，公式内部和实验继续使用各自控件。未展开／未编辑的内容不能在“导出可见正文”时消失。初期可在进入编辑时读取当前单元所需正文结构，不要求一次读取全课重正文。

对暂不支持编辑的内容类型保留原载荷或不可变引用，呈现为可识别的内容对象；不得静默丢弃。编辑器与课程模型的转换检查至少覆盖普通往返、未展开内容和未知类型保留，不以一张编辑截图代替。

## 稳定身份与编辑动作

| 动作 | 推荐的身份规则 |
| --- | --- |
| 修改文本、格式或移动原块 | 保留原块 ID；移动另记录父级与邻接身份变化 |
| 拆成两段 | 明确一个延续原身份的块，其余新建 ID，并保存能证明的片段对应 |
| 合并两段 | 明确保留目标与退出身份；原批注仍为一份个人记录，按已知对应更新定位 |
| 复制并粘贴 | 新内容获得新 ID，不因复制了编辑器属性而与原块重名 |
| 剪切并移动原内容 | 有可验证的原对象移动语义才保留身份；不能仅凭剪贴板中的 ID 推定 |
| 撤销拆分／删除 | 正文结构与对应身份一起恢复，经课程核心核对当前版本；相关个人记录不被附带删除 |

一次编辑器事务可能跨多个块。适配层输出实际受影响对象、结构变化与依据，不能把整个旧单元重新送回核心覆盖最新内容。稳定 ID 的插件只解决身份唯一性的一部分，不等于已经产生可靠的拆合对应或批注迁移。

批注的永久定位仍按[内容协议](内容演进与实时修改协议.md#批注定位把标住哪句话与画在哪里分开)保存版本、引用与有序片段。编辑器位置只是当前文档的坐标，需要明确与持久文本投影／Unicode 偏移的转换，不能直接当成原文偏移。

## 从一次输入到持久确认

以下名称只表示必要事实；具体方法和载荷可在实现时收敛，避免把每个内部动作暴露成外部接口。

1. **建立编辑上下文。** 读取单元当前正式内容、课程代际和未处理草稿；新会话有独立身份。存在旧草稿时先核对其依据，能对应的恢复，不能对应的保留原文供处理，不能覆盖当前正式内容。
2. **立即接收输入。** 编辑器先响应键入、选择和 Undo。输入序号在该会话中递增；受保护段落／选区及时同步给核心。自动保存无需等待离开段落；离开只关系到同处 Agent 更新进入现场的时机。
3. **合并待保存输入。** 同一会话的保存通道有界、按序处理。尚未发出的输入可合并为最新待处理状态，但必须包含前面仍未确认的变化，不能只保留最后一次按键。多个脏块及拆合结构都要保留。
4. **保留草稿，自动提交完整修改。** 核心校验会话、代际、输入序号和版本依据。未完成公式等输入可以先保留为草稿；成立的修改自动形成正式变更组。允许在同一次调用／短事务中完成两项，不要求每次输入固定写两遍。
5. **共同提交必要事实。** 正式内容、结构对应、必要引用或依赖状态、历史、操作回执和本次消耗的草稿进度一起提交；失败则不报告正式成功。与修改无关的个人记录和布局不随之覆盖。
6. **按回执推进界面。** 回执明确持久确认到哪次输入、哪次正式修改以及哪些对象修订。自身提交不再次作为新输入应用；同一回执经响应和事件到达时只对齐一次。编辑实例与可用 Undo 继续存在。

SQLite 的事务提供同库修改的原子性，但只有应用把相关事实放进同一事务，才能建立上述合同；它不替应用决定哪些草稿已被吸收，也不验证内容语义。[官方事务说明](https://www.sqlite.org/transactional.html)、[事务与错误处理](https://www.sqlite.org/lang_transaction.html)

### 较早回执不能代表较新输入

例如输入序号 12 正在保存时，学生又输入了 13：

- 12 的确认只推进到 12。13 尚未确认时，界面继续显示正在保存，不能把整个输入区标为最新内容已保存。
- 正式提交 12 只能消耗明确对应的草稿；已经保留的 13 不能被无条件删除，也不能因 12 的迟到回执降回旧值。
- 初期优先在核心中拒绝对已被较新同范围草稿取代的旧稿做延迟晋升，再处理最新版，不为此立即建立通用多版本草稿合并器。
- 如果 12 先完成提交、13 仍在界面待发送，适配层依据 12 的真实回执继续处理后续变化，保留学生输入，不把旧完整单元重新写回。发生重叠外部修改时，保留草稿并进入既定整合流程。

正式操作仍使用稳定 `operationId` 与载荷摘要去重；未确认结果先查询或按原操作重试，不能换 ID 后再执行一遍。最新草稿使用会话、序号和摘要确认重试，同序号不同内容应拒绝，已落后的输入不能重新成为最新草稿。结束会话／旧课程代际的迟到消息也不能复活旧稿。

最新草稿采用覆盖保留，不把每次完整草稿另存进不可清理的操作请求或正式历史。原[承载实验的请求留存](../../experiments/core-placement-spike/README.md)是统一测量负载，不能直接照搬为生产保存策略。正式提交保留其恢复与去重所需记录，两者不能混为一谈。

## 与 Agent、公式和撤销衔接

**Agent 改独立部分：** 核心按实际读取依据和写入范围核对；前端在当前编辑文档上应用对应的范围事务，保留学生输入和可映射的历史，不向学生 Undo 添加 Agent 动作。不能因段落不同就忽略共同祖先、插件事务或内容依赖。

**Agent 改当前段落：** 按已接受规则暂缓同处替换，候选可保留为工作草稿。学生离开后，先处理尚未确认的学生输入，再重核候选及任务资格。过期候选需要重新读取／整合，不能因为“光标离开了”就直接执行。仅选文未修改时的视觉延后与实际编辑时的提交保护继续区分。

**输入到达核心之前存在间隙：** 前端立即保护现场并持续同步；若 Agent 提交已先发生，真实提交与学生草稿都要保留，再整合。不能把某条 IPC 已发出当作核心已获知，或者声称所有竞争都能靠光标标记提前阻止。

**公式：** 外层文档持有公式对象及位置，MathLive 持有公式内部的输入、选区和 Undo。进入公式编辑期间，不用外部 `setValue` 回填同一个值来驱动同步。公式内快捷键只由当前控件消费，返回正文后由正文上下文处理。公式外层插入／删除与内部编辑如何形成不重复的动作，必须在组合验证中明确，不能默认两个历史插件会自动协调。

未完成公式先保存草稿；已成立的公式修改沿用[既有 C8 合同](../development/旧版运行基线与验收.md)：可表达的共享语义配置一起更新，无法转换时保留编辑并明确相关探索结果需要核对，不能继续宣称旧计算代表新公式。这里不新设“修改公式就自动启动 Agent”的产品行为。

**即时 Undo：** 已保存的学生动作仍可撤销，撤销产生的新内容继续自动保存。外部同处删除可能使部分旧步骤失去对应，应保留仍可用的其他历史，不能以旧全文快照强行还原。正式“撤回这次修改”与历史恢复继续由课程核心处理。

## 卸载、关窗与异常中断

- 活动输入／选区和未确认保存的状态不能因离屏而直接销毁；需要维持编辑实例或可继续保存的独立会话状态。仅仅离屏、切换应用不代表放弃草稿。
- 正常结束编辑或关闭学习窗口时，先将最新输入交给仍存活的课程核心并获得实际保留结果，再释放唯一持有输入的实例。保存失败时保留待保存内容并明确提示，不假装关窗已经保存；关窗后 Agent 任务仍按已接受规则继续。
- 窗口异常消失后，核心根据会话实际存活情况结束临时输入现场保护，但不删除已保留草稿。未整合草稿仍参加同处写入守卫，不能因“窗口不在了”而被忽略。
- 应用异常退出后，重开按数据库内容、草稿与正式操作回执恢复。最新尚未收到持久确认的输入不能宣称已保存；结果不明的提交先核对，不重新生成。重开不恢复整个编辑器 Undo 栈，也不静默重跑 Agent。

## 下一项有界组合验证

使用一个有多段正文、公式、例题／题解和批注的单元，以及附近少量静态单元。接入已选 Electron 宿主、宿主拥有的 Worker 和真实 SQLite；用可控的模拟 Agent 注入变更，准确标注它不是实际模型闭环。不再用 localStorage 或成功 stub 代替保存，也不先扩成 500 单元的新性能排名。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 跨段选取、替换、拆合与复制粘贴 | 连续编辑成立；ID 不重名；收纳内容不丢；明确对应的批注仍属于原个人记录 |
| 公式内部编辑、返回正文、撤销／重做 | 快捷键只处理一次；正文和公式值正确；没有重复动作或覆盖最新公式；重开值与已确认结果一致 |
| 输入 13 后收到 12 的确认／旧提交 | 不误报 13 已保存，不清除更新草稿；按真实回执推进，不倒退 |
| 已提交但响应丢失，同操作重试 | 只存在一次正式修改和一份对应历史，界面不会再次应用 |
| 学生改 A、Agent 改独立 B，再撤销 A | B 保留，A 按学生操作撤销；结果实际落盘并能重开 |
| 当前段落停顿、跨段选区、离开后更新 | 现场持续受保护；离开后使用最新学生输入重核；没有采纳门槛或过期候选直写 |
| 中文组合输入期间，其他段落和共同祖先变化 | 保留真实输入／候选状态、焦点与选区；必要范围暂缓。合成 composition 事件只能作自动回归，不能冒充真实输入法验收 |
| 未完成公式／草稿、关窗、重新打开 | 最新已确认草稿可接回；Agent 任务按既定寿命运行；旧会话回调不能覆盖新会话 |
| SQLite 写入失败或进程在确认前后中断 | 保存状态诚实；正式内容、历史与回执一致；待保存输入仍可处理，未确认操作可查验 |
| 正文增高、布局让位与编辑实例切换 | 不重建正在输入的实例，不抢回视口；背景更新不通过整文重设清空 Undo |

通过这些场景后，再接真实 Agent、扩展复杂正文类型和完整课程规模。现有一次性资源实验不需要因写了本设计就重跑；只有组合暴露了新的瓶颈，才针对该问题测量。

4. **完整课程迁移与交付。** 资料、个人内容、历史与未处理草稿共同迁移，格式升级和一致备份可回查；macOS 先验收，Windows 按已确认阶段推进。
