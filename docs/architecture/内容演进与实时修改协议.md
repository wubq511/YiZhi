# 内容演进与实时修改协议

2026-10-27 随[系统设计定稿](系统设计定稿.md)整体确认的实施合同；推理经过见[设计取舍记录](../adr/设计取舍记录.md)。本文的旧版源码核查保留设计时证据；现有桌面实现与验收见[桌面应用说明](../../desktop/README.md)。字段和事件名用于说明边界，实际 API 以桌面实现为准。

## 本轮结论

仅有稳定单元 ID 不足以保护完整学习现场。正文块的身份与结构变化、学生正在编辑的草稿、Agent 所依据的版本、个人内容的定位方式，以及当前显示位置需要分别表达，再由统一提交回执对齐。

复用既有单元与块身份；统一读写、操作幂等与恢复的职责继续需要。后端采用 TS／Node Worker 核心与每课 SQLite＋资源文件。合同覆盖块拆合对应、有效读取依据、进行中的修改和局部布局投影；不因这些能力把知识改存为 React Flow 场景或引入多人协同系统。决策与证据索引见[架构决策总览](架构决策总览.md)。

## 内容模型：保留身份，显式描述结构变化

| 对象 | 建议保留或增加的表达 |
| --- | --- |
| 知识单元 | 既有稳定 `unitId`、正文 revision、来源版本与块树；知识关系继续引用语义对象 |
| 正文块 | 既有 `blockId/kind/role/payload/sourceRefs/children`；派生自身内容 hash，结构顺序单独校验。布局或显示深度变化不换块 ID |
| 块位置 | 父块或单元根＋前后相邻块 ID；插入、移动操作引用这些身份，避免保存依赖旧数组下标的路径 |
| 结构变化记录 | 本次变更明确哪些块保留、移动、新增、拆分、合并或删除，以及可验证的片段对应。它属于内容变更记录，不属于视觉布局 |
| 个人笔记／标注 | 独立个人对象 ID、原引用、原内容版本及当前定位结果；视觉几何与正文语义分开保存 |
| 编辑现场 | 编辑会话 ID、当前基线、输入序号、草稿、光标／选区／composition 与实验输入；序列化状态独立于组件实例 |

单纯改写或移动保留块 ID。拆分时明确哪个块延续原身份，其余获得新身份；合并时明确保留目标和退出的身份。不能为了复用旧批注而把一个旧 ID 同时交给多个新块。

内容操作建议至少区分 `replacePayload`、`insertBlock`、`moveBlock`、`splitBlock`、`mergeBlocks`、`removeBlock`。同一变更组中的正文、引用、结构对应与相关计算配置一起校验；不能让公式已经改变而实验仍宣称计算同一结论。存储内部可以继续原子替换实体，前端与工具不因此只能提交完整 HTML。

## 编辑范围：同一单元连续编辑

Robert 已确认：同一知识单元 B 内，普通正文作为一篇连续文档编辑。稳定正文块是存储和变更身份，不必等于学生每次只能操作的一段文本；当前逐块编辑的实现不是下一版体验上限。

| 方案 | 学生实际操作 | 取舍 |
| --- | --- | --- |
| 同一单元连续编辑（已接受） | 在普通正文中跨段选择、替换、插入或拆分段落；同一编辑会话的撤销按动作时间跨段回退 | 更接近连续讲解的创作与修改，需要编辑模型统一维护结构、选区和撤销；仍可按块记录实际变化 |
| 逐段进入编辑（已比较） | 每次明确进入某段，当前编辑与即时撤销围绕该段；跨段修改需分开操作 | 编辑范围更局部，但打断跨段改写，用户需要感知更多编辑切换 |

阅读态仍保留自然选取与复制。跨单元、独立笔记、画板以及复杂实验有各自操作上下文，不因选择连续正文就把整张画板变成一个文档编辑器。公式内部与实验控件仍有自己的编辑机制，需要与正文结构操作衔接。

轻量化按活动范围创建编辑实例，其余单元继续静态阅读；不为 500 个单元常驻编辑器。按单元提供编辑上下文，也不等于按单元保存整份历史或锁住全部正文：草稿保护及外部修改判断仍落在实际受影响片段和依赖上。

同处更新时机已进一步确定为离开当前段落或结束编辑后再自动对齐，详见下方[输入保护](#同处更新与输入保护)。学生新内容优先、自动保存和重新读取规则继续有效；编辑器库、内部表与消息字段由该体验目标和验证结果选择。

具体连接见[正文编辑与保存衔接设计](正文编辑与保存衔接设计.md)：稳定身份与连续文档的映射、未展开内容保留、草稿序号、正式提交和回执推进。编辑器已确定为 Tiptap／ProseMirror／MathLive，[候选核查](../research/topics/正文编辑器候选核查.md)保留选择依据；合同仍需实施验证，不改变本节已确认的编辑体验。

## 批注定位：把“标住哪句话”与“画在哪里”分开

文字定位建议保存：对象／块身份、原内容版本、可注释字段、文本投影版本、选段及前后文，并记录该版本中的起止位置。偏移明确采用 Unicode code point，范围采用包含起点、不包含终点；浏览器的 UTF-16 DOM offset 需要转换。文本投影由内容模型生成，并建立到呈现文本的索引映射，不直接把 MathLive 或其他渲染后的 `innerText` 当作稳定原文。

这参考 [W3C Text Quote Selector](https://www.w3.org/TR/annotation-model/#text-quote-selector) 的 quote＋上下文，以及 [Text Position Selector](https://www.w3.org/TR/annotation-model/#text-position-selector) 的位置表达。规范也指出单靠位置难以抵抗内容变化。本产品额外需要课程版本与结构对应；采用这些思想不意味着已经实现整套 Web Annotation 标准。

定位按证据处理：

1. 同一块和字段未变：使用原定位，不因同单元其他段落更新而要求重新关联。
2. 纯移动或布局变化：稳定身份继续定位；文字高亮根据当前文本区间重新生成显示矩形，图像局部标记根据目标坐标变换。
3. 原块文字改写：先使用经校验的变更对应，再核对选段及上下文；唯一且可证明的对应才自动跟随。原引用和原版本始终保留。
4. 拆分或合并：用结构变化记录映射范围。一个笔记仍是一份个人内容；必要时以有序片段表达一个原选区，不能把同一笔记自动复制成多个独立笔记。
5. 目标删除或对应不唯一：保留原语境和个人内容，明确等待重新关联；不随意跳到另一处相同文字。

文字高亮绑定文本区间；图像上的圈线绑定图像与相对几何；自由标记绑定对象或画板坐标。这些定位方式不能互相冒充。

**公式局部批注已确认纳入首版：支持直接选择符号或子表达式创建批注。** 保存公式身份与版本、原公式、选中片段及该版本中的定位和结构语境；移动时继续关联，改写后只有明确对应才自动迁移，无法确定时保留原引用与批注，标为待重新关联。例如 `x+x` 改为 `2x`，不能仅凭名称相同把左侧 x 的批注认作所有 x 的批注。[公式符号批注机制核查](../research/topics/公式符号批注机制核查.md)已核对 MathLive 选区与结构能力：选区数值和运行时 atom ID 都不是应用已获得的永久符号身份，应用需维护对应。该能力已设计，静态阅读与公式编辑之间的定位、局部修改、复制、Undo 与重开仍列入实施验收。

当前 UI 不支持通用跨块选区，这是既有实现事实。下一版已要求同一单元正文跨段选取；创建跨块批注时需要将这一可见选区表达为有序片段，复用拆分后的关联表示，仍保留一份个人内容。具体编辑器与批注手势尚未实现验收。

## 局部布局：手动基线与阅读投影分别管理

Robert 已确认允许手动摆放对象临时让位；下述内部合同与[总稿的空间交互](系统设计定稿.md#2-工作区阅读与空间交互)共同作为实施依据，动态宽度与完整内容尚需组合验收。

- **布局基线**记录课程原有组织及学生明确移动、调整后的结果。
- **阅读投影**根据当前内容尺寸、显示深度和已展开材料产生临时位移。展开记录可自动保存，临时位移可以重新计算，不把每次展开都写成学生重新排版。
- 展开或正文增高后，集中处理受影响的碰撞链，保持理解顺序与相对分组，不从头排列全图。其他列／主题没有实际冲突时不移动。
- 收起时依据**当前基线**重新计算，不恢复一份过期位置快照；展开期间学生作出的布局调整不能被收起操作抹掉。
- 用户拖动中的对象由该手势控制。内容尺寸变化和拖动不能各自抢写它的最终位置；固定宽度、向下投影的隔离实现已检查拖动与增长、跨列移动、多次展开及最新基线恢复，见[动态布局验证](../../experiments/architecture-spike/动态布局验证.md)。这不是任意布局算法或正式课程闭环的验收。

阅读锚点使用稳定内容位置及其屏幕坐标。布局调整前后若锚点世界位置改变，相机控制器只补偿这段位置差，保留缩放比例；这属于保持原阅读位置，不是恢复 Agent 跟随。用户平移增量与布局补偿由同一相机控制器合成，不能由两个监听器互相覆盖。

正文持续生成时按实际尺寸变化合并测量与局部排布；相机移动不触发重新测量全部正文。选区、活动输入和实验实例继续受生命周期保护。当前隔离验证已覆盖连锁让位和展开期间拖动；主题分组语义、复杂标注、动态宽度和正式持久化仍需进一步验证。7 秒持续增长并移动相机的补测保留了一次 100ms rAF 空档，不能由功能通过推定实机始终流畅。

## 实时修改：三种状态各自准确

| 状态 | 含义与保存规则 |
| --- | --- |
| 正式内容版本 | 已经通过内容校验并提交；有 operation／commit 回执，可按既定规则撤回 |
| 正在形成的内容 | 实际收到的有效显示增量，可包含未完成段落或尚未启用的实验；作为工作草稿自动保留，不能伪装为正式内容已完成 |
| 学生编辑现场 | 当前输入、选区和实验操作；选文可只影响呈现保护，实际修改则生成自动保存的草稿与内容命令 |

草稿可以真实保存，所以不能把“只有正式提交才算任何内容已保存”作为规则。草稿已保留、正式内容已更新和任务已完成是不同事实；正常使用不增加保存按钮、预览采纳或人工提交步骤。

Robert 已选择“正式修改历史＋可恢复草稿”，不要求永久记录每个按键或模型 delta。⌘/Ctrl+Z、指定修改撤回、历史版本恢复及对应成本，统一由[历史管理与恢复设计](历史管理与恢复设计.md)细化；本协议不另外建立一套全文事件历史。撤回需要的前后值与回执随正式提交保存，时间分组只是展示。

选中一段文字而未修改时，保护该处的实际 DOM 和选区，暂缓视觉替换；这不必锁住整个单元的正式提交。学生真正修改时，则需要把新草稿／修改依据同步到课程边界，阻止旧依据的同块 Agent 改动直接覆盖。

### 同处更新与输入保护

状态：**Robert 已选择“离开当前段落后自动更新”。** 具体场景是学生正在第二段修改，暂时停下来思考，光标仍在该段；Agent 根据已知的最新学生修改，准备进一步改写同一段。即便未发现依据冲突，也先保留学生正在操作的现场。

| 体验候选 | 停顿时的行为 | 取舍 |
| --- | --- | --- |
| 保持当前段落／选区，离开后自动对齐（已接受） | 不把短暂停顿视为结束编辑；保留现场，可提示该处有更新，光标移到其他段落或结束编辑后再自动处理 | 更稳定地保护思路和输入位置；同处结果会晚一些出现，无关且可独立提交的修改继续 |
| 输入暂停后尝试同步（已比较） | 组合输入结束、没有受保护选区且能维持输入现场时，尝试显示新内容 | 能更早看见修改，但思考期间文字也可能变化；无法可靠保留输入现场的情况仍需等待 |

已选方案不增加内容预览采纳步骤。保护范围根据当前段落、实际输入与选区确定，跨段选区覆盖其实际涉及范围，不因为一个单元有编辑器就暂停整篇内容。切到其他应用也不能被解释为放弃未完成输入。

- 仍在输入的重叠部分：Agent 候选可作为工作草稿保留，不能凭旧基线覆盖学生输入，也不能把等待处理的部分宣布为已正式完成；其他独立部分继续。若一组修改必须共同成立，不能为了局部显示而拆成不一致的半组。
- 仅选文而未修改：可按既有规则延后视觉替换，新批注引用学生实际看到的版本；这不必阻止不破坏其他约束的正式提交。
- 离开保护范围：只解除现场保护，不解除草稿、版本和任务资格校验。先确保学生输入已进入核心，再重新核对／整合候选，不能把等待期间的旧结果直接塞回正文。
- 保存与撤销：学生草稿及完整修改继续自动保存，后台更新不加入学生即时撤销栈。编辑事务能否映射选区和既有撤销应按实际编辑模型验证，不能用清空整单元撤销栈作为普通后台更新的默认处理。

官方机制核查表明，范围事务可以为保留选区与局部历史提供位置映射，但合法位置不保证原语义仍相同；组合输入、共同祖先结构变化及插件追加事务也需要处理。因而“其他独立部分”不能仅按段落 ID 或文字范围不相交判断。依据与局限见[编辑事务核查](../research/topics/编辑事务与并发现场机制核查.md)；当前没有接入或验证正式富文本、中文 IME 与 MathLive 的组合。

## 命令与事件的最小建议

每个独立变更组关联任务、执行尝试和编辑会话。当前执行尝试的取消资格、课程代际、读取依据及写入对象在同一道提交边界检查。

```json
  "operationId": "OP-example",
  "courseId": "COURSE-example",
  "generation": 4,
  "actor": {"kind": "agent", "taskId": "TASK-example", "attemptId": "ATTEMPT-example"},
  "editSessionId": "EDIT-example",
  "readToken": "server-issued-version-observations",
  "writes": [
    {"op": "replacePayload", "unitId": "KU-example", "blockId": "BLK-example", "payload": {"text": "完整且可校验的段落"}}

}
```

这是形状示意，不是当前 HTTP v1 已接受的载荷。`readToken` 代表服务记录的本组读取依据，包括目标块、实际读取的依赖内容及必要结构；默认不能因为工具只写一个块就省略已读依据。可以提供更窄的读取工具减少无关冲突。记录版本只能证明使用了当前数据，不能机械证明模型理解正确，内容与来源校验仍然需要。

重复的 operationId 与相同载荷返回已有结果；载荷改变必须使用新 operationId。冲突后不能只换成最新 revision 再发送旧内容，必须重新读取和整合。

| 建议事件 | 消费方行为 |
| --- | --- |
| `edit.started` | 标明真实工作对象与读取基线；跟随控制器据自己的控制权决定是否定位 |
| `edit.delta` | 按编辑会话内序号更新正在形成的片段；重复增量去重、缺口请求工作草稿；不整板刷新 |
| `draft.saved` | 推进该草稿的实际保存进度；草稿仍可能不是完整可执行内容 |
| `content.committed` | 应用已保存版本、结束对应工作片段，关联同一 operation；HTTP 回执和事件不得应用两次 |
| `student.changed` | 记录学生已修改的内容与版本，令受影响的旧工作依据失效；不能仅标记通知已经发出 |
| `edit.rebased` | 新一轮真实读取／整合已建立基线；不是收到 `steer` RPC 回执就自动产生 |
| `edit.conflict` | 保留双方内容，停住不兼容部分；其他可独立部分继续，仅在确需决定时询问 |
| `task.stopped`／`task.completed` | 以服务端状态终止本次执行；不由 SSE 断开或模型一句“完成”替代 |

持久事件使用可恢复的全局游标；进行中增量另有编辑会话内序号。临时显示增量不提前推进持久保存游标。重连先取得已保存内容／工作草稿与任务状态，再按对应游标补齐；不要求未经落盘的显示尾部能够原样重放。草稿与正式内容均持续自动保存，具体合并频率通过端到端测量确定。

当前适配器透传执行器通知，但运行时只消费回答文本 delta 和完整工具 arguments。首个可实现路径是连续的小步编辑工具调用：创建工作会话、写入可校验片段、自动提交完整变更组；真实参数流支持需要另行核实。不能用对话假打字替代画板的实际修改进度。

## 六个必须保持正确的时序

| 具体情况 | 推荐处理与可验证结果 |
| --- | --- |
| Agent 修改段落 A，学生修改互不依赖的段落 B | 保留 B；重新核对 A 及本组读取依据后提交 A。若 B 实际是 A 的推导前提，即使不在写入目标中，也必须让 Agent 重新读取和调整 |
| 学生选中 A，Agent 已保存 A 的新版 | 选择期间屏幕保留原片段及版本；新批注明确引用学生实际看到的旧版本。选区结束后再对齐新版，不能把旧 offset 套在新文字上 |
| 学生正输入 A，Agent 又产生 A 的旧增量 | 本地输入立即保护，草稿自动送达服务；服务已知的学生新修改令旧组失效。若 Agent 在学生通知到达前已经提交，回执仍是真实历史，但必须保留草稿并重新整合，不能丢弃输入或假装提交未发生 |
| 学生点击停止，同时一个写入已在途中 | 停止与提交串行决定先后。停止生效前已提交的保留；停止生效后的新提交拒绝。迟到的已保存回执可以补齐状态，不能因迟到被误认成再次写入；前端区分正在停止与已停止 |
| 内容已提交，但回执或 SSE 丢失 | 以相同 operationId 查询／重试获得原回执；不重复应用、不重复生成正文或批注；事件丢失不等于内容未保存 |
| 课程历史恢复，旧任务／旧草稿仍有消息到达 | generation 阻止旧正式提交；保留草稿供核对并隔离旧工作显示。继续任务产生新的执行尝试，旧尝试的回调不能因此重新获得提交资格 |

现有停止保证依靠同一个 AgentRuntime 锁。若未来把小步提交、输出处理或工具执行拆到其他路径，必须让它们继续经过同一道资格与提交顺序检查；单独给事件加 `stopped` 标签不形成保证。

## 实验生命周期：已确认默认行为

组件应分别提供可序列化状态、暂停、恢复与销毁；卸载 DOM 不等于计算已停止。运行状态与实验结果也不应该混入权威知识定义。

Robert 已确认：**默认离屏暂停在当前状态，返回后续接；明确需要跨时间观察的实验才支持继续运行，并显示其运行状态。** 后台运行能力由内容组件合同声明、学生明确开启；不把每个实验默认变成持续计时任务。具体运行层实现与验证仍待完成。

Robert 进一步确认：Agent 已保存新实验定义时，当前实例等本次拖动或输入结束后自动迁移兼容的参数与运行状态；不兼容时保留旧现场，只针对冲突询问是否重新开始。旧实例继续标明自己使用的定义版本，不把“新版已保存”与“当前实例已切换”合成一个状态。迁移按最新已确认现场执行，晚到的旧实例消息不能覆盖新实例；不增加每次更新都手动采纳的步骤。

纯显示动画暂停不改计算状态；连续实验必须明确使用实验自身时间还是现实经过时间，恢复不能靠任意补跳一大段来假装一直计算。本轮不替所有课程统一决定模型时间，也不把暂停／恢复接口视为任意生成代码已受控的证明。

## 本轮已收敛与后续范围

Robert 已接受两项推荐：手动摆放对象允许临时让位，收起按最新手动基线恢复；实验默认离屏暂停、返回续接，确需持续运行时再明确开启。

这些产品决定不等于布局算法、内容协议或整套系统已经实现与验收。后续已明确采用 Electron、TS／Node Worker 核心和每课 SQLite＋资源文件，分别记录在 ADR-0002 至 ADR-0004。本文件继续细化正文编辑范围、提交与历史、增量投递、检索及迁移的接口；旧 HTTP／SSE 形状不自动成为已选桌面核心的传输要求。
