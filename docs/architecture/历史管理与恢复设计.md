# 历史管理与恢复设计

2026-10-27。状态：**下一版实施合同，已随[系统设计定稿](系统设计定稿.md)整体确认；已补隔离语义、成本与键盘事实验证，尚未接入正式应用**。已确认的前提是“正式修改历史＋可恢复草稿”、所有输入自动保存、修改直接生效、个人内容受保护。Robert 进一步要求只做真实场景需要的能力，同时控制性能、存储与系统复杂度；本设计据此缩减方案。

证据入口：[Notion](../research/topics/历史与恢复/Notion历史参考.md)、[Figma](../research/topics/历史与恢复/Figma历史参考.md)、[Obsidian／VS Code](../research/topics/历史与恢复/本地编辑器历史参考.md)。交付形态已接受独立桌面，当前只打磨 macOS，后续 Windows 必做；这里的行为不依赖 Electron、某种数据库或后端语言。

## 从真实问题出发

学生主要需要四件事：刚才输错了能撤销；异常关闭后找回正在写的内容；看清 Agent 改了哪里并撤回不合适的修改；必要时取回以前的讲解。课程迁移后，这些已有记录仍然有用。

不需要因此建设 Git 式分支、永久逐键回放、多人协同、任意历史混搭或独立事件溯源平台。**推荐保留当前数据、一套正式变更记录、最新可恢复草稿；历史列表和旧版预览从它们生成。** 不再同时维护另一套全课快照、全文事件日志和可写历史副本。

| 真实需求 | 最小机制 | 避免的成本 |
| --- | --- | --- |
| 改错一个字、移错一个对象 | 当前编辑器／画板的撤销栈 | 不用每次撤销都打开全局历史 |
| 重开后继续尚未完成的输入 | 保存最新草稿及必要基线 | 不永久保存所有按键与模型 token |
| 看懂一次 Agent 修改 | 正式变更记录关联任务和修改者 | 不把每次自动保存都列成独立时间卡片 |
| 撤回一次修改，保留后来笔记 | 对指定变更构造有版本检查的逆操作 | 不回滚整课；不承诺任意文本都可自动合并 |
| 找回某个单元以前的内容 | 从对象历史预览、复制或恢复 | 不为每次正文改动复制 500 个单元 |
| 整课恢复或迁移 | 明确范围的新恢复操作；完整课程备份 | 不把版本历史当独立磁盘备份，不先做在线备份系统 |

## 撤销、撤回、恢复分别是什么

| 操作 | 用户意图与作用范围 | 是否跨重启可用 |
| --- | --- | --- |
| **⌘/Ctrl+Z 撤销** | 当前编辑中的最近一步；连续输入、一次拖动各按编辑动作分组 | 已确认只服务当前编辑会话；关窗重开后通过历史找回内容，不持久恢复整套编辑器撤销栈 |
| **撤回这次修改** | 移除指定学生操作或 Agent 任务的已提交影响，保留后续无关修改 | 是，依靠正式变更记录 |
| **恢复此版本** | 把明确选定范围改成过去的内容，可能覆盖该范围内后来的正文；覆盖前的版本仍保留 | 是，恢复本身也是新的正式修改 |
| **恢复草稿** | 异常中断后接回尚未完成的输入／输出 | 是，取最新已确认保留的草稿，不声称可逐键回放 |
| **从备份恢复课程** | 原课程丢失、损坏或迁移后打开完整副本 | 依靠备份包含的数据；同盘历史不能代替独立副本 |

例如：Agent 把讲解 A 改成 B，学生随后在另一块补充 C 并写了笔记 N。撤回 Agent 修改应得到 A＋C＋N；恢复整个单元到更早版本，可能移除单元正文中的 C，但默认保留独立笔记 N，并保留恢复前内容供反悔。若 C 是对 B 同一段的再次改写，不能假称无冲突撤回。

### ⌘/Control+Z 的具体路由

Robert 已确认撤销的作用期为当前编辑会话，不要求关闭学习窗口后继续连续撤销上次操作。这个决定减少的是跨窗口重建编辑器撤销栈的负担；正式修改历史和最新可恢复草稿仍按原规则保存。

Robert 已确认同一单元的普通正文连续编辑；同一次正文编辑会话的撤销按动作顺序跨段回退，见[编辑范围](内容演进与实时修改协议.md#编辑范围同一单元连续编辑)。这不意味着跨单元、独立笔记、公式内部和画板共用一套撤销栈。

| 焦点所在 | 撤销对象 |
| --- | --- |
| 单元正文编辑器 | 当前单元正文编辑会话中的最近输入、删除、格式及段落结构操作，可按操作顺序跨段撤销 |
| 独立个人笔记编辑器 | 该笔记编辑器中的最近输入、删除、格式等操作 |
| 可视化公式编辑器 | 公式编辑器自己的结构与光标相关编辑操作 |
| 对话输入框 | 输入草稿，不能把快捷键解释为删除已发送消息或停止 Agent |
| 画板操作上下文，未在文本框中输入 | 学生最近的移动、调整、绘图或删除等可撤销动作；一段拖动只形成一步 |
| 历史只读预览 | 不修改历史版本，也不暗中撤回当前课程；先返回当前内容再编辑 |

优先让当前控件处理快捷键；外层只接管明确属于画板的操作，不能再执行第二次。重做按平台惯例提供对应快捷键。平移、缩放、选择对象和切换阅读位置不进入内容撤销栈，返回导航另行处理。

后台 Agent 不加入学生的即时撤销栈，不改变“最近一步”指向。已经持久保存的学生操作仍可以撤销；撤销后的结果也走正常自动保存，不以“已保存”为理由禁止撤销。

**不直接把原生 Undo 当并发协议，也不因同一单元收到外部修改就废弃全部撤销。** 正常局部更新应沿用编辑实例与状态，通过有依据的范围事务映射选区和本地历史；是否结束当前编辑组是另一个决定，不能等同于清空旧记录。Agent 的变化不进入学生即时撤销栈，但仍可能改变原动作的可撤销范围。

本轮核查的 ProseMirror 官方固定源码中，未入栈事务仍向 undo／redo 分支追加位置映射；`closeHistory` 只结束分组。原内容被替换／删除时，旧步骤可能失去对应；合法的映射位置也不保证恢复原意。因此不能以整单元 `setContent` 或重建空历史状态作为普通同步方式，也不能承诺任意同处改写后的原撤销语义无损。[官方 history 固定源码](https://code.haverbeke.berlin/prosemirror/prosemirror-history/src/commit/3d21c24fcb2a5dc8664c2a4dbe0b8e03a93cd8a9/src/history.ts#L260-L298)、[机制核查与边界](../research/topics/编辑事务与并发现场机制核查.md)。Tiptap／ProseMirror 路线现已按 ADR-0006 确定；这些源码事实不代替产品组合验证。

活动输入／选区按已确认的[同处更新规则](内容演进与实时修改协议.md#同处更新与输入保护)保护；必要时等待离开当前段落后，先核对学生最新输入再自动整合。无法安全对应的旧操作不能用旧全文覆盖当前内容，正式历史仍可查找；其他无关的可用撤销应尽量保留。画板撤销也核对当前修订，冲突时保留当前内容并说明阻点。首期不建立跨编辑器、跨重启、跨任意外部修改的统一字符级撤销栈。

## 自动保存与历史记录如何配合

草稿保存、正式内容提交、历史列表分组是不同频率的工作。

- **输入保留**：正文、未完成公式、对话输入及生成中的输出持续保存最新状态；以编辑会话和递增输入序号拒绝迟到覆盖。草稿确认可以早于正式内容更新。
- **自动正式提交**：可成立的完整改动按编辑动作或可读内容组提交。连续输入可以合并；暂停、结构动作和持续输入中的有界刷新形成提交机会，不要求失焦、点保存或点击采纳。具体合并时长由输入体验和保存负载决定，不照搬 Notion 的 10 分钟。
- **正式历史**：每个正式变更组保存其必要前后内容、修改者、任务／编辑活动和时间。不能把草稿每次覆盖、光标移动、模型每个 delta 都永久记作正式版本。
- **列表展示**：学生的一段连续编辑、Agent 的同一任务默认合成可展开的活动。按分钟分组只改变列表，不改写已经存在的提交记录或恢复含义。

Agent 的完整修改仍然自动生效。上面的“正式提交”是系统内部的保存边界，不引入用户确认门槛。停止任务保留已提交部分；未完成输出作为草稿保留，不能显示为完整成果。

学习对话按消息保存，生成期间追加或更新当前未完成消息，结束后保留完整消息；不为每个 token 再复制整段对话。阅读视口与实验临时状态保存最新值即可，除非它们本身成为明确的用户编辑，不加入正式内容历史。

## 历史界面只服务三个动作

从单元进入时先看这个单元的历史；从课程入口进入时看全课活动。初版只需时间、修改者、简短说明、影响对象及差异预览，同一 Agent 任务可展开查看已提交部分。截图中的差异定位有实际价值，可以在预览中逐处跳转。

1. **看哪里变了**：默认比较选中活动的前后内容，支持跳到实际变化；不要求先阅读操作日志。布局变更用位置前后表示，复杂实验先比较可声明的配置，不伪造通用字符 diff。
2. **撤回这次修改**：从活动或任务结果进入，按下述逆操作规则处理。
3. **取回旧内容**：预览旧版后，复制所需片段，或恢复明确范围。只有用户选择恢复时才改变当前内容；普通修改流程不因此多一层预览。

历史预览只读，暂时独立于当前阅读视口；退出后回到进入前的位置。后台任务可以继续，当前内容若发生与恢复有关的新改动，执行前重新计算影响。首期不做分支视图、版本合并工作台、任意两版的所有媒体通用比较。命名／书签节点可随后增加；它不是恢复正确性的前置条件。

## 撤回与恢复的执行规则

### 撤回指定修改

以原来的正式变更组为最小一致单位：公式、相应实验配置和必要引用若共同提交，撤回也不能拆成互相矛盾的半组。同一 Agent 任务可以包含多组。

对每组比较原修改前 A、修改后 B、当前 C 及其间的修改记录：

- 目标和必要结构未被后续改动：生成 B→A 的逆操作。
- 后来只改了其他独立块、笔记或布局：保留它们。
- 同一受影响字段／结构又被修改：首期采用保守冲突处理，展示当前与原前后内容，不自动做任意文本三方合并。值碰巧又等于 B 也不足以证明没人改过，要核对修订来源。
- 跨组没有依赖的无冲突组可撤回；有冲突的一致组保留并说明，不能提示整项任务已完全撤回。

撤回整个任务时，先确定目标提交集合，再按提交逆序计算逆操作；本次撤回形成的中间修订不当成外部冲突。例如同一任务连续 A→B→C，无其他修改时可以依次 C→B→A。目标集合之外的后续编辑才触发保护；若学生在两组之间改过同一处，不能用“属于同一任务”跳过该学生修改。

新增块若已被后来的笔记引用，撤回其创建后仍保留笔记和原语境，标为待重新关联；不能删除个人记录或自动复制到猜测的目标。拆合块只采用有证据的对应关系，沿用[内容演进协议](内容演进与实时修改协议.md)。

若任务还在执行，撤回入口应明确为“停止并撤回已完成修改”：先撤销继续提交资格，再核对截至停止的实际提交集合；不能一边撤回一边让同一尝试继续写入。普通“停止”仍只停止，不暗中撤回。

### 恢复某一旧版

默认从单元或块开始，显示将替换的内容。**Robert 已确认：恢复单元旧版本默认只恢复课程内容，当前布局、个人笔记和掌握状态保留；布局可另选。** 学习对话继续保留。个人状态的历史恢复是独立明确操作，不能因恢复正文被顺带覆盖。

恢复用新的操作写入当前课程，原历史继续存在，并记录恢复来源和恢复前的位置。被替换的当前版本已在同一历史体系内，不再额外复制一份整课数据库作为“恢复前保护”。必要元数据与恢复一起提交，丢回执可查询，重复请求不重复恢复。

只恢复正文也必须满足知识一致性：恢复旧公式若涉及实验配置、关系或引用，先计算最小必要范围，并在影响列表说明。不能静默扩大到整门课程；不能留下悬空引用或前后不一致的计算对象。旧内容继续引用当时的来源版本，不能因为资料库已更新而偷换依据。

**整幅历史恢复已有独立产品合同**：恢复学习内容与所选用户状态，产生新课程代际和对象修订；操作去重记录、事件序号、任务执行事实不倒退，旧任务提交资格失效，继续需重新核对。新导入资料不因恢复旧正文而被删除。局部取回则是普通受版本检查的内容变更，不必为了改一块就停止全课所有独立任务。见[已有合同 C4](../development/旧版运行基线与验收.md)。

恢复前有活动草稿时先保证其已保留，不静默丢弃或强行变成有效正文。恢复本身可以被撤回；之后又有人改同一处时仍遵守冲突规则，不承诺随时无条件一键回到任意状态。

## 最小存储方案与性能取舍

以下是实施所需的逻辑结构；数据库已按 ADR-0004 确定为每课 SQLite，历史组织按本节与总稿执行，不额外构建一个通用版本控制引擎。

| 数据 | 首期建议 | 费用边界 |
| --- | --- | --- |
| 当前对象 | 保留正常读取所需的当前值与修订 | 日常阅读不从头重放历史 |
| 正式变更组 | 操作身份、作者／任务、时间、必要读取依据、受影响对象及前后版本 | 只记变化对象；不重复整门课、整段会话或未变化附件 |
| 变化对象内容 | 以实际可编辑的块、笔记、关系或布局对象为粒度，保存足够恢复的前后值；先用直观结构 | 不先做字符差分链、通用压缩或独立内容寻址正文仓库；正文块粒度须与编辑合同共同验证 |
| 最新草稿 | 每个编辑上下文保存最新已确认内容、基线和序号；自动恢复可能替换它之前保留必要保护副本 | 普通每键输入不无限追加历史草稿 |
| 来源和大资源 | 已有不可变资源按版本引用，历史复用同一文件 | 旧笔记／历史仍引用的资源不能按“当前没用”删除 |
| 历史列表／索引 | 从正式记录按对象、任务、时间查询，可按需重建 | 不再持久保存另一份含完整正文的事件流 |

这套记录还须包含对象初始值、创建／删除状态、必要父子归属和顺序，以及同组共用的提交序号。初始课程登记一次基线即可，后续只记录改变的对象和结构；删除保留其历史身份。否则只能找回旧文字，不能知道当时单元包含哪些块。上述信息仍属于同一套记录，不新增另一套历史系统。

正式内容、必要前后值、提交回执应在同一提交边界成功；历史预览、差异计算和展示分组可以在用户打开历史时按需计算。业务历史不是 SQLite WAL，WAL 也不能代替它。

保存对象的前后值会有一定重复，但结构简单、故障容易核对，通常比首次就引入差分压缩链更合适。先避免最大的放大源：每个小修改存整课、每个 token 存整段会话。对象级版本索引可直接找某个时点的状态；是否需要额外全课快照，只在长历史恢复实测确有瓶颈后决定，不作为首期预置机制。

日常输入不触发全历史扫描、全课 diff、历史缩略图渲染或全文快照。历史列表分页，默认只加载当前范围；旧版大资源按需读取。后台历史整理不是每次自动保存必须等待的步骤，但撤回所需的最小记录必须随提交保存。

### 保留与清理

Robert 已选择**设定期限、自动清理过期正式历史**，并明确默认 **140 天，学生可在设置中调整**，替代先前“不按天自动删除”的推荐，见[ADR-0007](../adr/0007-configurable-history-retention.md)。每门课程保存自己的正整数保留天数，新课程默认 140 天；设置随课程迁移。界面说明实际可恢复范围，空间占用按类别可查看；清缓存与清理正式历史分别处理，诊断日志和临时生成碎片不作为课程历史永久累积。

期限只作用于正式修改与历史恢复记录。当前内容、个人笔记、学习对话、未处理草稿及它们的原引用继续保留；仍在保留区间内的变更、个人原语境、运行现场或备份使用的资料与资源不得随旧历史一并回收。清理需要保留恢复区间起点的必要状态和操作去重事实，不能删除前半条记录后留下无法重建的历史链。具体算法与失败恢复随课程核心合同收敛；首期不增加自动云备份或多级冷热存储。

清理由核心在空闲机会分批执行，不阻塞每次输入，也不在读取历史时临时删半条记录。以正式提交时间确定候选到期范围，整组保留或清理；先物化窗口起点所需的对象状态并验证窗口内版本可重建，再在短事务中切换保留边界。未完成的撤回／恢复、待处理草稿以及仍在运行的实验版本属于明确引用，清理不得破坏它们。设置调小时按新窗口清理，调大只影响未来保留；已经清理的明细在历史中明确不可恢复，不从任务摘要伪造差异。

事件游标、课程代际和操作身份不随历史清理倒退。可以保留不含旧正文的最小操作去重结果；旧请求已过可重放窗口时明确要求重新读取，不能当成新操作再执行。独立备份中的完整副本按其自身保存管理，不会因为当前课程历史到期而被静默改写。

运行器的原始工具输入／输出不得成为另一套永久正文历史。它们只为有效任务恢复、明确证据引用或保留期内历史保留；用途结束后清理重复正文，只留必要身份、摘要和结果事实。学习对话中的实际消息继续独立保留，隐藏工具转储与执行诊断不因此永久保留。当前个人笔记等记录保留，不表示这些记录的每个旧修改版本都脱离历史期限。

## 现有证据与下一步最小验证

### 本轮新增的可判别结果

[历史语义与成本实验](../../experiments/history-spike/README.md)完成 37 项检查：同一任务连续修改按逆序撤回，保留后来独立文本／笔记／布局；同块后来编辑即使值碰巧相同也不绕过保护；内容恢复、显式布局恢复、恢复后的撤回、预览范围变动拒绝、重复请求与最新草稿重开得到验证。数据侧的“键盘撤销”使用调用方明确提供的操作目标，没有实现实际快捷键路由；草稿有一次真实异常退出测试，不能扩大为历史恢复中途崩溃已通过。

成本比较固定当前单元写法与 `FULL` 持久化，500 单元副本、40 个活跃单元，每轮 1,600 次混合保存，含 400 个正文组／800 个单元改动。三对比较中，正文历史前后值从 30.24 MB 降至 1.86 MB；数据库净增长从 30.99 MB 降至 2.95 MB。两边最终内容与十个中间历史预览相同。**减少约 93.85% 的分母是这条合成轨迹的正文历史载荷，不是整个课程或物理 I/O。** 保存 P95 有波动，中间轮变化块策略更慢；计时不含完整课程校验、撤回、UI 或 IPC，不能宣布整体性能胜出。

这足以继续采用“只记变化对象”的方向，暂不增加压缩链或全课周期快照。该轨迹只有固定结构中的段落追加，不能外推全部编辑类型、长期容量或结构恢复成本。

[键盘撤销事实实验](../../experiments/undo-input-spike/README.md)在现有隔离页面实际使用 macOS 合成键盘：textarea 与 MathLive 的 ⌘Z／⇧⌘Z 有效，正文模拟更新期间仍保持各自撤销目标与输入保存；实际拖动对象后，画板上的 ⌘Z **没有恢复位置**。22 项事实检查包含确认这一缺口，不表示画板撤销已经实现。textarea 不代表正式富文本，样例 localStorage 不代表 CourseService，Windows Ctrl+Z 与物理输入法未验。

因此首期需要的是编辑器保留自身撤销、画板为学生操作维护短期目标栈，并复用核心的受版本检查逆操作；不需要为每个控件重造编辑器。两条隔离实验尚未连接成正式界面到持久课程的闭环。

### 既有事务证据与尚需连接的范围

[隔离存储实验](../../experiments/storage-spike/README.md)已验证共同事务、回执去重、草稿守卫、停止竞争、进程异常退出与合成资源迁移，136 条断言通过。它没有实现本设计的选择性撤回、对象级历史或整课恢复；混合负载仍保存整个单元历史和完整请求，不能据此宣布历史成本已解决。

该实验在 500 个单元副本下执行 240 次混合保存，其中 60 次正式提交各改两个单元，checkpoint 后数据库约增长 3.08 MB。此数包含多类记录，**不是磁盘写入总量、纯历史体积或长期增长率**。它提供了需要细分测量的理由，不是马上建设压缩系统的依据。

下列原计划中，独立的语义、成本与部分键盘事实已按上文验证；不重复已通过内容。后续把尚未贯通的连接放入同一条真实编辑场景：

1. 学生文字、公式输入和拖动各用 ⌘Z／重做；后台 Agent 修改另一对象不抢走撤销目标；同对象过期撤销不能覆盖新内容。
2. Agent 分组改两个块，学生随后在独立块编辑并写笔记；撤回任务时保留这些内容，同块冲突明确保留双方依据。
3. 输入未完成公式后异常退出，重开恢复草稿；完整正文保持可读，不要求从头重放每个 token。
4. 预览旧版时发生新编辑，恢复必须重新核对；恢复后的反悔、旧任务失效、原引用和迁移在同一小场景验证。
5. 历史粒度的同轨迹成本比较已完成，当前没有增加压缩／快照的依据。正式实现只需核对加入真实校验与 UI 后是否引入新的瓶颈，不为扩大数字重新跑相同隔离基准。

当前阶段先收敛行为和成本，不因第三方产品拥有某项功能就把它变成我们的首期任务。桌面宿主实验与数据库事务通过，都不能代替这里的撤销／历史行为验证。
