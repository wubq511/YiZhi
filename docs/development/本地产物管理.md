# 本地产物管理

本地调试、验收和打包输出统一存放在**原仓库根目录**的 `artifacts/`。整个目录由 `.gitignore` 排除；其中可能包含课程副本、个人记录、运行日志和本机路径，不上传 Git 或直接作为 Release 附件。

## 目录职责

| 位置 | 内容 | 清理时机 |
| --- | --- | --- |
| `artifacts/scratch/<任务>/<运行>/` | 临时脚本、探针、构建中间包和可重建的测试副本 | 问题解决、必要证据归档后，当次任务结束前清理 |
| `artifacts/evidence/<任务>/` | 最小验收证据、原始失败现场、版本与摘要、必要的恢复输入 | 留存原因写入该任务的索引；被等价证据替代或问题关闭后复核清理 |
| `artifacts/releases/<版本>/` | 准备分发的 ZIP／DMG、校验值、构建清单及 Release 说明 | 保留正在准备或已发布的版本；验证替代包后删除重复副本 |
| `artifacts/README.md` | 本机现存任务与产物的相对路径、用途和待处理项 | 搬迁、替换或删除产物时同步更新 |

安装给用户运行的应用放在 `/Applications/YiZhi.app`；验收副本与用户安装分开记录。应用外的课程和个人学习目录继续沿用课程／迁移协议，`artifacts/` 中的测试副本不自动成为用户的权威学习目录。

多工作树共用原仓库的产物根目录，使用独立的任务／运行子目录，显式传入绝对 `--out`、`--output` 或 `YIZHI_EVIDENCE_DIR`。不把长期保留物写入 Agent 全局目录、系统临时目录或即将归档的工作树，也不建立指回这些位置的兼容软链。

`node_modules/`、`desktop/dist/`、`desktop/test-results/` 和 `desktop/playwright-report/` 保持工具的既定位置并由 Git 忽略；它们不是归档入口。保留其中的有效结果时只提取必要证据，不复制整个依赖或构建目录。

## 每次任务的收尾

1. 运行前选择任务／运行子目录；重复运行使用新身份，保留仍待诊断的失败现场。
2. 成功后把最终包放入 `releases/`，把必要的报告、日志、截图、原始测量和版本／SHA 清单放入 `evidence/`。索引明确区分程序回归、真实模型、实体操作、跳过项及失败项，不能用重跑覆盖历史结果。
3. 核对替代文件的内容摘要、模式和必要的软链目标，再删除本任务已不用的重复包、重复附件和临时探针；同一次运行不同时长期保留完整打包目录与内容相同的安装副本。验收完成后清理该轮复制的课程、profile、运行依赖和重复资源；需要继续使用的恢复输入或测试基线，每个明确用途只保留一份并说明原因。
4. 删除前检查正在运行的应用、脚本和数据目录引用。正常退出并等待保存完成；不得为腾空间强杀仍在编辑的应用。原课程、个人数据库、唯一备份、未迁出的恢复输入和归属不明的目录保留并列出原因。
5. 更新本地索引，列明保留物、清理项和未完成事项；核对 `git status` 与 `git check-ignore`，确保二进制、课程副本、profile 和个人日志没有进入 Git。规则和可复用操作说明留在 `AGENTS.md`／`docs/`，不把单次任务流水账加入正式文档。

## 搬迁既有证据

原始日志、测量、截图、包清单和验收输入保留其原始字节与来源身份，不批量改写其中的旧绝对路径。迁移时记录旧根目录到新根目录的映射和文件摘要，在本地索引中提供有效入口；需要再次执行时另建输入文件并指向新路径。更新当前状态与继续入口，完成校验后移除旧目录，避免两处同时积累。
