状态：模块实现与独立浏览器验证中；公共 app/index/service/storage/provider 由主 agent 接入。未将整张 04 标为 done。

## 冻结的 mount(host) 接缝

加载 `/web/editing.css`、已有本地 MathLive 和 `/web/editing.js` 后调用 `window.ReviewEditing.mount(host)`，返回 `{refresh, flush, destroy, ownsGesture, controller}`。不另建 storage/history，不直接 fetch、localStorage 或写文件。

| 方法 | 返回与责任 |
| --- | --- |
| `selectedUnit()` | 当前 unit 对象（兼容 KU ID 字符串）；打开编辑时固定目标，后续导航不漂移 |
| `getEntity(id)` | Promise `{entity,hash,revision,generation}`，entity 为权威完整 raw 实体，含 reading/children/sourceRefs；not_found reject |
| `applyContent(command)` | Promise `{saved:true,operationId,...}`；统一 knowledge CAS/历史/事件，先更新 host 快照再通知刷新。正文使用下述标准命令；关系通过显式 `relation.create` 交由主线业务校验 |
| `personalEntries(namespace)` | 同步全局快照 `[{key,value,revision}]`，包括所有单元的 notes/annotations/layout。可由现有 `persistence.entries(namespace)` 转换，revision 用 read 获取；不能只取当前选择。value=null 为墓碑 |
| `applyPersonal(changes,kind,metadata)` | Promise 落盘回执，changes 为 `{namespace,key,value}` / `{namespace,key,delete:true}`；metadata 为 `{operationId,groupId,expectedRevisions}`。**使用模块捕获的预期修订**，不能在提交时改取最新修订；否则旧笔记、旧拖动会静默覆盖别人。一次图形+布局必须原子提交 |
| `onRefresh(handler)` | host 快照/正文重渲染/统一历史变化后通知，返回 unsubscribe |
| `undo(operationId)` | Promise 落盘回执，选择性逆操作且 CAS；逆操作返回新的 operationId，不能恢复整幅个人状态 |
| `history()` | 建议提供：统一历史当前 `{undoOperationId,redoOperationId}`，空为 null；支持连续多步撤回。缺省只有本模块最近一次已确认操作的 ID 游标，不缓存快照或构建另一套历史 |
| `redo(operationId)` | 可选：参数为 history 提供的重做 ID 或上次撤回产生的逆操作 ID；缺省调用 `undo(inverseOperationId)` |
| `stageDraft(key,value)` | 可选：交给公共草稿恢复机制；value=null 清除。无此接缝仅在页面内保留失败草稿并阻止无提示离开。重开恢复草稿 UI 由公共恢复流程负责；模块不另建浏览器缓存 |

`saveEntity()` 不作为必需接缝；本模块已直接按确认的标准 knowledge changes 调用 `applyContent`，不需要主线再做第二次载荷翻译。`flush()` 处理尚未提交编辑；仍有冲突则 reject。`destroy()` 在未确认保存时 reject，避免集成方误销毁草稿。

## 正文标准命令

```js
{
  operationId: 'OP-<uuid>', groupId: 'EDIT-<uuid>', actor: 'student',
  kind: 'knowledge.update', generation: baseRecord.generation,
  changes: [{namespace:'knowledge', key:'KU-055', value: completeRawEntity}],
  expectedRevisions: {'knowledge:KU-055': baseRecord.revision},
  expectedEntityHashes: {'KU-055': baseRecord.hash},
  semanticImpact: {status:'needs-review', blockIds:['…'], reason:'…'} // 相关改动才有
}
```

明确保存一次正文为一个编辑组；MathLive 原生草稿撤销不混同已提交撤回。raw entity 深拷贝原对象，仅改受支持 payload 字段，保留稳定 ID/role/sourceRefs/children/coverage/知识主位置。支持 paragraph/callout text、formula latex/caption、steps items、table 可编辑格（保留公式 `{latex}` 结构）、figure alt/caption、knowledge-reference targetUnitId/intent、example/exercise title/problem/hint。引用正式 Q 时不改共享题干的 KU 副本；题解 children 可分别打开编辑。interactive 不接受任意 JSON/脚本。

公式、图或表改动影响本单元探索时，保留编辑，并将受影响 interactive 的 `payload.semanticStatus={status:'needs-review',blockIds,reason}` **包含在同一个完整 raw entity**，同时附 semanticImpact。现有 bindings 混用 block ID 与配置字段名，不能证明同步时保守标记本单元探索。主线须允许这项标识通过校验、哈希与保存，不可将旧输出继续称为一致。模块会在真实 block 上显示“探索结果需核对”；语义重新转换后由统一语义模块清除。

回执仅 `saved===true` 且 operationId 对应本次请求才清草稿。丢回执时重试同一 operationId 与原载荷；不会悄悄把更新后的输入塞进旧操作。revision_conflict 保留原请求/草稿，要求核对或显式放弃后重开，绝不强制覆盖。

## 正式关系命令

```js
{
  kind:'relation.create', operationId:'OP-…', groupId:'EDIT-…', actor:'student',
  generation: fromRecord.generation,
  expectedEntities: {[fromId]:{hash,revision}, [toId]:{hash,revision}},
  expectedRevisions: {['knowledge:'+fromId]:fromRecord.revision, ['knowledge:'+toId]:toRecord.revision},
  relation: {fromUnitId,toUnitId,type,directed,value,sourceRefs,view:'auxiliary',requirementGroupId?,route?}
}
```

主线分配 REL ID 并校验：端点存在/有效、引用真实、关系价值、重复/冗余、前置环和 AND/OR 路线组一致性，再走统一 knowledge namespace 原子提交与事件。UI 必选类型、方向、价值及来自端点原 sourceRefs 的来源。requires 从前置指向后继；inverse 只可双向。已有 AND/OR group/route 可显式填写，不从画布位置猜。手绘 arrow 始终为个人 annotations，绝不自动生成此命令。没有关系业务入口时须 reject capability_unavailable，不能伪报成功。

## 个人对象、局部布局与锚点

notes 独立 `NOTE-<uuid>`：`{noteId,objectId,text,anchor,createdAt,updatedAt}`。新增片段/对象笔记不复用原对象笔记 ID。笔记连续输入 900ms 或离开输入框自动保存，一次保存为一个组。

annotations 独立 `DRAW-<uuid>`：`{drawingId,objectId,tool,color,anchor,createdAt,updatedAt}`；tool 为 line/wave/highlight/rectangle/ellipse/arrow。layout 使用 drawingId 作 key：`{objectId,blockId,x,y,width,height,flipX,flipY}`。坐标为锚定 block/单元局部 CSS 像素。只在 pointerup 保存拖动/尺寸组，pointercancel/Escape 不提交；相反方向箭头保留 flipX/flipY。

anchor：`{objectId,blockId,revision,originalText,sourceRefs,selector?}`。revision 为原 reading.revision（无 reading 时用实体 revision）；selector 为 `{exact,prefix,suffix,start,end}`。重关联原语境留在 `originalAnchor`，历次定位留 `relocations`；原 DRAW/NOTE ID 不变，图形和新布局原子提交。

原对象/块删除、退休或选段无法唯一定位时保留个人对象及布局，出现在全局“待重新关联”列表。可输入新 KU 和 block ID 重新关联。相同 block ID 移动随 DOM 跟随；改写标原语境需核对；不能确定拆合对应时不复制、不自动指向新对象。来源读取失败不当作真实删除。

## DOM 与手势

实际单元 `.unit[data-unit]`（兼容 `.unit-panel[data-unit]`）。块按权威 ID 查 `.reading-block[data-block-id]`、`details[id]`、`.reading-exercise[id]` 等，不将派生 hint/answer ID 当新正文块。原位编辑入口只在编辑模式显示；不向 provider 写内容。overlay 位于单元内部，用 block 偏移重新定位，隐藏材料不挪到别的块。

主 app viewport 的 pointerdown 排除 `[data-editing-ui]`、`[data-annotation-overlay]`、contenteditable、math-field；`body.dataset.editing==='true'` 时正文允许原生 selection。可在自身手势逻辑前调用实例 `ownsGesture(event)`。模块不改 camera，不劫持 zoom/wheel；空格、中键让 host 平移，第二指取消当前笔画并让 host 接管。默认“选取文字”不拦截高亮文字；“移动 / 尺寸”才启用图形命中区域与尺寸手柄。

`refresh()` 用 host 最新原实体核对锚点，重建缺失入口/overlay，保留打开的编辑草稿。host 更新 DOM 后必须 onRefresh 通知；resize/toggle 用于重新定位现有 overlay。
