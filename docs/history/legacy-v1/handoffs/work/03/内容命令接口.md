# 03/04 共享内容命令与历史接口

实现：`复习画板/reviewboard/content_commands.py`。调用 `ContentCommands(service)`；使用同一个 `service.store`、`service._command_lock`、`service.catalog` 和 `service._validators`。不自动注册 HTTP、不更改 service/knowledge/renderer。

## 冻结的外部 API

- `get(id)` → `{id, entity, hash, revision, generation, deleted}`，entity 为原始权威实体，不是 Store.get 的派生摘要。初始已存在实体 revision=1；未创建的目标提交 expectedRevision=0。已删除实体返回 entity/hash=null，保留非零 revision。未知 ID 报 not_found。
- `read(id)` → 同 get，额外提供 `value=entity`。
- `apply(command)` → CourseStore 标准提交结果，附 `knowledgeChanges`（changes 中 namespace=knowledge 的原始实体变更）；operationId 原样保留。
- `undo(operationId, command=None)` → 新的逆向提交结果；默认 operationId 为 `undo:<原operationId>:<当前generation>`，同代际重复撤销返回原回执。显式 command 可提供 `{operationId, actor, generation}`。redo 调用 `undo(逆操作operationId)`。
- `restore(sequence, command=None)` → 整幅知识与所选个人状态恢复的新回执；generation 加一，所有知识实体（包括墓碑）和所选个人对象 revision 单调增加，reading.revision 也重新分配。command 可提供 `{operationId,actor,generation}`。省略时每次调用视为新的回退请求。
- `versions()` → `[{versionId,sequence,generation,label}]`；含 initial、各提交及 before_restore 恢复点；相同 sequence 可有多个检查点，restore 取该序号最后一个检查点。
- `history()` → `{versions: self.versions()}`，供主线 GET /api/v1/history。个人单独提交的序号也可 restore，由 CourseStore.history 重建所选个人状态。
- `changed(result)` 可选构造参数，在模块持有的锁释放后调用；失败返回 saved:true 且 notificationError，不能冒充通知已确认。主线已有通知时不传此回调，统一在 service 释放锁后调用 runtime.notify_change。

## apply 命令

```json
{
  "operationId": "OP-stable-id",
  "actor": "student",
  "kind": "knowledge.edit",
  "generation": 1,
  "expectedRevisions": {"knowledge:KU-001": 3, "semanticChanges:KU-001": 0},
  "expectedHashes": {"knowledge:KU-001": "optional-base-hash"},
  "changes": [
    {"namespace": "knowledge", "key": "KU-001", "value": {"id": "KU-001", "...": "完整原始实体"}},
    {"namespace": "semanticChanges", "key": "KU-001", "value": {"status": "needs-review", "blockIds": ["RB-stable"], "reason": "绑定公式变化"}}
  ]
}
```

删除使用 `{namespace:"knowledge",key:"REL-…",delete:true}`；value:null 不是知识删除 API。actor 仅 student/agent/import。knowledge 支持更新现有原始实体，创建 KU/REL 和 G*/RG-* 路线组。已删除身份不得重新分配；恢复旧实体用 undo/restore。关系来源使用 sourceRefs，额外价值沿用权威字段 value；提供 extraValue 时也必须为非空字符串，但不能替代必需的 value。所有写入复用当前知识模块完整校验；额外校验关系来源非空、requires 方向、路线组端点和成员双向对应。OR 组增删须与关系同一命令，不静默降为 AND。

已注册的个人及 metadata namespace 由 service._validators 验证，和 knowledge 共享一次 SQLite/JSON 提交；semanticChanges 不写进 reading。任务、会话和消息执行事实不接受内容命令修改。

expectedRevisions 可包含不在 changes 中的依赖对象（例如关系端点），这些对象也参与最终 CAS。可选 expectedHashes 按 `namespace:key` 提交，严格检查当前原始实体 hash；Runtime 已在最新 get 后做 block 三方合并时，只传整数 revision 也有最终 CAS 保证。

可选 `baseValues:{"knowledge:KU-…":原始基础实体}` 支持模块内部三方合并：基础实体必须匹配指定 revision 的已有历史；按稳定块 ID、字段合并。字符串、非 ID 数组视为单个片段；同一 payload/text 或 latex 改动冲突，不猜测字符合并。expectedHashes 是严格当前校验，想使用陈旧基础自动合并时不要同时提交旧 hash。

冲突为 StoreError(code="revision_conflict", details={conflicts:[{namespace,key,path,entity,revision,…}]} )；路径如 `/reading/blocks/@RB-…/payload/text`。正文撤销只逆向仍能确定的改动，保留后来不同块及个人笔记/标注；个人对象撤销要求 revision 精确相等，失败整组不提交。

## 保存、恢复与集成边界

SQLite documents 的 knowledge value 仅 `{hash}`（删除则 null），正文仍只编辑权威 JSON。CourseStore.history 保存真实前后实体；content_versions 是只读历史恢复点，不能作为第二当前正文接口。

提交顺序：完整校验/CAS → SQLite durable journal → SQLite 写事务内再次 CAS → 同目录临时 JSON fsync/replace/目录 fsync → 历史/事件/去重/版本一起 COMMIT → 清理 journal。只有落盘后返回 saved:true。中断后由 operations 账本确定回滚或前滚；恢复按实体/块合并，保留无关外部导入；同片段外部变动则保留文件和 journal，返回带精确 paths 的 save_failed，不擅自覆盖。

**启动要求：首次知识/图读取前初始化 service.content，知识/图读取也持有 service._command_lock。** lazy property 本身不会在 open_course/catalog.view 前自动恢复 journal。首次初始化及每次 get/apply/history/undo/restore 都检查未完成 journal 和外部 JSON 内容变化。外部导入按原始内容检测，不依赖 mtime/size，登记 import 事件及受影响实体新修订。

**单写入口要求：正式导入调用 content.apply，或在 content.writer_lock() 内完成重读、校验和外部写入。** 同线程锁可重入。锁顺序为 service._command_lock → 知识路径旁 `.content.lock` advisory lock → CourseStore SQLite；POSIX flock / Windows byte range lock。不合作的直接文件写入会在重读检查中被检测和保留，但任意写进程若在最终检查与 rename 间覆盖文件，单方 advisory lock 无法排除该窗口。02 正在写的 CLI 未在此工作线修改。

整幅恢复默认选择 notes/annotations/review/reading/layout/semanticChanges；保留其余 namespace，尤其 tasks/conversations/messages、事件序号、去重账本与执行事实。恢复前会存当前内容和所选个人状态的 before_restore 恢复点。旧任务 generation 即使实体值相同仍被拒绝。
