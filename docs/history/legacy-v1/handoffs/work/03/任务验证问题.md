## 复现

在 `复习画板` 目录运行，仅加载本次新增测试：

```sh
python3 -B -W error::ResourceWarning -m unittest discover -s tests -p test_agent_runtime.py -v
```

单独复现某项，在上述命令后加 `-k 方法名片段`，例如 `-k commit_ledger`。不需要 Codex CLI、网络、凭据或额外 pip 包。

测试先复制实际完整知识 JSON、布局、三个实际 Python 工具和所有来源/版本文件，随后每项测试复制到独立临时课程。不复制正式 manifest/SQLite；临时 CourseService 自建课程身份和状态。临时目录在 cleanup 删除。仅 SQLite 故障注入使用真实连接/trigger，没有 monkeypatch 服务、存储或命令实现。

执行顺序由 Queue 工具回复、started/interrupted/closed Events、steer 通知与持久任务状态控制；状态轮询间隔 10ms、有 5 秒期限，无固定长 sleep。`close()` 后核对所有 runtime worker 已退出。

## 首次发现的 7 项（主线已反馈修复）

### 1. 正文提交后 task 保存失败，重开丢失已提交操作身份（优先）

- 测试：`test_restart_recovers_commit_ledger_when_task_record_save_failed_after_commit`。
- 顺序：review_get → review_edit；真实 SQLite trigger 仅拒绝包含非空 operationIds 的 task UPDATE，允许正文/历史/operations 提交 → 工具收到 save_failed → 不再投递事件，关闭并重开服务。
- 已证实：正文含新内容，课程事件账本有且只有 1 次 Agent 知识提交；旧 task 的持久 operationIds 仍为空。重开不启动新 turn，但恢复 task 的 operationIds 仍为 `[]`，应包含账本中那个已提交 ID。
- 影响：后续 continue 的 alreadyCommittedOperationIds 无法反映已保存的工作。这里已证明恢复遗漏身份，未把尚未执行的重复写入推断为已发生。
- 定位：`AgentRuntime._tool` 的 `service.apply_command` 与 `_save_task` 分属两次提交；`_reconcile_one` 未补全本地提交关联。需要持久保存可恢复的 task/operation 关联，不能只扫描内存中的 task。

### 2. 首次 task 保存失败后，同 requestId 重试命中“幽灵任务”（优先）

- 测试：`test_failed_task_save_keeps_draft_and_review_and_same_request_can_retry`。
- 顺序：保存已有对话草稿和 weak 掌握状态 → trigger 拒绝首次 tasks INSERT → submit 返回 save_failed → 删除 trigger → 完全相同 requestId/payload 重试。
- 已证实：原草稿、知识和掌握状态保留；但重试返回的 taskId 在持久 tasks 中不存在，执行器也从未创建。
- 定位：`submit` 先加入 `_task_cache` 再 `_save_task`，失败不清理；重试在方法开头命中缓存直接返回。失败回滚或重试必须同时修复任务/消息/启动资格，不能只返回缓存。

### 3. 已有部分提交时，剩余冲突仍被标为 completed

- 测试：`test_unresolved_conflict_after_partial_commit_still_needs_input`。
- 顺序：第一段提交成功 → 读取第二段 → 学生修改第二段，steer accepted 落盘 → Agent 持旧基础修改第二段，收到 revision_conflict → turn/completed。
- 已证实：第一段已提交结果保留、第二段学生内容未覆盖，但任务状态为 `completed`，应为 `needs_input`。
- 定位：`_run` 的结束分支要求 `lastConflict and not operationIds` 才设置 needs_input；历史成功提交不能消除当前未解决冲突。

### 4. 断线会覆盖已保存的部分回答

- 测试：`test_disconnect_keeps_partial_output_instead_of_replacing_it_with_error`。
- 顺序：delta 输出“已经输出的解释，断线后仍应保留。” → 工具往返屏障，确认消息已落盘 → connection/closed → reconcile。
- 已证实：同一 assistant 消息 text 被替换为“连接断开，需要核对实际任务状态。已提交的 0 次修改仍保留。”，原解释消失。
- 定位：`_run` 的异常处理调用 `_message` 覆写固定 `MSG-taskId`。错误状态应保留部分输出，不能通过相同消息身份覆盖它。

### 5. 重开核对到 completed turn，仍不恢复完整回答

- 测试：`test_reconcile_recovers_completed_answer_without_starting_another_turn`。
- 顺序：ask 已启动；执行器实际上完成，但完成通知丢失 → 关闭服务并重开 → reconcile 返回匹配 turnId、status=completed 及完整 agentMessage item。
- 已证实：没有新 turn；task.reconciledExecutorStatus 已是 `completed`，但 assistant 消息仍为 `[]`，task 仍是 needs_input。
- 定位：`_reconcile_one` 只读取 turn.status，不恢复 items，也不完成已核实的问答任务。应从查询结果恢复完整输出，而非要求用户重跑已完成回答。

### 6. item/completed 后迟到 delta 被重复拼接

- 测试：`test_completed_item_is_not_extended_by_delayed_delta`。
- 顺序：同 itemId delta“完整” → item/completed 全文“完整回答” → 迟到 delta“回答” → 工具往返屏障 → turn/completed。
- 实际：消息为 `完整回答回答`；预期：`完整回答`，且只保留一条 assistant 消息。
- 定位：`_run` 对已完成 item 没有终结标记，delta 继续追加到完整文本。

### 7. 重复工具事件不重复写，但返回结构丢 knowledgeChanges

- 测试：`test_duplicate_tool_events_return_original_commit_after_later_student_edit`。
- 顺序：固定 tool event id、相同工具参数提交 → 学生继续修改同段 → 重放完全相同事件。
- 已证实：知识账本仍只有 1 次 Agent 提交，operationIds 只有 1 项，学生后续修改保留；但重放结果比首个 saved 结果少 `knowledgeChanges` 字段，违反返回原提交结果约定。
- 定位：`_tool` 命中 operations 后直接 `json.loads(result_json)`；正常路径的 `ContentCommands.apply` 会额外 decorate 出 knowledgeChanges。两条返回路径应使用一致的公开结果形状。

## 已通过的 11 项

- 普通问答即使执行器主动调用 review_edit 也不能写入知识。
- 相同 requestId 重复提交只产生一个 task/user message；不同 payload 拒绝。
- 停止后拒绝新的迟到写入，停止前已提交操作保留。
- 跨对话共享修改队列；问答独立运行；排队后切换 UI/修改原请求对象不会漂移目标；启动读取最新正文。
- 学生修改后运行中通知携带最新正文，accepted 落盘；不同块修改合并后两方内容都保留。
- 已 accepted 的通知不绕过最终 CAS：同块冲突保留学生内容、返回具体块、进入 needs_input。
- steer 失败记录 accepted=false/error；执行器显式重读后可以兼容提交，最终说明通知未确认。
- 历史恢复增加 generation/sequence；旧任务即使仍 running 也不能提交，再 invalidation/interrupt 保留执行事实。
- 正常重开只 reconcile、不 start；点击 continue 才启动，携带已提交 IDs，仅补另一块内容。
- connect 报 CLI 不可用时明确 failed/executor_unavailable，知识不变。本项验证 runtime 对端口故障的处理，不冒充真实 CLI 集成。
- 正文 operations 提交被真实 SQLite trigger 拒绝时，JSON 回滚、草稿/掌握状态保留；移除故障后相同工具参数重试只提交一次，重开仍保留草稿/状态/正文。
