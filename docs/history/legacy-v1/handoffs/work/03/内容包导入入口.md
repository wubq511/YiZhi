# 02 内容包统一导入入口

从项目根使用：

```bash
python3 复习画板/import_content.py 内容包相对路径.json
python3 复习画板/import_content.py --course /临时课程副本 内容包路径.json
```

包路径相对当前工作目录解析；服务端收到绝对路径。直接 HTTP 调用的相对路径按课程根解析。

CLI 先核对本课程 runtime、health 的 courseId/instanceId，已有服务时 POST `/api/v1/content/import`。服务拒绝或回执丢失时不启第二写入者，请重试同一包。没有服务时持有同一个 CourseLock，构造临时 CourseService，导入后关闭。不会启动浏览器、Agent 或额外常驻 HTTP 服务。

主线 HTTP 注册：

```python
from .content_imports import import_content_package
result = import_content_package(service, command.get("packagePath"),
                                course_id=command.get("courseId"))
```

主线 boot 注册收据 validator，保证重开后可以直接 undo 导入：

```python
from .content_imports import register_imports
register_imports(service)
```

导入函数在 content.writer_lock 内恢复 journal、重读并同步外部修订，调用 02 的 apply_package，仅把 units/questions/sources 的实际实体 diff 交给 content.apply 一次提交。source 元数据、正文、共享 Q 与轻量 contentImports 收据处于同一事务。包资源先按 02 的路径、命名空间和摘要校验原子落盘，再提交引用；失败可能保留可复用的未引用资源，不会独立重写知识 JSON。通知由主线在导入函数返回、释放锁后发送。

operationId 固定为 OP-IMPORT-<packageId>。包摘要使用整个包的规范 JSON；相同包重试返回原回执，即使后来编辑或 generation 已改变；相同 packageId 换内容明确拒绝。无正文 diff 的包也落盘收据，返回 status=unchanged。收据不复制正文。

主线已在 content_commands.py 允许 actor=import 时创建新的 SRC 实体；新 SRC、已有 SRC 更新和正式 Q 更新均走普通 knowledge 命令。新增 SRC 与资源的原子导入测试已通过，适配器不旁路命令或改写 JSON。

**原生 `期中/工具/复习内容.py import` 仍不参与 .content.lock。** 它与学生/Agent 并发写入仍有已知 race；本工作线没有修改或覆盖 02 文件，也不宣称旧入口已经安全串行。02 正式导入应改用本入口，或另由主线协调旧入口的锁接入。

验证仅使用自动生成的临时课程和受控 HTTP 服务；不操作正式数据。定向测试入口：`cd 复习画板 && python3 -m unittest discover -s tests -p test_content_imports.py`。实际运行 8 项全部通过：实体 diff/共享 Q 更新/操作 ID 去重与包 ID 冲突、无变更收据及重开后撤销、共享题目冲突原子拒绝与课程身份校验、独立服务并发导入不同单元、新 SRC 与包资源同次提交、资源目录 fsync 失败重试、真实 SQLite COMMIT 失败重试、CLI 受控 HTTP 转发/错误后不启动旁路写入者/服务停止后离线重试及新包实际提交。CLI 在线路径使用受控 HTTP 处理器，正式 HTTP 路由注册由主线负责。本工作线未读取或修改正式课程 JSON、未调用 02 原生导入 CLI、未访问凭据。
