# 正式版数据与行为合同 v1

日期：2026-10-25。本文定义共同合同；01 的实际 HTTP、存储和扩展入口见 [实施接口](../../../../legacy/review-board/接口.md)，其余能力随对应工作线实现。以 [任务规范](01-正式版任务规范.md) 的产品行为为准；实现者可以调整模块内部方案，不能私自改变共同字段含义、保存保证和用户行为。接口调整由当前集成者合并到本文，并注明受影响票号。

## C1：课程的权威来源与身份

| 数据 | 唯一职责 | 不能承担的职责 |
| --- | --- | --- |
| 权威知识数据 | 主题、单元、阅读正文、题目、证据、来源、正式关系、路线组与退休记录 | 个人掌握程度、视口和聊天草稿 |
| 独立布局 | 视觉对象绑定、稳定位置、尺寸、阅读顺序与必要布局元数据 | 发明前置关系或复制正文 |
| 个人内容 | 笔记、图形标注、复习状态及其独立修订 | 覆盖课程重要性或成为正式关系 |
| 阅读上下文 | 视口、当前位置、选择、导航返回、展开、答案、面板与草稿状态 | 对正在执行任务的目标重新赋值 |
| 对话与任务记录 | 消息、请求快照、执行器映射、运行状态、已提交操作与恢复信息 | 仅凭模型成功就认定数据已保存 |
| 历史记录 | 已提交变更的前后内容、作者、影响对象、撤回与恢复所需信息 | 作为另一份可独立编辑的当前课程 |

当前正式知识数据仍为唯一内容入口，现有查询模块继续负责知识语义；新增正文和引用须从该模块读出。前端内嵌快照、HTML、Markdown、搜索索引与内容包都是可重建或待导入数据，不能作为第二权威来源。#01 为先打通保存，可只读复用现有四个原型样本及其稳定身份；#02 统一迁入 reading 后切换同一读取适配器。过渡样本不继续扩写，也不成为可独立编辑的第二课程数据。

当前有效单元共 84 个：`KU-001` 至 `KU-086` 中不含 `KU-049`、`KU-073`。既有 `TH/KU/Q/MAP/REL/REF/SRC` 身份保持；新增正文块、资料版本、笔记、图形、对话、任务和操作使用各自命名空间，不能把视觉 ID 当语义 ID。重命名、改写和移动不换 ID；删除保留可追溯身份，不重新分配退休 ID。

课程清单包含稳定 `courseId`、课程格式版本和指向权威知识、布局、个人内容、对话、任务、历史及资料的课程相对路径。当前工作区可作为第一门课程的根；迁移后不依赖原电脑绝对路径。应用资源可以独立于课程保存，但字体、公式、图示和阅读所需资源均须本地可用。

## C2：阅读正文与内容包

### 单元阅读材料

给知识单元增加可选 `reading` 扩展，扩展版本为 `review-reading-1`。保持已有 `midterm-map-1` 数据可读取；缺少 `reading` 表示正文未完成，不能显示成“已收纳”。新增字段也必须进入校验与内容哈希。已有摘要与内部项继续可查询；需要两处显示同一公式或表格时使用稳定内容引用，避免分别维护同一事实。

| 字段 | 含义 |
| --- | --- |
| `revision` | 本单元阅读材料的修订；与布局、个人状态分开 |
| `status` | `draft` 或 `complete`；只有学习目标和证据检查通过才能标 complete |
| `blocks` | 有序正文块，按连续阅读顺序组织；正文完整文本只在这里或被引用的题目实体维护 |
| `coverage` | 掌握目标对应的核心、示意、方法、例题或练习及核对记录；允许有理由的“不适用”，不允许把未写当不适用 |

每个正文块包含稳定 `id`、`kind`、`role`、该类型的 `payload`、`sourceRefs`。`role` 为 `core`、`material` 或 `supplement`：核心保持可见，已有材料可展开，补充说明用于额外解释。支持的 `kind` 为 `paragraph`、`formula`、`figure`、`table`、`steps`、`callout`、`knowledge-reference`、`example`、`exercise`、`interactive`。容器可包含按顺序读取的子块，子块同样有稳定 ID。所有 ID 由创建者分配一次，不能每次构建重新生成。

- 文本、公式和表格保存可编辑的语义内容；公式内部可用 LaTeX，界面不要求学生输入源码。
- 图示引用本地资源并有说明；需随数据变化的图由语义配置渲染，不能用一张固定截图冒充动态结果。
- `knowledge-reference` 只保存目标知识身份和定位意图；目标完整正文不复制。
- `example` 展开即见完整讲解。`exercise` 分开保存题干、可选提示和完整答案，揭示状态保存在阅读上下文。
- 已有正式题目使用 `Q` 身份引用；共享题干与标准解答归属题目实体，单元可附针对本方法的解释。来源页上的答案、Agent 据题干推导的答案和编制自测须明确区分。
- 自测变式是正文练习材料，不冒充已有正式题号，不自动改变题目映射和评级。
- `interactive` 保存组件种类、语义配置、输入初值、与公式/图示的绑定。首先支持已验证的 MUX、译码器和卡诺图探索；后续增加组件通过同一接口扩展。

布局信息不放进阅读正文。必要条件不得隐藏在折叠层，三类单元按学习目标选内容；不要求每个单元机械拥有每一种块。

### 内容包交换格式

待导入包版本为 `review-content-package-1`。它是一次可审查的修改提案，至少包含以下信息；由 #02 提供实际校验、导入和预览入口。

| 字段 | 要求 |
| --- | --- |
| `packageId`、`ticketId` | 章节包均属于 #02；packageId 区分同一工作线内的批次并识别重复提交，不为每包另建票 |
| `baseSourceHash`、`baseEntityHashes` | 记录提案依据；集成时按实际目标实体判断是否变化，不因其他单元刚导入就误拒绝整包 |
| `unitIds`、`units` | 明列本批次负责的单元；每项只提出该单元阅读扩展及明确解释的必要纠错 |
| `questionUpdates` | 需要的正式题目题干/解答增补；共享题目相同候选只存一次，不一致候选进入集成冲突，不按后到覆盖 |
| `sourceProposals`、`assets` | 新增引用元数据与本地资源，使用本包命名空间；不得无声替换已有资料 |
| `evidence` | 每单元的课件定位、教材双页码或笔记小节、实际看图核对记录、答案性质与阅读检查结果 |

导入顺序为：检查包及拥有范围 → 在课程临时副本应用 → 检查来源/身份/正文/关系与资源 → 预览实际读取路径 → 由集成者通过统一命令串行导入 → 重建并复核受影响产物。单包不能因部分写入失败留下半份正文；失败明确报告对象及原因。正式课程已有的更新必须保留；不整文件覆盖另一位作者的成果。

#02 负责全部 84 单元，包括迁入 `KU-035/055/056/063` 四个已有样本及补齐其余 80 单元；不把原型 HTML 直接作为新权威正文。工作线内部按章节登记当前内容负责者，防止多个作者覆盖同一单元，不为每个包再建票。包集成并核验后，工作副本和不再需要的临时图可清理；保留必要来源与验收记录。

## C3：CourseService 的外部行为

本地服务是唯一写入口。以下是逻辑操作合同，#01 同时确定实际 HTTP 映射并记录在应用接口说明；后续模块按此调用，不另造直接文件写入接口。

| 操作 | 请求 | 返回和保证 |
| --- | --- | --- |
| `openCourse` | 课程位置 | 课程身份、格式、已提交修订、可用能力、阅读上下文与待处理任务摘要 |
| `getEntity` | 稳定实体 ID | 权威实体及其修订；单元含 reading；沿用既有语义查询 |
| `getGraph` | main / auxiliary / all | 全部主题与单元、选定关系、主题聚合、布局；保留原始关系身份 |
| `queryKnowledge` | 既有 search / related / path / questions 参数 | 保留 AND/OR、direct/support、明确错误及稳定顺序 |
| `getPersonalState` | 可选对象范围 | 独立笔记、标注、复习状态及修订，不修改知识数据 |
| `saveReadingContext` | 当前阅读上下文与上下文修订 | 自动保存确认；重新打开恢复，更新不触发 Agent 内容冲突 |
| `applyCommand` | 操作 ID、作者、目标、预期修订、业务操作及载荷 | 校验后提交、提交 ID、新修订、实际影响对象与事件序号 |
| `eventsSince` | 已看到的课程事件序号 | 可继续读取的已持久化事件；过旧时明确要求重新取快照，不假装丢失事件不存在 |
| `resolveSource` | 来源 ID、版本 ID、位置 | 对应本地资料及定位信息；缺失、越界、版本不匹配明确失败 |
| `searchCourse` | 查询、范围、关键词/描述模式 | 已存在的分类命中、版本、摘录与定位，不返回伪造实体 |
| `submitRequest` | 对话 ID、请求类型、固定目标、选段引用、指令 | 应用任务 ID、队列/运行状态和已持久化请求快照 |
| `controlTask` | 任务 ID 与 stop / continue | 实际状态；继续只补未完成操作，停止不撤回 |
| `undoOperation` | 已提交操作或任务 ID | 选择性逆向提交，保留后续个人内容；冲突明确定位 |
| `restoreVersion` | 明确历史版本 | 整幅历史状态恢复记录；与选择性撤回区分 |

统一错误至少区分 `not_found`、`invalid_parameter`、`invalid_content`、`revision_conflict`、`source_unavailable`、`save_failed`、`executor_unavailable`、`capability_unavailable`。无结果是成功的空集合，不能与错误混用。错误含可定位的实体和原因；前端不把失败响应改成成功提示。

能力由阶段明确暴露，尚未实现的按钮不假装可用。#01 实现开课、查询、对象笔记、复习状态、阅读保存及通用提交/事件；#02 扩展正文、资料阅读和关键词检索；#03 接入 Agent、修改/撤回/任务恢复与描述性检索；#04 接入手动编辑、片段笔记、图形标注和明确关系建立。各票按共享接口联调，不等待无关功能全部完成。

## C4：保存、版本与操作

- 每次修改有稳定 `operationId`、`actor`、`targetIds`、`expectedRevisions`、操作种类与载荷。`actor` 区分学生、Agent 和内容导入。修改知识与修改个人内容使用不同对象修订，写一条笔记不应让无关单元的编辑失效。
- 一次命令可修改多个直接相关对象，提交前检查全部目标版本和内容有效性；冲突返回当前对象及修订，不覆盖，不只应用其中几项。
- 同一操作重复提交返回原提交结果。已提交事件有单调课程序号，模型 delta 不等于已提交内容事件。
- `saved` 只在数据与恢复所需记录真正落盘后返回。写入失败保留原已提交状态和可恢复的编辑内容；文件中断后恢复到完整提交前或提交后状态，不留下半份 JSON 或知识与撤回记录相互矛盾。
- 后端只允许一个课程写入者；多个浏览器和排队任务通过同一命令入口序列化。外部内容包按实体哈希对比，在集成前检查课程是否变化。
- 自动保存适用于笔记、状态、阅读、布局、对话草稿与消息；连续输入可以合并存盘，界面应区分未保存、保存中、已保存和失败。刷新/关闭前处理剩余保存；服务重启时恢复已确认保存的数据。
- 历史记录保存足够构造选择性逆操作的信息，不要求把每次鼠标移动变成一个历史版本。拖动结束作为一次布局操作，连续输入使用合理的编辑组。
- 版本回退保存当前状态为可恢复节点，明确其整幅恢复语义；选择性撤回则仅处理指定操作，不能借用整幅回退实现。
- 历史恢复只恢复学习内容与所选用户状态，产生新的课程代际与对象修订；事件序号、操作去重账本和任务执行事实不得随快照倒退。恢复前活跃任务的旧提交资格失效，迟到结果被拒绝，任务重新核对后由学生决定是否继续，不能因旧修订值再次出现而通过检查。

## C5：阅读上下文、笔记与状态

阅读上下文包含 camera、当前位置、显示深度、选中对象、展开块 ID、已揭示练习 ID、交互输入、导航返回栈、目录/小地图开关、面板宽度与开关、原文位置和各对话草稿。位置和显示深度分别管理；缩远隐藏内容不清空其状态。任务提交时另存目标快照，不能继续引用可变的当前选择。

笔记保存独立 `noteId`、内容修订、创建/修改信息与 `anchor`。anchor 可以是对象或片段，至少记录目标语义 ID、可选块 ID、当时正文修订、原引用及必要的片段定位信息；图形标注另有图形 ID 和位置绑定，但延续规则相同。

- 移动时跟随对象；改写后保留原引用，即使成功重新定位也不能抹掉书写时语境。
- 拆分合并只接受明确对应关系；不能确定时标记待重新关联，不自动复制到多个新单元。
- 原对象被删除或退休后，笔记继续在笔记列表和搜索中出现，支持重新关联；不随正文级联删除。
- 选择性撤回保留后续笔记和标注。若学生后来修改了同一正文片段，逆操作也做版本比较，只处理能够确定的部分并说明冲突。

复习状态枚举为 `todo`、`weak`、`mastered`，显示分别为待复习、薄弱、已掌握。仅有效 B 有一个当前状态；新 B 默认 todo，A 计算汇总。看答案、完成 Agent 任务或修改重要性均不自动改状态。

实质变化由修改记录标出受影响的重要结论或方法及理由，形成待学生决定的状态提示。正文提交不等待此决定；学生未确认时保持原状态，纯措辞和排版不创建提示。确认也须针对提示产生后仍有效的单元状态，不能覆盖学生刚手动改过的标记。

## C6：来源与版本

沿用现有 `SRC` 来源身份，补充稳定资料版本。版本记录版本 ID、内容摘要、课程内相对资源位置及显示名称；PDF 定位保存从 1 开始的页序，教材同时保存中文书页。课程笔记使用文档小节和必要摘录位置；它不是新画板里的个人笔记。

正文、题目、原文选段和聊天引用都应指明版本。首次迁移时把既有引用固定到当前实际原件；导入新版不能重解释旧引用。保留旧版资源；所有消费端解析引用时按指定版本定位，不能一律跳最新版。

原文选段保存来源、版本、位置与选中文字；扫描 PDF 使用已核对原页和可定位文本层/OCR，无法可靠取得文字时提供该页或选区上下文，并明确实际携带内容。不可把未选中的文字当作选段。

新增/替换资料先保存版本并提示是否更新画板。用户选择暂不更新时，正文和旧引用保持；搜索与 Agent 可以访问新版本，但必须注明版本，涉及差异时说明。用户选择更新后才提交修改任务，结果直接生效并可撤回，不增加生成后采纳步骤。

## C7：Agent 任务与执行器

应用任务记录包括 `taskId`、`conversationId`、`requestKind`、提交时目标/选段、指令、排队序号、开始时目标修订、执行器 thread/turn 映射、已提交 operation IDs、状态与最后确认信息。执行器是适配端口，课程写入仍经过 CourseService。

| 状态 | 对学生的含义 | 后续行为 |
| --- | --- | --- |
| `queued` | 修改等待前一任务完成 | 开始时重取目标最新状态；目标已失效则说明，不能套用旧对象 |
| `running` | 正在回答或处理请求 | 可继续阅读；修改任务可分批提交完整、可读的改动 |
| `needs_input` | 仅具体冲突或真实执行所需信息待处理 | 保留已提交结果，明确需要处理的部分 |
| `completed` | 任务已结束且应用结果已核对 | 说明改动、同时修改情况及定位入口；不自动跳视口 |
| `failed` | 执行或应用失败 | 区分失败阶段和已经保存的结果 |
| `interrupted` | 已按停止请求结束 | 保留此前提交，停止之后的迟到结果不再写入 |
| `reconciling` | 重连后正在核对实际状态 | 阅读可用；核对历史、提交记录及执行器，不能立即重跑 |

同课程修改队列跨对话唯一；问答不进入写队列。若所用执行器不支持单会话同时运行，由适配器安排独立执行会话，不能因此阻塞全课程阅读或把普通问答误作修改。切换学习对话不回退画板。

并发处理规则：学生编辑目标后，通过运行中通知把变化及最新正文送到 Agent，并记录通知是否被接收；最终命令仍做版本检查。未成功通知时不能假装已处理同时修改，须同步最新内容后继续或进入需要处理状态。可兼容变更保留学生修改后整合，不兼容时只询问冲突部分；两种情况均在结果中说明。

恢复规则：先恢复课程已提交状态，再查询执行器实际状态及本地提交记录。断线不等于取消或失败；不能依赖 delta 自动重放。需要补做时提供“继续”，用户点击后以最新内容处理剩余意图，用操作 ID 去重。停止后禁止迟到的新提交；已提交操作不因停止被自动撤回。

首版优先复用本机 Codex 的正常登录和独立 app-server 会话。实现时检查当前 CLI/协议能力并记录版本；不读取或复制凭据，不依赖本聊天的内部工具。真实执行权限请求按实际执行器信息呈现，不与内容预览采纳混淆。

## C8：搜索与交互一致性

搜索范围固定为知识、个人笔记、对话和原文四类，可多选，默认全部。结果包含真实实体/消息/来源身份、版本、摘录和定位目标；描述模式可重写查询或重排候选，但只能输出确有内容的命中。新解释走 Agent 回答。无命中、索引尚未更新与来源不可读分别说明；编辑、导入和撤回后索引随已提交事件更新。

交互组件共享持久化的语义配置，输入变化只改变探索状态，不改知识事实或个人掌握状态。已绑定公式、图、表及输出随同一配置计算；若编辑无法转换为受支持语义，保留编辑并明确该探索结果需要核对，不能静默沿用旧计算。添加新的组件种类必须补充有限输入下的正确性验证和离线资源，不能直接执行内容文本里的任意脚本。

## C9：读写范围和验证证据

每个功能票提交可运行的端到端场景；不把“仅后端”“仅 UI 空壳”或“API stub 返回成功”当完成。所有新呈现遵守阅读顺序、B 全览、自然讲解、视线连续性和操作响应，并保留手绘、端正、配色。

完成证据记录实际命令与结果、浏览器可观察行为及未验证部分。自动化不能证明物理触控板手感；旧原型截图不能替代新应用检查。对源数据变更沿用既有检查/构建接口；本地服务检查使用临时课程副本，真实模型只验证必要的集成路径。
