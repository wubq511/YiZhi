# 本地复习系统：设计讨论记录

更新日期：2026-10-27。本文保存产品规则及其讨论经过。既有正式应用的整课验收见[2026-10-26 记录](../../legacy/review-board/验收/整课联合验收-2026-10-26.json)；新的架构设计、验证和未决问题从[架构决策总览](../architecture/架构决策总览.md)进入。后文的考试日期、首版准备与当时状态属于对应阶段记录，不代表当前尚未交付应用，也不代表下一版架构已验收。

## 核心理念

> 在用户需要的时候呈现必须但又充足的最小化信息。

视图组织以知识层级为先，再决定每层需要哪些内容。信息应足以支持当前的定位、理解或操作，避免同时呈现无关细节造成信息过载。精简展示也不能遗漏完成当前学习任务必需的结论、条件或操作入口。

2026-10-25，Robert 进一步明确：学生应能主要通过画板完成完整复习，正常阅读不依赖跳到外部资料或临时询问 Agent 来补齐内容。复习所需的正文、图示、方法、必要推导和题解应已在画板中；显示深度与收纳只控制哪些内容在此刻可见。原文回查和 Agent 解惑继续可用，但不作为正常复习的必经步骤。

## 阅读体验的长期要求（2026-10-25）

以下五点由 Robert 在真实内容原型试用中明确提出，适用于后续全部课程内容、布局和交互。后续增补内容、调整显示深度或更换画板实现时，必须继续满足，不能只作为本轮原型的修补项。

1. **视觉顺序与阅读顺序一致。** 主题、模块和知识单元按真实知识关系与学生理解顺序布局，以从左到右为主、从上到下为次。先给必要基础，再给方法与应用；并列分支保持并列，不因排版顺序制造前置关系。目录顺序与画板一致，不能随机摆框再用长线补救。
2. **保留主题内单元全览。** 进入主题先定位第一个知识单元；由阅读位置缩远，先能看清该主题包含哪些单元及其关系，继续缩远才回到 A 主题视图。必须有足够宽的中间缩放区间，不能刚离开单元正文就把 B 全部替换成 A；定位与显示深度变化保持同一画板及稳定空间位置。
3. **讲解自然、准确、连贯。** 采用学生能顺着读懂的完整句子，避免生硬口号、含义不清的缩写和机械拼接。符号、条件和术语在首次需要时说明，不能为了短而删去理解所必需的信息。
4. **减少视线跳跃。** 卡片内部按概念与条件、理解与规则、使用方法、例题练习组织；图、公式、解释和操作结果紧邻对应内容。卡片之间和主题之间也遵守连续阅读顺序，不让学生为了理解当前一句话反复跨栏、跨卡片找条件。顺序按具体知识调整，不机械套用同一模板。
5. **缩放与拖动顺手。** 参考 Excalidraw 等成熟画板，检查鼠标滚轮、触控板捏合、指针锚定、拖动和连续输入的响应。既不能迟钝，也不能突然跳层；连续手势不丢增量，不因频繁重绘关系或小地图卡顿。输入方式应明确，不能依靠不可靠的设备猜测。

以上要求与已接受的手绘笔触、端正排版、内容配色同时成立。具体验收见 [阅读体验检查](legacy-v1/首版交付与接入验证.md#阅读体验检查)。

2026-10-25，Robert 在试用修订后的真实内容原型后反馈“差不多可以”。当前阅读布局、三级显示深度、讲解组织和画板操作方向已获基本认可，作为后续实现基准；细节继续按实际使用反馈调整。后续扩充课程内容或接入功能时，继续遵守上述五项要求与三项视觉要求。此处记录的是原型方向认可，正式应用的完成状态仍以验收文档为准。

| 例题与练习 | 例题展开后直接显示完整讲解；练习先显示题目，提示与答案由学生按需揭示。材料均提前备齐，查看答案无需询问 Agent。 |
| 原文核对 | 点击来源后，在当前页面临时展开可收合的原文阅读区并定位原页，保留画板位置；原文选段也能携带出处进入提问。 |
| 阅读工作区 | 画板、原文和 Agent 可同时查看，都按需展开、可调宽。空间不足时优先保证当前操作区域可读，允许暂时收起画板或其他区域；恢复时保留画板位置、原文页码和聊天草稿等状态。 |
| 资料范围 | Agent 优先依据课程资料，允许按需要使用通用知识、类比与查证补充；原文依据可回查，补充解释与原文清楚区分。 |
| 课程笔记参考 | 将既往 `笔记/` 纳入复习正文准备的参考，吸收有助理解的讲法、推导与易错提醒，保留出处并对应正式知识单元；课程范围与评级继续按已确认的教师资料和证据规则。 |
| 资料变更处理 | 导入新资料或替换资料后先提示，由用户决定是否更新画板；不自动修改画板。用户选择更新后，结果直接呈现并可撤回。 |
| 新旧资料并存 | 暂不更新画板时，Agent 仍可查阅新版资料；涉及新旧差异时说明依据版本与差异，保持画板和旧引用，并保留旧依据供回查。 |
| 对话组织 | 每门课可保存多段对话，自动保存并默认继续最近一段；对话共同服务同一张课程画板，切换对话不会切换或回退画板内容。 |
| 课程搜索 | 支持关键词与描述性查询，查找已有内容；默认搜索课程内的知识内容、个人笔记、历史对话与资料原文。用户可选择查询范围，结果按类别清晰呈现并可定位到出处；进一步解释可交给 Agent。 |
| 内容更新 | 所有修改直接出现并持续自动保存，可随时撤回、回退和继续修改；不设“先预览、再采纳”的内容更新门槛。正常使用不把保存操作留给学生。 |
| 修改意图与边界 | 采用改写、纠错、补充理解、扩展内容、整理结构与布局、精简或移除六类意图区分。主内容有缺漏就补好主内容，额外帮助理解的材料默认放入附注；一次请求可包含多种意图。 |
| 关联纠错范围 | 同步修正直接受影响的主内容，并简述改动对象；更广泛的章节重组由相应整理请求触发。 |
| 任务执行 | 任务绑定提交时的目标，后续浏览和选择变化不改变该目标；完成后提示并提供前往改动的入口，保持当前阅读位置。停止保留已完成修改，撤回本次修改另行执行。 |
| 修改任务顺序 | 同一画板的独立修改任务默认按顺序执行，问答和阅读可以继续；任务开始时依据画板最新状态处理提交时的目标与要求。这与运行中发送新消息的“引导／排队”设置分别管理。 |
| 运行中发送新消息 | 在设置中选择“引导／排队”，默认“引导”。引导下由 Agent 理解消息并响应补充、纠正或独立事项；排队下等待当前处理结束。输入区不另外提供“下一轮处理”入口。 |
| 修改过程可见 | Agent 修改期间，画板原位实时呈现实际变化，完整部分持续自动保存；正在输入或选择的片段暂缓替换，保护学生操作。具体边界见 [系统架构讨论](系统架构讨论.md)。 |
| 跟随修改 | 默认跟随 Agent 当前修改内容；学生主动平移、缩放或导航时立即接管，后续输出不抢回视野。显示“返回并继续跟随”按钮，由学生决定何时定位当前修改处并恢复跟随；任务结束后改为“查看修改结果”。再次主动发起修改时默认跟随；当前内容可读时不反复移动或缩放。 |
| 自动保存 | 正文、公式、个人笔记与标注、布局、复习状态、学习对话和输入草稿都自动保存，不要求点击保存或退出编辑。保存失败时明确提示并保留待保存内容；不能把生成成功当作真实落盘。 |
| 人与 Agent 同时修改 | Agent 必须感知学生在任务执行期间对目标内容的编辑，保留学生最新修改并基于最新内容调整；完成后明确告知发生过同时修改、涉及哪里及如何处理。无法兼容时只询问冲突部分。 |
| 笔记归属 | 笔记可关联整个对象或具体片段，随所指内容移动；改写后保留笔记与原引用，关联失效时提示重新关联；原对象删除后笔记仍可找到。 |
| 拆分合并后的笔记 | 能明确对应的笔记自动关联到新位置；无法确定时保留笔记与原引用，提示重新关联，不向所有新单元自动复制。 |
| 复习状态 | “待复习／薄弱／已掌握”互斥，标记对象为知识单元 B，新单元默认“待复习”；主题 A 仅显示下属单元状态汇总。学生可随时修改 B 的状态，与课程重要性星级分开，支持定位和筛选；Agent 不自行判定学生已掌握。 |
| 内容变化后的状态调整 | 已掌握内容的重要结论或方法实质变化后，Agent 主动询问学生是否调整原标记，学生确认后再更改。未确认时保留原状态；纯措辞、排版调整无需额外提醒。 |
| 失败恢复 | 自动恢复阅读和已保存内容，先核对任务实际状态；未完成任务提供“继续”，用户点击后基于最新内容补做剩余部分，避免静默重跑和重复修改。 |
| 撤回与版本回退 | 撤回某次 Agent 修改时，保留后续个人笔记；恢复整幅历史状态另用版本回退。 |
| Agent 能力 | 包括提问、解释、修改、增补与添加交互内容，不能把入口仅称为“修改面板”。 |
| Agent 侧栏 | 可收起、展开和调整宽度，由学生按需操作；选中内容后的菜单也能唤起 Agent，并自动展开侧栏、携带所选内容。 |
| 本地边界 | 内容与阅读在本地；生成可用云模型；断网仍能阅读已有内容。 |
| 底层依赖许可 | 本地应用的底层库与 SDK 必须宽松开源，产品运行无需额外厂商授权或许可密钥；必要功能不依赖另行授权的 Pro 组件。 |
| 视觉与内容表达 | 采用实际样例 A 的字体、符号与手绘视觉；文字和整体框体端正排列、不做装饰性旋转，框线、电路与箭头保留轻微起伏和复描的手绘笔触，阅读体验优先。Excalidraw 默认浅色要求用于画布背景与系统控件；学习内容、知识框、公式、路径和个人笔记应使用协调且有信息含义的颜色，不能整体去色。主题切换与自定义后续再做。内容以带关系标签的概念图为主，单独追溯前置，并配题型流程图。 |
| 公式编辑 | 采用可视化公式编辑，学生无需先掌握或输入 LaTeX 源码；内部表示方式不成为学生操作前提。 |
| 手动编辑与标注 | 首版支持编辑文字、公式与笔记，绘制基础形状和箭头，以及移动、调整对象大小；工具栏按需展开。画笔标注明确为直线、波浪线和荧光笔高亮，均沿用已接受的手绘视觉，保持正文清晰可读。 |
| 复杂交互实验编辑 | 首版按完整内容对象组织，学生操作参数及声明可编辑字段，Agent 修改内部结构与逻辑；普通正文、公式和基础图形继续直接编辑。 |
| 图形标注与知识关系 | 手画箭头默认作为个人图形标注，沿用个人笔记的跟随与保留规则；明确选择“建立知识关系”并指定含义后，才加入正式知识关系。Agent 不把随手标注自动视为知识事实。 |
| 原型交付 | 提供可独立打开、全屏操作的网页原型；不再以对话内嵌交互原型作为交付入口。 |

## 当前交互建议

以下把已定方向落实为可检验的动作；细节仍可调整。

1. 打开后直接处于复习画板，章节／主题目录与小地图默认展开，可点击收起或重新展开。章节或区域入口是定位器，点击后移动、缩放视口，不打开多层目录页。
2. 导航只改变看到哪里，不自动重排节点。保留区域的空间位置，让反复阅读形成位置记忆；全图与上一处位置均可快速返回。
3. 点选概念、关系或一组内容后出现上下文菜单；学生可选择提问、解释、修改或添加交互内容。进入 Agent 时保留该选择，并展开侧栏。
4. Agent 侧栏可手动开关。普通提问暂定先在侧栏回答；明确要求添加时直接写入画板，回答也可一键加入。此项是当前可用的暂定规则，可继续调整。
5. 明确的内容修改直接呈现在原画板，并保留可理解的改动记录。导航的“返回上一处”与内容的“撤回修改”分开，避免混淆。
6. 更新可以分批呈现完整、可读的改动；直接生效不要求把尚未完成的中间文件或半段数据暴露给学生。
7. 修改按已确认的六类意图处理。表达不满意时原位改写，错误或缺漏修正主内容，额外解释可以作为可收合的补充说明保存；实际空间变化再按所改内容确定。
8. 后续内容通过知识引用跳到已经讲解过的知识主位置，并提供快捷返回。返回需要恢复来处的阅读上下文；具体按钮、连续跳转与状态恢复在原型中验证。
9. 资料变更提示用于决定是否发起更新任务；用户选择更新后按既有规则直接生效、可撤回，不增加生成结果的预览采纳步骤。

这份说明不把“外部 Agent”解释为学生必须切换到外部聊天。执行器可以位于后台，学生在画板同页完成操作、反馈和阅读。

### 单元内部内容的参考分类

以下六类仅用来检查各层可能需要哪些学习材料，不作为视图分层依据或已经确定的必备清单。图、文字、公式和交互属于表达形式；一段推导也可能承担必要解题步骤或额外辅助理解的不同作用。

| 学习用途 | 具体内容 | 数字逻辑示例 |
| --- | --- | --- |
| 概念与结论 | 定义、规则、公式、符号含义、适用条件 | MUX 的选择规则与选择端含义 |
| 结构与关系 | 对象组成、数据对应，以及经价值筛选的知识联系 | 电路结构、真值表、时序图，以及已审核的前置、构造与优化关系；数学等价可在公式和说明中表达 |
| 方法与步骤 | 一类问题的解法、判断条件与流程 | 选择变量 → 按选择组合分组 → 求各数据端表达式 |
| 例题与练习 | 题干、已知条件、解答、推导与变式 | 已有 MUX 示例；变式可供自己作答后核对 |
| 验证与探索 | 改变条件、观察结果、检验理解的活动 | 切换 x、y、z，观察被选中的数据端与 F |
| 对比与易错 | 相似概念辨析、典型错误、反例与适用边界 | 交换选择端顺序导致分组不同；区分相似器件的功能 |

这六类描述学习用途，不要求一类对应一张卡片，也不要求每个知识单元都凑齐六类。例题以展示方法为主，展开后可读完整讲解；练习以自行作答为主，先显示题目，提示和答案按需揭示。

附着在上述内容上的材料另行讨论：

- **补充说明**：在已有主内容之外，保存某次疑问的额外解释、类比或扩展推导；具体表达可以包含文字、图或交互。
- **个人笔记**：学生自己的理解、提醒或待解决疑问。它与补充说明在归属和撤回时的保留规则上不同，界面可以采用相近的收合形式。
- **来源引用**：指向依据所在的原文位置，按已确认规则打开原文阅读区。
- **复习状态**：已确认互斥的“待复习／薄弱／已掌握”，新内容默认待复习，与课程重要性分开；已掌握内容实质变化后由 Agent 主动询问，学生确认后调整状态。具体显示仍结合后续知识呈现讨论。

主内容缺漏与额外补充说明的边界已经确认；个人笔记的保留仍遵循此前的撤回规则。个人笔记关联对象或片段、保留原引用的原则已确认；具体附着入口与收合界面仍待细化。

## 已确认的修改分类与处理原则

普通问答继续按暂定规则先在侧栏回答。下面讨论的是明确要保存或改变画板的请求，不把“我没听懂”自动当作修改授权。

| 修改意图 | 典型请求 | 处理原则 |
| --- | --- | --- |
| 改写表达 | “这段太绕，换个说法”“把文字换成图” | 原位替换对应表达，保留其学习目的与关联 |
| 纠正内容 | “选择端标反了”“这个结论不成立” | 修正受影响的正文、图或关系；不能只在旁边加说明而保留错误主内容 |
| 补充理解 | “把另一种解释记下来”“给这里加个说明” | 保留主内容，附着到所指内容，以可收合的补充说明保存 |
| 扩展学习内容 | “补上缺的前置知识”“加一道变式题”“加一个交互实验” | 按学习用途加入相应知识单元；能否作为附注取决于它是额外解释还是复习主内容 |
| 整理结构或布局 | “把重复内容合并”“这几块换个位置”“重新组织这一章” | 区分内容身份与关系的整理、单纯位置的整理；笔记能明确对应时随内容关联，不能确定时保留原笔记与引用并提示重新关联 |
| 精简或移除 | “压缩这段解释”“这块暂时收起来”“删掉这段” | 区分改写压缩、隐藏和删除，不把折叠或暂时不看理解为删除 |

一次自然语言请求可能包含多种意图，例如“改正公式，再把原因补到 notes”；这份分类用于确定行为，不要求学生逐项选择内部操作类型。新增或整理个人笔记也应被支持，但其归属不能因 Agent 协助编辑而被当作可随生成内容丢弃的补充材料。

“按需展开”指显示已经备齐的内容，不等同于按需生成。“必要示意”属于完成当前理解或操作所需的核心，不能仅因它是图或例子就收起。A/B 的重要性评级继续按课程规则，个人复习状态与其分开。

## 当前候选与事实边界

“Archify 的交付形式”“自由画板”“Excalidraw 手绘风格”分别对应阅读结构、交互能力与视觉语言。偏好某种体验不等于必须采用它的原生数据格式。

个人笔记已确定跟随所指对象或片段，改写或删除后仍保留笔记和原引用；拆分合并后能明确对应则重新关联，无法确定则保留并提示。重新关联的界面仍需验证。知识正文采用单一主位置，其他位置引用跳转并提供返回；此处的区域不表示按期中、期末拆出不同视图。

公开接口核查与独立会话实测表明，同页 Agent 交互有可构建的执行基础。已通过 Codex App Server + stdio 验证真实问答、执行中学生编辑通知、保留新编辑并明确反馈，以及停止；画板仍需实现上下文、显示、保存与恢复。接口有实验性限制，当前验证不代表浏览器和课程内容已经完成集成。[接入核查](legacy-v1/agent-integration-feasibility.md) · [官方协议](https://learn.chatgpt.com/docs/app-server)

## 交互草图与验证

当前真实内容入口：[独立阅读原型](../../experiments/content-depth-prototype/index.html) · [操作与验证说明](../../experiments/content-depth-prototype/README.md)。下文保留早期 [交互草图](../../experiments/review-board/README.md) 的验证范围，与本轮真实内容原型分别记录。

独立网页已通过 Chrome 本地地址的整窗布局、区域定位、选中菜单、侧栏、直接更新、撤回保留笔记和刷新恢复验证。自动化调用网页全屏被浏览器拒绝，已验证备用提示；原生浏览器全屏与双击 HTML 的 `file://` 方式未直接验收，具体范围见打开说明。

上一轮比较了“分区总览”和“全图中聚焦”，验证了固定 MUX 示例的预览、采纳、撤回和笔记保留。根据本轮反馈，分区首页与采纳门槛已退出当前方向；旧草图仅保留为讨论历史。

本轮草图改为同一画布内的区域定位、拖动与缩放，可收起并调宽的 Agent 侧栏和选中菜单，以及直接更新和撤回。它只模拟指定的 MUX 问答与更新，不会处理任意输入要求、调用模型或修改正式资料；也不是手绘视觉定稿。

浏览器验收已验证区域定位、实际指针拖动平移、缩放、选中 I1 后经菜单展开侧栏、侧栏宽度从 290 调至 390 像素、直接补充解释、撤回与重做。先添加解释、随后编辑个人笔记，再撤回解释，笔记仍保留。新增交互中的 xy=01 在 z=0 与 z=1 时分别输出 1 与 0，与真值表一致。1024 像素预览能阅读全图内容；390 像素预览无横向页面溢出，远景显示标题，Agent 面板移至下方。检查期间未发现浏览器错误。

验收中修正了保存状态的回传导致选中菜单立即关闭的问题；聚焦范围现在按实际已出现的内容计算，新增解释的连线也随内容正确显示。上述验证只说明草图交互可用，未覆盖真实 Agent、持久化文件、冲突处理或完整课程内容。

前期 Excalidraw 原生 MUX 示例中的 35 个元素为 roughness=0，22 个文本为 fontFamily=3；它只验证了原生编辑与导出。后续已在图文样例中完成字体、笔触、排版与配色比较，当前接受的视觉基准见上文。

当前没有形成同时满足“难以逆转、有真实取舍、未来读者需要原因”的技术决策，暂不创建 ADR。
