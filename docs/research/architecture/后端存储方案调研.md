## 结论与推荐条件

**从学生提供资料到形成可复习内容，必须贯通“不可变输入与产物、可追溯执行、生成候选、校验发布、个人学习记录”。这些产品边界先于 WebUI、现有语言、文件格式和工具。** 500 个完整知识单元是阅读规模约束，不限制来源版本、解析产物、执行尝试和历史的增长。

- **A：JSON 权威内容＋SQLite 状态与历史**。只有直接编辑权威文本本身是明确产品需求时，其文件形式才构成优先理由。长期需协调正文发布、执行结果、血缘和历史的一致性；现有 journal 仅是该成本的代码证据，不是必须继承的设计。
- **B：SQLite 统一权威内容／状态、逻辑分层＋开放格式导入导出**。当前已接受方案：将候选状态、校验记录、正式修订、血缘、个人关联和提交回执放在同一事务边界，更直接地表达完整生产流程。大文件及解析产物可存为独立不可变文件，数据库管理身份与引用；这仍属于 B。选择依据是产品一致性边界，**不是普遍性能结论**。
- **C：按对象文本文件＋事务索引／日志**。当前不建议作为并列首选。它只在“经常按对象人工编辑／Git diff／独立处理文件”确有价值时值得继续；单凭 500 单元没有实际收益证据，反而增加多文件发布与恢复面。

按本轮明确纠正，旧工具零改造、迁移省事和继续采用 WebUI 都不作为主要选型理由。现有数据用于真实负载与未来迁移核验，现有实现用于观察失败边界；A 可作为比较对照，不拥有默认优先权。PRODUCT.md 中 JSON 权威约定描述当前运行状态，不约束未来方案；本轮尚未正式迁移。

## 长期生产流程：现在稳定边界，分阶段实现功能

用户最新明确：架构现在就必须容纳“学生提供课件／作业等资料 → 解析 → 抽取 → 内容生成 → 校验发布”的持续演进。自动抽取功能可以后续实现，不能因当前只做阅读编辑而把输入、产物和任务全部塞进一次对话。以下为候选合同，不预设数据库表、UI 形态或部署拓扑。

### 数据身份与执行事实

| 边界 | 现在应稳定的含义与约束 | 可以后定的实现 |
| --- | --- | --- |
| 来源与版本 | 稳定来源身份、不可变版本、原始字节摘要、课程范围及资料角色；新版本不能覆写旧证据。相同字节可共用资源，但不强行合并不同来源身份 | 文件存储布局、去重算法细节、上传方式 |
| 解析产物 | 每版 OCR／文本／表格／公式／图片产物绑定输入版本、解析器与配置版本、产物格式版本、摘要和错误；原页位置与派生文本位置均可回查。人工纠正形成新版本 | 具体解析器、OCR 模型、整文或分页面执行、产物内嵌或外置 |
| 阶段任务与尝试 | 分开逻辑任务和每次 attempt；记录显式输入清单、课程范围／规则版本、模型标识与可取得的版本、实际 prompt／上下文及工具版本、配置、输出引用、失败与取消状态 | 调度算法、worker 数量、运行器、prompt 内容、重试次数；可重跑不承诺再次生成相同字节 |
| 抽取与生成候选 | 抽取结果、关系提案和生成内容有自己的版本与证据；候选保存不等于已发布。更新候选绑定所依据的正式修订和学生编辑基线；重算候选不自动更换既有知识身份 | 候选细粒度、生成模型、一次生成一个块还是一致变更组 |
| 校验与发布 | 校验记录绑定候选摘要、输入／规则／校验器版本及具体结果；发布重新检查依赖、当前修订、学生草稿和 attempt 资格，再形成正式修订与回执 | 校验器实现、领域规则集合、可计算题目的验证工具；不将模糊置信分数当通用通过条件 |
| 证据与血缘 | 记录“此产物由哪次尝试、使用哪些版本得到”，以及候选论断对应的原文片段；依赖失效图与知识前置／语义关系图分别维护 | SQL 递归查询或应用内图遍历；无需先引入图数据库 |
| 学生个人内容 | 笔记、标注、状态和布局独立；正文中的学生改动保留修订来源，候选发布须比较其基线。关联保存原版本与原语境，无法证明对应时保留待关联 | 编辑器、锚点匹配算法、呈现方式 |

血缘采用“实体、活动、使用、生成、派生”的区分，参考 [W3C PROV-DM](https://www.w3.org/TR/prov-dm/#component1)，不要求实现整套 RDF 标准。**执行时读过某资料，不足以证明某论断被它支持**；因此执行读取集用于保守失效，论断证据用于核验来源，二者不能互相代替。PROV 本身也区分使用／生成链与实际派生关系。[PROV derivation](https://www.w3.org/TR/prov-dm/#term-Derivation)。

证据定位至少绑定不可变来源版本、页／区域或原文片段、解析产物版本及坐标／文本投影约定；不能只存“第 12 页”或某次 OCR 的 offset。[W3C Text Quote／Position Selector](https://www.w3.org/TR/annotation-model/#text-quote-selector)支持引用与上下文定位，也说明纯位置在内容变化后易失效。解析产物即使理论上能重算，已有发布证据依赖的旧版本仍须可回查；有损解析、人工纠正及不可复现输出不能当普通缓存直接删掉。

### 局部重算、提交与恢复

现在应稳定的操作合同只有：**登记／读取版本化输入与产物，启动／停止／核对执行尝试，取得依赖与影响范围，保存／校验候选，以及按修订条件发布和查询回执**。数据采用可版本化的开放表示，允许后续添加阶段与产物类型；不让第三方解析器对象、Python 实例或 TS 类型成为长期课程格式。

候选调度可从一个本地协调器、持久任务记录和少量 worker 开始。领取阶段、登记完成、取消资格和发布使用短事务；解析、模型请求及校验计算在事务外执行。SQLite 的事务与唯一性约束可支撑本地任务去重和条件更新，[UPSERT](https://sqlite.org/lang_upsert.html)处理唯一键冲突，[recursive CTE](https://sqlite.org/lang_with.html#recursive_common_table_expressions)可遍历依赖；这些能力不自动提供完整调度器、正确血缘或外部模型调用的 exactly-once。当前没有证据需要 Redis、队列服务或分布式调度。

- **复用与重跑分开。** 输入版本／实际读取集、阶段实现、prompt、模型／工具及配置共同构成复用依据；同一请求重试返回已有结果，显式重新生成创建新 attempt／候选。仅输入文件相同不代表两次生成请求等价；未知或可变的模型版本应如实记录，不承诺严格复现。
- **失效不删除。** 输入变化标记依赖它的候选及下游产物需要重算／复核，旧正式内容仍可读且保留旧引用。只按已记录依赖收窄范围；依赖不完整时扩大到可能受影响的组，不能宣称精准局部重算。若阶段实际读取整份资料，则整份版本变化可能使该阶段失效；缩小计算粒度需要真实输入隔离。
- **文件完成与任务完成分开。** 外置产物先写完整并校验摘要，再在事务中登记产物、血缘及 attempt 结果；文件发布后崩溃允许留下待核对孤立资源。旧／已停止 attempt 的迟到结果不能被登记为新的有效完成或发布。停止保留此前已提交候选／内容，重开核对记录，继续仍需明确动作。
- **外部执行可能结果未知。** 模型已执行但本地没有收到结果时，先按执行器请求身份核对；无法核对就记录未知，不能因本地去重键存在而声称没有重复调用或费用。保存实际输出用于恢复，不能靠再次生成“恢复”原结果。

### 具体场景：新版作业只重算受影响候选

以下为设计场景，使用示意身份，不是对正式课程的新知识判断或已实现验收。

1. 学生加入作业版本 `S2`，其中第 4 页第 3 题修正一个条件；保留 `S1` 原件、解析产物 `P1` 和现行已发布修订 `R10`。登记新资料并解析不直接更新画板；学生选择“根据新版更新”后启动内容更新任务。
2. 用记录了实现／配置版本的解析阶段得到 `P2`，保存题目条件与原页区域对应。解析器可以重扫整份文件；只有经校验输入上下文未变的局部产物才复用，不能仅按页号或文本 hash 假定同一段。布局重排但内容未变的页也要核对新的证据定位。
3. 影响分析发现该题解析片段被“例题解答候选 C1”和依赖它的“方法说明候选 C2”使用，另一主题候选 C3 的完整读取集不受影响。因此仅为 C1、C2 建立基于 `S2/P2/R10` 的新尝试，复用 C3；旧正式内容继续可读。若解析无法可靠定位差异，则扩大受影响范围并记录原因。
4. 新候选附具体证据和依赖。程序校验身份、引用存在性、来源版本／区域、关系端点／方向／AND-OR 组、约定的关系价值与来源字段，并对适用的公式／真值表／题解运行独立领域检查。**结构合法和引用可打开仍不证明推导成立；LLM 自称“来源与关系已校验”不能构成通过记录。** 无法由规则或独立工具判断的证据支持、关系含义及矛盾留为待核对，必要时请求人工判断，不静默标为已通过。
5. 生成期间学生已经改了方法说明的同一块，并在旧例题旁写了笔记。发布先比较当前修订与草稿：重新整合该块后重验；不能只替换成最新 revision 再发旧候选。笔记保留原引用，只有明确的内容对应才更新锚点。互不依赖的候选可独立发布；相互依赖的解答／方法作为一致组校验和提交。
6. 在仍有效的更新意图下，通过校验的组自动成为下一正式修订，记录候选、校验、来源、块对应、历史和提交回执，并触发派生索引更新。此处“发布”是课程正式内容提交，不新增每组预览采纳步骤。提交前若收到停止或依赖再变则拒绝；提交后丢回执，以原操作身份查询，不重算、不重复发布。以后查笔记仍能回到 `S1/R10` 的原语境。

### 对存储与语言候选的影响

这条链增强了 **B：同库管理权威元数据、候选／正式内容及学习状态，外置不可变大产物** 的验证优先级：发布涉及的多种事实能共同提交，文件职责限定为可校验资源。A 也能承载全流程，但每次跨权威正文与执行账本发布都要自建一致性协议；C 只在对象文件直接创作有实际需求时增加价值。三者都须保留可移植的版本化交换合同；“支持开放格式”不要求开放文件与数据库同时可写且同时权威。

存储与执行合同不应锁定 Python 或 TypeScript。Python 的 [ProcessPoolExecutor](https://docs.python.org/3.14/library/concurrent.futures.html#processpoolexecutor)可在进程中运行计算，但对象传递有序列化限制；Node 的 [worker_threads](https://nodejs.org/api/worker_threads.html)面向 CPU 密集的 JavaScript，异步 [child_process.spawn](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options)可以运行外部解析工具。这支持“统一课程提交边界＋可替换阶段执行器”的候选，而不证明某语言已经胜出。

语言选择应由候选解析／OCR／校验组件的真实能力、宽松许可、发布打包和跨进程成本验证：可以是单语言，也可以仅将确有收益的阶段放在另一语言的本地 worker。跨边界传递输入／产物引用、版本化请求、进度和终态，外部 worker 不直接改正式内容；不用为每个阶段部署微服务，也不因当前工具用 Python 或未来界面可能用 TS 而决定全部后端语言。

## 官方语义核实及对本产品的含义

以下“官方事实”与“产品推论”分开；本节是文档核实，不是本项目动态验证。链接均为 SQLite／Python 官方来源。

### 写事务与单写者

SQLite 一个数据库同时只能有一个写事务，多个连接可以轮流写；WAL 支持读写同时进行。`BEGIN IMMEDIATE` 提前申请写事务，其他写者存在时可能返回 `SQLITE_BUSY`。读者可持有旧快照；读后升级写入可能遇到 `SQLITE_BUSY_SNAPSHOT`，不能继续把旧读取当作新依据。[Transaction](https://sqlite.org/lang_transaction.html)、[Isolation](https://sqlite.org/isolation.html)。

产品推论：单人仍有多标签页、学生编辑、Agent、自动保存和索引维护并发。建议一个课程的正常写入通过同一提交协调边界，其他进程不绕开它；模型生成和资料解析放在 SQL 写事务外，提交时再核验版本。busy timeout 只是等待锁，不能实现学生优先或防旧内容覆盖；也不应让 30 秒等待悄悄阻塞正常编辑。

多标签页不需要每页直连数据库：标签页持自己的编辑会话、输入序号和依据版本，服务统一排序与回执。不同标签页的同一草稿不能无版本地“最后到达覆盖”；具体会话表达属于后续接口设计。多进程 Service 若要支持，必须让停止资格、读取依据、幂等与提交在同一跨进程边界成立，不能只复用 Python RLock。

当前 Python 连接 `isolation_level=None` 配合显式 BEGIN，属于官方支持的事务控制路径；Python 3.12 起还有 autocommit 属性，未来适配时必须明确其模式，不能直接设 `autocommit=True` 后仍假定 `Connection.commit()` 会提交显式事务。[Python sqlite3 transaction control](https://docs.python.org/3.14/library/sqlite3.html#transaction-control)。这不是更换 Python 的理由。

### WAL、checkpoint 与备份

WAL 中可以存在已经 commit、尚未搬回主数据库的内容，checkpoint 负责搬回。自动 checkpoint 默认阈值为 1,000 页；长读事务可能阻碍完成。`-wal` 属于持久状态，不能手动删除或只复制正在使用的主数据库；WAL 要求参与进程在同一主机，不适合作为网络共享目录上的并发数据库。[WAL](https://sqlite.org/wal.html)。

`wal_checkpoint(TRUNCATE)` 成功时才把 WAL 截断；返回三列中的第一列表示是否因 busy 未完成。当前 `CourseStore.close()` 检查这一列并报错（storage.py `:346–363`），所以“已调用关闭”不能自动等同“checkpoint 成功”。[PRAGMA wal_checkpoint](https://sqlite.org/pragma.html#pragma_wal_checkpoint)。

备份边界建议：

1. 已确认的正常方式仍为**停止服务与所有写者后复制完整课程目录**。若异常退出遗留 journal/WAL，保留整套恢复材料，交由应用在恢复阶段核对；不先清理所谓临时文件。
2. 若后续需要不停服备份，SQLite 使用 Online Backup API（Python `Connection.backup()`）或 `VACUUM INTO` 生成数据库一致快照；**数据库快照不是课程目录快照**。A 还须在课程协调边界捕获匹配的知识 JSON；A/B 都须固定资料版本与附件引用清单，并阻止复制过程中回收仍被该清单引用的附件。[Backup API](https://sqlite.org/backup.html)、[Python backup](https://docs.python.org/3.14/library/sqlite3.html#sqlite3.Connection.backup)。
3. 只有完整快照生成、文件同步和清单验证完成，才发布“备份成功”。`VACUUM INTO` 输出也是一致快照，但执行中断可能留下不完整目标文件，不能把目标存在当成功。[VACUUM INTO](https://sqlite.org/lang_vacuum.html#vacuum_with_an_into_clause)。

无需为了研究 A/B 改成数据库服务，也无需把活跃课程移到网络盘；“迁移整个课程文件夹”与“在共享盘多人并发写”是不同需求。

### 持久化与异常恢复

官方原子提交保证的是数据库事务的全部或全无，依赖文件系统与同步机制正确工作；WAL＋FULL 增加每次提交的 WAL 同步，而 NORMAL 可能在断电后丢失最近已提交事务。当前 FULL 是基线，不能为未测量的性能收益直接降级。[Atomic commit](https://sqlite.org/atomiccommit.html)、[PRAGMA synchronous](https://sqlite.org/pragma.html#pragma_synchronous)。

需要分别处理：

| 情况 | A | B | 共同验收条件 |
| --- | --- | --- | --- |
| 进程在提交中退出 | 先由 SQLite 恢复，再按持久意图和 operations 核对 JSON；当前已有对应路径 | 同库正文／个人状态／历史／回执由同一事务恢复 | 已确认保存的内容仍可读；未确认命令以原 operationId 查验，不靠重新生成 |
| 正文已保存，任务记录或通知未更新 | 以 operation 中 task 关联重建任务结果 | 同样需要；可以把必要关联放进共同提交，但外部执行器仍不在 SQL 事务中 | 不重复修改、不把通知失败当保存失败 |
| 服务重开，任务未完成 | 核对执行器与本地账本，保留草稿／输出 | 同左 | 不静默重跑；明确继续才新建执行尝试，旧尝试不能重新获准写入 |
| 文件／数据库实际损坏 | JSON 可单独检查，但个人状态／历史仍依赖数据库；journal 不保证修复任意坏文件 | 从一致备份恢复，开放导出提供额外可读副本 | 数据库检查通过之外还要验证知识语义、引用、对象身份和附件摘要 |

SQLite `.recover` 是损坏后的尽力抢救，可能缺记录、复活已删除内容、破坏约束；不是日常恢复或备份的替代方案。[Recovery limitations](https://sqlite.org/recovery.html)。

A 还有一个外部可见性边界：JSON rename 完成但 SQL 未 commit 的短暂期间，绕过 Service 直接读取文件的工具可能看到尚未最终确认的正文。当前统一读入口和 writer_lock 可保护合作方，不能赋予任意文件读取者跨存储快照。这比“能否在编辑器打开 JSON”更接近需要决定的问题。

### 附件／资料版本：SQL 事务不覆盖任意文件

当前上传先把资料写入临时文件并 fsync，以摘要命名、硬链接独占发布，再提交来源版本与操作身份；失败时只在确认无引用的情况下清理。证据：[material_import.py](../../../legacy/review-board/reviewboard/material_import.py) `:158–185,196–207,220–289`。它已经把文件发布与业务提交区分开，方法值得保留，但不能从文件头的 atomic 描述推导出所有物理写入是同一事务。

即便 B 把所有元数据统一到 SQLite，外部 PDF、图片、组件资源仍不是 SQL 事务的一部分；SQLite 多库 WAL 提交也只保证每个库自身原子，不能靠 ATTACH 把外部文件纳入原子组。[WAL limitations](https://sqlite.org/wal.html#overview)、[Python os.replace](https://docs.python.org/3.14/library/os.html#os.replace)。

推荐的共同候选协议：完整资源先持久发布、校验摘要，再在业务提交中引入引用；崩溃留下未引用文件可以后续核对，不能产生“saved 成功但目标资源尚未发布”的引用。删除／回收必须考察当前内容、笔记、对话原引用、历史和备份持有的版本；不以当前正文不再引用为唯一删除条件。直接内嵌 BLOB 可把特定资源纳入同库事务，但会改变备份和访问方式，当前没有把全部资料内嵌的需求或实测依据。

### FTS、中文与索引重建

当前子串搜索能匹配中文片段；换 FTS 时不能只验证英文 `MATCH` 就称为等价。

- `unicode61` 按 Unicode 类别区分 token／分隔符，连续 token 字符形成一词；它不是中文词法分词器。由此推论，无空格的中文片段不能默认获得当前任意子串召回。
- `trigram` 支持子串，但全文 MATCH 的查询少于 3 个 Unicode 字符不会命中；短 LIKE/GLOB 没有可用三元片段时需扫描。二字词、单字器件／符号、公式和混合英文都必须有明确回退。
- external-content FTS 的内容表与索引一致性由应用负责，新增触发器不会补建旧记录；`rebuild` 可以按内容表重建，contentless 表不能直接用这条命令恢复内容。

以上见 [FTS5 tokenizers](https://sqlite.org/fts5.html#tokenizers)、[trigram](https://sqlite.org/fts5.html#the_trigram_tokenizer)、[external-content pitfalls](https://sqlite.org/fts5.html#external_content_table_pitfalls)、[rebuild](https://sqlite.org/fts5.html#the_rebuild_command)。

候选路径：先保留可验证的子串回退；比较 trigram＋短词回退与独立中文分词器，只有召回／延迟／体量实测支持后才引入额外分词依赖，并核对其宽松许可。500 单元不构成现在必须上 FTS 的证明；课程原文和长对话可能才是搜索规模来源。

当前产品基线已由 Robert 确认为**本地基础检索＋联网描述增强**：离线提供关键词、别名和符号匹配；联网时 Agent 可将含义描述转为可检索表达，再从真实已有内容返回结果。当前不引入本地语义模型，也不要求离线复杂描述召回与联网相同；索引技术继续按上述真实查询证据收敛，不能用新生成解释冒充命中。

索引必须是可重建投影，记录其对应的内容／资料／消息版本与投影版本。A 从一致的 JSON＋个人对象快照重建，B 从一致数据库快照重建；OCR／原文提取是另一个可重建层。命中返回真实对象、片段、版本和定位，不能把生成解释当搜索结果。后台索引允许滞后时须明确保存游标与索引游标不同；重要的保存后即搜可用同步小范围更新或当前对象直查补齐，不伪造索引已跟上。

## 自动保存、历史与版本更新的共同设计

这些是 A/B 均需要的行为接口，**不是数据库表 schema**。

| 数据种类 | 推荐保存语义 | 不应混用的概念 |
| --- | --- | --- |
| 正在输入的正文／公式与工作草稿 | 持续保存编辑会话、基线与有序草稿；无效／未完成内容也能保存；有效部分自动转正式变更组 | 草稿已保存不等于正式正文已更新；不增设手动保存／采纳门槛 |
| 学生正式编辑和 Agent 正式修改 | 在短提交边界校验身份、generation、读取依据、写入依据和当前尝试资格，产生回执 | 画面先显示或模型返回成功不是 saved；通知送达不是依赖重新读取 |
| 学习对话输出 | 按消息／内容片段追加并确认持久偏移；最后完成状态独立记录 | 不为每个 token 复制整段会话及全部课程历史；输出部分已保存不等于任务完成 |
| 布局／阅读／实验状态 | 领域独立，按对象保存基线和可序列化状态；重复高频输入可以合并，实际保存状态仍真实 | 临时布局投影和组件实例不能成为权威知识；合并写入不等于停止自动保存 |
| 事件与历史 | 回执和必要前后值同业务提交；以正式变更组支持撤回，列表与差异按需计算 | WAL 不是永久业务历史；不另外复制一套全文事件；额外全课快照只在实测需要时加入 |

当前每次知识提交的 before／after `_checkpoint()` 会保存整份知识和所选个人状态（content_commands.py `:208–221,564–576`）；通用 apply 又保存事件、请求／回执及历史。Robert 已选择正式修改历史＋可恢复草稿，并要求控制性能、存储和复杂度。新设计先保留一套变化对象的必要前后值和最新草稿，不把所有复制模式原样迁入 B，也不先建设周期快照、差分压缩与分支体系。具体方案和 ⌘/Ctrl+Z 的区别统一见[历史管理与恢复设计](../../architecture/历史管理与恢复设计.md)。

后续[历史成本实验](../../../experiments/history-spike/README.md)已在相同当前数据写法、操作轨迹和持久化等级下比较整单元与变化块历史。正文历史载荷约减少 93.85%，但总库大小、增长量和物理 I/O 不是同一分母，保存延迟也并非各轮都更好。这支持先去除大粒度复制，不支持立即增加压缩系统或将其当作正式 CourseService 性能结论。

### 选择性撤回与资料更新

当前 `undo()` 从操作历史生成逆变更，与当前值三方合并；同一字符串视为原子片段，非知识对象被后续修改则冲突，不回退整个数据库。整幅 restore 则另行恢复选定个人状态、提高 generation，并保留执行事实及新来源版本。证据：content_commands.py `:41–90,643–687,689–759`。

这为“保留后来的个人内容”提供已有机制，但不能据此声称普通块拆合、重复短句和所有高亮都能自动重定位。正文逆变更、块身份对应与笔记／标注的原语境和待重关联状态，需要共同校验。B 让这一组变更易于同事务落盘，仍不能自动决定语义对应；A 经 journal 也可实现。

SQLite Session Extension 可记录、反转和应用行 changeset，有冲突处理；默认编译关闭，需启用相关编译选项。它不理解“后来的笔记”“学生优先”或 JSON 内块拆合，不宜直接替代当前语义历史，也不应先增加绑定依赖。[Session Extension](https://sqlite.org/sessionintro.html)。

资料新版本仍按不可变身份追加，学生选择更新才生成画板变更；引用不能因 current 指针更新而偷换。应用／课程格式升级和资料版本升级也应分别管理：开放导入导出须保留稳定身份、来源版本、正文结构与资源相对路径；整课备份则还须保留个人内容、草稿、对话、任务及历史。仅导出 Markdown 或当前正文 JSON 不等于完整可迁移备份。

未来迁移须读取既有知识身份、原引用、个人内容、任务与历史，而不是只迁当前正文。当前 `KnowledgeCatalog` 依赖文件 mtime／size，`ContentCommands` 依赖 JSON 路径及私有 SQL 接口，说明迁移需要专门适配；这些类和接口名不必成为新架构。新边界按生产与学习领域定义，旧格式只通过迁移／交换适配器进入，并验证含义与身份保留；不得运行时双向同步两套权威正文。

## 真正影响存储的根产品决定

以下供主讨论后续收敛，不是本报告向用户提出的新问题；不重复确认自动保存、离线或可迁移。

| 需要明确的分界 | 为何影响选择 | 当前推荐条件 |
| --- | --- | --- |
| 课程资料角色、范围与哪些校验结果允许自动发布 | 决定抽取／生成输入和发布资格，不能让模型自行扩大课程范围或自称审核通过 | 长期接口现在表达范围／规则版本、证据和待核对状态；具体领域校验器后续实现 |
| 权威内容写入方式已确定 | 已确认画板／接口＋开放格式交换足够，不要求直接编辑内部权威文本 | 已选择 B；开放导出不成为第二套可写权威 |
| 核心写入组织已确定 | TS／Node Worker 统一执行提交资格与版本校验；SQLite 锁只处理存储写事务，不能代替任务资格 | 一个应用核心管理多课，窗口共享对应课程入口；重复打开和异常恢复仍需验证，不默认多个独立写入运行器 |
| 历史粒度已明确；保留与清理仍需结合实际增长 | 已选择正式修改历史＋可恢复草稿，不要求永久逐键／逐 token 回放 | 先避免全课／整段会话重复复制；不静默删除正式历史，不据此承诺无限保留或预置压缩系统 |
| 正常停止后整目录复制之外，是否需要不停服一致备份／自动快照 | A 需额外捕获 JSON 与 SQLite 的共同版本；B 少一个正文文件边界，但仍有附件 | 当前按已确认的停止备份实现验收，不把在线备份当首版已承诺功能 |
| 搜索必须覆盖哪些中文短词／公式与别名，是否要求保存即搜 | 决定 token 策略、短词回退和索引一致性合同；不直接决定权威存储 | 保住当前子串召回，再以小型金标集合比较；描述性查询只返回真实内容 |

“内容、状态、布局分离”本身不要求分成不同物理存储；“宽松开源”也不迫使采用 JSON。SQLite 官方交付代码属 public domain，无需运行许可密钥；所选语言绑定、中文分词器、备份工具仍应单独核对，不把可选付费支持当必需许可。[SQLite copyright](https://sqlite.org/copyright.html)。核心语言与承载已另见 [ADR-0003](../../adr/0003-typescript-node-worker-core.md)，具体 schema 和绑定仍属实施选择。

## 后续最小可判别验证

下表保留原比较计划，不表示已完成所有格子。B 的共同事务、混合保存、故障、停止竞争与有限迁移已完成隔离验证，结果见下一节；A 同条件对照、语义编辑与选择性撤回、完整资料、在线备份和长期负载仍未完成。中文检索另有独立实验。没有进行正式课程迁移。

长期流程的首个可判别实验可用小型合成资料和确定性假生成器完成，无需付费模型：一份资料改一个条件，断言只重算其真实依赖闭包；改解析器／prompt 版本时对应候选失效；缺证据或校验器未支持时不可自动发布；学生同块修改和旧 attempt 回调不能越过发布门禁；分别在产物文件完成、登记、发布前后退出，验证去重、旧引用可回查和重开不静默重跑。它检验合同与恢复，不证明真实 OCR／抽取／生成质量。

| 顺序 | 最小实验与记录 | 可判别结果 |
| --- | --- | --- |
| 1．合同等价 | A 与 B 的薄适配器承载同一小课程：有效／无效草稿、块编辑、关系变更、来源版本、个人笔记；只检查公共读取与命令回执。B 导出再导入隔离目录，比较稳定 ID、语义结构、资源摘要、个人内容与历史关联 | 先排除“B 导出只剩正文”或“A 直接编辑丢个人状态”的伪等价；不先设计完整 schema |
| 2．真实混合保存 | 分别用 84 单元真实结构和 500 单元合成完整正文；固定合成历史长度和输出字节流，混合草稿、布局、状态、正文小组提交与搜索。记录保存确认 P50/P95／最大值、失败、排队、重试、写入次数／字节、CPU／内存、DB/WAL／快照增长 | 将整段会话复制、全量 snapshot／校验、文件 fsync、SQL 锁等待分开；判断差异是否足以值得迁移。相同持久化等级、负载与机器，重复运行；不靠前端 rAF 数据推断后端 |
| 3．最小故障矩阵 | A 在 after_journal／before_replace／after_replace／before_sqlite_commit／after_sqlite_commit 各点退出；B 在 commit 前后退出；双方都在附件发布与元数据提交间退出、丢回执再重试 | 重开后 content／personal／history／receipt 一致；相同 operationId 不重复；允许确认可清理的无引用附件，不允许引用缺文件却 saved |
| 4．并发与停止 | 两标签页同块／异块输入；Agent 读 A、B 后只写 A，学生改变 B；保存草稿但尚未形成正式正文；停止与提交同时到达；continue 后再送旧 attempt 回调 | 学生输入保留、依赖变化拒绝旧推导、停止后的新操作拒绝、停止前已提交回执可补齐，旧 attempt 不能复活；不以 steer 成功代替这些断言 |
| 5．选择性撤回 | Agent 改正文，学生随后加笔记／改另块／移动布局；依次撤回、拆合块、删除目标，再导入资料新版本与整幅恢复 | 个人内容不消失；不确定锚点保留原语境待关联；实质冲突明确；旧任务 generation 失效；资料旧引用仍可读 |
| 6．迁移／备份与中文检索 | 停止后复制完整课程到新路径；异常退出版本携 WAL/journal 恢复；在隔离副本删除派生索引重建。查询单字、二字、长词、混合英文、公式、错别名；若决定需要在线备份，再加 Backup API／附件清单组合实验 | 迁移后不依赖原路径／浏览器缓存；重建前后金标召回一致且定位版本正确；长读不导致 WAL 无界增长，checkpoint busy 不误报备份成功 |

现阶段不为了完整填表再造 A/C 或重复已通过检查。B 的部分 1／2／3／4／6 已提供共同事务的可行性证据；接下来优先补实际仍影响产品的编辑／历史合同及端到端接入。只有选型仍存在需要实测判别的疑点，才值得增加 A 同条件实现；C 不因比较表存在就成为实施任务。

阶段门槛建议：所有已确认保存的内容在约定故障边界内可恢复，幂等／停止／依赖／个人内容保护断言全部通过，再比较成本与体验。保存延迟阈值应由端到端体验和实测共同确定，本报告不杜撰“必须低于若干毫秒”的验收数字。

## 已补充验证：B 的事务、故障与有界保存

2026-10-27，[storage-spike](../../../experiments/storage-spike/README.md)在隔离临时课程内使用真实 SQLite 事务，最终 136 条断言通过。实验及依赖输入的哈希保存在机器记录中；文档哈希描述执行当时的合同版本，后续设计更新不应被误报为实验源代码漂移。

| 覆盖 | 实际结果与限制 |
| --- | --- |
| 共同提交与去重 | 正文、个人对象、历史、资源引用、任务与回执共同提交；丢回执重试取得同一结果；同 ID 不同载荷拒绝 |
| 故障 | commit 前、commit 后回执前、资源发布后登记前，分别实际异常退出／强杀，共六次；复制包含 WAL 的临时课程后可核对一致；不代表断电、磁盘坏或满盘验收 |
| 并发与停止 | 两个真实进程争用写锁，覆盖停止先提交与正文先提交两种顺序；旧 attempt、读取依赖变化和活动草稿阻止不合格写入 |
| 迁移与交换 | 目录复制及实验 JSON 表记录往返保留身份和关联；资源为合成字节，未搬运真实 PDF／图片，也不是生产交换 schema |

## 已补充验证：中文检索不能直接换成默认 FTS

2026-10-27，使用前端验证已经导出的 84 个真实单元及其正文块，另生成重复到 500 单元的负载，比较现有字面子串语义、FTS5 unicode61、trigram，以及 trigram 加短词子串回退。共 17 条指定查询，覆盖单字、二字词、长词、器件、别名、英文、公式片段和无结果项。数据库均在临时目录中创建并清理，未访问个人对话或修改正式课程。

两个规模得到相同结论：unicode61 有 13 条查询与子串结果不同，单用 trigram 有 6 条不同；加入短于三个 Unicode 字符的子串回退后，17 条查询的命中集合均与基线一致。删除并重建派生 trigram 索引后，命中集合保持一致。详细数字、投影范围、环境、fixture 摘要和复现脚本见[检索实验](../../../experiments/search-spike/README.md)。

因此不能把“启用 FTS5”当作现有中文搜索的等价替换。trigram＋短词回退值得进入下一步索引比较；本次不证明所有中文查询的相关性，也没有测量资料全文、长对话、并发更新、写入持久化或线上索引追赶。
