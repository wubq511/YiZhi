# 交互实验运行与迁移机制核查

2026-10-27。有界一手资料研究；未安装依赖、运行实验或修改正式代码。下文区分技术事实、设计推论与待测行为，不把接口存在写成实现验收。

## 结论与既定边界

**推荐常用组件注册表与课程内 HTML／JS 扩展并存，统一管理参数、状态、资源版本与生命周期。** 单独使用固定注册表无法覆盖已经允许的全新交互类型；任意 HTML 放进 iframe 也不能自动满足离屏暂停、故障隔离或课程迁移。

依据为 [PRODUCT.md](../../../PRODUCT.md) 的复杂实验、生成、离线与许可规则，[系统架构讨论](../../history/系统架构讨论.md)前 100 行与 317 行附近，以及[内容演进与实时修改协议](../../architecture/内容演进与实时修改协议.md#实验生命周期已确认默认行为)。沿用 Electron＋TS／Node、宿主拥有的课程核心 Worker、每课 SQLite＋资源、本地单人；学生修改参数和声明字段，Agent 修改内部逻辑；离屏默认暂停并保留现场。

关键区分：**宿主能力隔离限制代码能访问什么；CPU 故障隔离决定它卡住时谁还能响应。** Chromium sandbox 仍允许消耗 CPU 与内存，不能据此宣称无限循环已被限制。[Electron sandbox](https://www.electronjs.org/docs/latest/tutorial/sandbox)

## 两条可落地路径

| 路径 | 运行与离线载入 | 收益 | 真实代价与边界 |
| --- | --- | --- | --- |
| 固定组件注册表＋受限配置 | 应用交付已实现的控件，课程保存 `type/version/inputs/state`；renderer 只按类型映射，动作采用有限指令 | 能统一暂停、可编辑字段、错误展示和迁移；常用真值表、波形、参数图适合复用 | 组合能力受注册表限制；全新算法或控件仍需扩展。组件自身若阻塞 UI，同样会卡顿 |
| 受约束课程内 HTML／JS 扩展 | Agent 生成浏览器可运行的 HTML、CSS、ES modules 与资源清单；在独立实验源的 sandbox iframe 加载 | 新类型可随课程携带，无需把每种实验加入应用发布；可复用常用组件的浏览器构建产物 | 包含可执行逻辑，必须另做生命周期与状态适配；不能承诺任意网页都可无损暂停或迁移 |

第一条的“受限”应指数据与有限动作；若允许配置通过 `eval`、任意回调或动态导入宿主模块执行，就已经越过固定注册表的边界。这是设计推论，不能仅靠配置文件后缀判断。

第二条的模块包应是**已生成或预构建的浏览器资源**，不是运行时安装 npm 包。浏览器裸模块名需要 import map 或构建时改写，模块响应需正确 MIME；使用相对 URL／本地映射并把传递依赖一起带入课程，才能断网重开。[MDN modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)

这些机制不需要 Pro：iframe、Worker、CSP 是 Web 平台能力，Electron 自身采用 MIT 许可；但这不证明任意课程依赖均满足许可。资源清单保留准确版本、来源及许可文本，新增库继续遵守 PRODUCT 的宽松许可约束；不引入插件市场或在线授权服务。[Electron 固定版 LICENSE](https://raw.githubusercontent.com/electron/electron/v40.10.6/LICENSE)

## 宿主、iframe、资源源与通信各自负责什么

| 边界 | 能提供的机制 | 不能据此推出 |
| --- | --- | --- |
| Electron renderer sandbox | 无页面 Node 环境，特权操作需经宿主 IPC | 不限制计算总量，不替应用决定 IPC 授权范围 |
| `contextIsolation` | preload 与页面分离 JS 上下文 | 暴露出去的桥接方法仍可被页面调用；不是实验与画板之间的 DOM 隔离 |
| iframe `sandbox`＋不同源 | 限制导航、弹窗等能力，同源策略限制双方 DOM 访问 | 不承诺独立线程、独立进程或 CPU 配额 |
| CSP | 约束脚本、连接、资源与 Worker 的加载来源 | 不判断算法正确性，不停止获准脚本的死循环 |
| 自有 scheme＋资源路由 | 离线响应课程中明确存在的资源，建立稳定 URL | 不自动检查路径、内容哈希或跨课程资源权限 |

前两项依据：[Electron context isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[sandbox](https://www.electronjs.org/docs/latest/tutorial/sandbox)；后三项依据：[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)、[CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)、[Electron protocol](https://www.electronjs.org/docs/latest/api/protocol)。表中不承诺的部分是据机制边界得出的判断。

**宿主连接建议：**宿主保持 `sandbox: true`、`contextIsolation: true`、`webSecurity: true`，关闭页面、子 frame 与 Web Worker 的 Node integration；实验不获得文件系统、SQL、任意 IPC 或执行 Agent 的桥。画板接收实验数据后，再由 CourseService 执行本实例的保存。既定的 host-owned **Node Worker 是可信课程核心**，不能顺手拿来运行生成代码。[WebPreferences](https://www.electronjs.org/docs/latest/api/structures/web-preferences)

**实验源建议：**例如宿主 `app://workspace`，实验 `lab://<package-hash>/index.html`；URL 是示意，实际 origin 序列化须用目标 Electron 核查。实验按包划源，不与宿主共源；状态由宿主提供，不依赖实验 localStorage 形成第二权威来源。

`sandbox="allow-scripts"` 会使文档成为 opaque origin；通信的 `origin` 不能拿字符串 `"null"` 当唯一身份，模块 CORS 与 Worker 创建也需单独处理。若要常规模块与 Worker 加载，推荐在**确实不同于宿主的实验源**使用 `allow-scripts allow-same-origin`：后者保留实验自身源，不是把它变成宿主源；同源父子同时开放两者可能允许移除 sandbox，不能照搬到宿主同源页面。[MDN sandbox tokens](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)

自有 scheme 在 app ready 前注册；`standard` 支持相对资源解析，`secure` 是安全上下文属性，`supportFetchAPI` 是 Fetch 能力，三者均不等于“可信代码”，也不应启用 `bypassCSP`。`protocol.handle` 在对应 session 注册，处理器只按已登记的包与资源清单取内容，不把 URL 直接拼成任意磁盘路径。[Electron protocol](https://www.electronjs.org/docs/latest/api/protocol#protocolregisterschemesasprivilegedcustomschemes)

扩展页由宿主响应头设置 CSP，候选从 `default-src 'none'` 开始，脚本／样式／图片按包源开放，`connect-src 'none'`，需要计算才开放本包 `worker-src`；脚本外置，避免依赖 `unsafe-eval`。这约束资源加载，**不是完整的导航禁令**；新窗口与 frame 重导航另由宿主限制。Worker 脚本响应也要有 CSP，通常不会自动继承创建页面的策略。[MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy#csp_in_workers)

跨源用 `postMessage`，发送指定目标源，接收检查 `event.source === iframe.contentWindow` 与准确 `origin`，再验证消息结构；可在握手后转移专用 MessagePort。运行实例还需绑定对象 ID、内容 revision、运行代际与请求序号；重载／替换／销毁后关闭端口并拒收旧代际。源检查防串源，代际检查防旧实例迟到写回，互不替代。[MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)

## 离屏暂停：停止显示与停止计算不是同一件事

**能力事实：**CSS 隐藏 iframe 不触发其文档的 visibility 变化，iframe 的 Page Visibility 跟随父文档；画板平移把实验移出视口，更不能据此推断停止。浏览器可能暂停 rAF 或节流定时器，那是调度策略，不是实验时间与计算停止的产品合同。[MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

**能力事实：**Web Worker 无通用 `pause()/resume()`；标准接口提供消息与 `terminate()`。暂停消息只有任务让出执行后才能处理，长同步循环不会因发送消息立即停止；`terminate()` 可强制停止，却不给最后导出状态或清理的机会。[WHATWG Worker 接口](https://html.spec.whatwg.org/multipage/workers.html#dedicated-workers-and-the-worker-interface)、[MDN terminate](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate)

**推荐的最小运行合同：**`initialize(inputs, snapshot)`、`pause`、`resume`、`snapshot`、`dispose` 表达行为，不预定复杂 SDK。计算采用可让出的短步，在完整步边界产出带序号快照；离屏停止发新步、等待在途步确认，暂停动画、音频与计时，保留最后完整状态。未确认前只能标为“正在暂停”。

Worker 是浏览器 **Web Worker**，不同于课程核心的 Node Worker；持有其句柄的控制层要能终止它。Dedicated Worker 只由创建它的脚本直接访问，因此 iframe 自建 Worker 后，父画板不能凭消息端口自动取得 `terminate()`；若 frame 控制线程也卡住，父侧暂停请求同样可能无效。[MDN Using workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)

**故障退路：**暂停超时或逻辑失控时，能控制 Worker 的一侧终止它并从最近完整快照重建；这会丢失未确认的计算，不可声称精确冻结。若要求生成的 DOM 脚本死循环时画板仍可操作，普通 iframe 不足以作为证明，须验证独立 renderer／受控 webContents 的方案与开销；Electron 多进程是另一层机制，不由 sandbox token 保证。[Electron process model](https://www.electronjs.org/docs/latest/tutorial/process-model)

序列化保存的是输入、模型变量、模拟时间、随机种子及必要中间结果，不是线程栈、闭包、DOM、React 实例或 GPU 句柄。structured clone 支持的类型比 JSON 多，但仍不支持函数与 DOM，且不保留一般对象原型；“可 postMessage”也不等于已有稳定磁盘格式。[MDN structured clone](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm)

`dispose` 必须覆盖实际拥有的 Worker、timer、监听器、端口、媒体与外部订阅；React unmount、停止 rAF、移除显示节点均不能单独证明这些已结束。恢复按保存的实验时间继续；现实经过时间只用于内容明确声明、学生开启的后台运行语义，不默认补算离屏期间。

## 最小可迁移合同：字段为何需要，保证到哪里

以下是从离线加载、结构校验与状态重建推出的**本产品建议**，不是 Electron 或 JSON Schema 已有的完整实验迁移标准。

| 保存项 | 最小内容与用途 | 保证边界 |
| --- | --- | --- |
| 稳定实例与运行接口 | `experimentId`、`type`、`runtimeApiVersion`、定义 revision | 身份与宿主接口兼容性可核对；不能用 DOM ID 代替 |
| 不可变资源版本 | `packageVersion`、入口、HTML／JS／CSS／图片及依赖的内容哈希清单 | 能找到并核对同一份字节；只留 npm 名称／版本或 CDN URL 不够离线恢复 |
| 输入合同 | `inputSchema`／版本、当前 inputs、学生可编辑字段声明 | 检查类型、范围、必填与字段权限；不是所有声明字段都可让学生修改内部程序 |
| 状态合同 | `stateSchemaVersion`、对应 schema、snapshot、步序号与模拟时间 | 判断旧现场能否由目标实现解释；不同于资源版本，也不同于数据库格式版本 |
| 学习上下文 | 所属块／知识身份、来源引用、结果与个人状态的独立归属 | 更新程序不悄悄改知识身份或学生掌握状态；复用课程已有身份与保存边界 |

JSON Schema 可描述与验证 JSON 结构；`$schema` 指**校验方言**，不会自动表达实验状态版本或执行迁移。输入与 state schema 都应随包离线携带，外部 `$ref` 也需本地解析。[JSON Schema 2020-12 Core](https://json-schema.org/draft/2020-12/json-schema-core#section-8.1.1)

内容哈希提供字节一致性依据，不证明出处真实、算法正确或新旧语义相同；SRI 展示了浏览器对资源字节核对的机制，但不会替应用自动验证整个依赖图。这里建议由包清单覆盖实际依赖闭包、在发布／导入时核对，不假设入口 `integrity` 会递归保护全部 import。[MDN SRI](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity)

Agent 修改逻辑产生新资源版本；输入／状态兼容性由新版本明确声明。兼容时先在副本恢复；需迁移时执行明确的旧版→新版状态转换并校验结果，再经 CourseService 提交新引用与状态；失败保留原包与原快照。没有迁移器时保留旧版继续查看，不能静默清零现场或把结构校验通过写成教学语义正确。

SQLite 保存定义引用、输入、状态与确认事实，资源目录保存不可变包；备份必须覆盖被这些引用及历史依赖的资源。运行堆、浏览器缓存、绝对磁盘路径都不属于可迁移合同。此处复用既定课程备份／历史机制，不另造扩展发布平台。

## 仍需用目标 Electron 验证的内容

本轮没有实测；以下是机制尚不能替代的验收，不是额外的安全审批流程。

- 自有 scheme 下的真实 origin、不同包隔离、模块 MIME／相对 import／动态 import／Worker 与 CSP；断网且清空缓存后，从复制课程目录重开仍完整可用。
- 离屏后实际 CPU 与计时是否停止，返回后参数、模拟时间、随机序列和输入现场是否续接；含 Worker、timer、音频的销毁后无残留工作。
- 有意长同步循环、Worker 不回应、frame 重导航／重载与旧消息迟到：分别观察画板是否响应、暂停是否只是请求、最近快照能否恢复；不能只测静态页面或 UI 消失。
- 升级输入／状态 schema、缺依赖、哈希不符与迁移失败时，原版本和现场仍可找回；资源字节一致与学习结果正确分别验证，后者用具体课程样例与来源核对。

## 供主 Agent 收敛的三项产品设计决定

1. **内容表达：推荐两条路径并存。** 常用实验走注册表，新类型走课程内浏览器资源包；不让全画板依赖新 DSL，也不把新类型限制为必须更新应用。
2. **现场与失控边界：推荐把可分步计算、完整快照和生命周期适配纳入实验交付。** 正常离屏精确续接，异常回到最近确认快照；若要求任意生成 DOM 死循环也绝不拖住画板，再为其选择并验证独立 renderer，不能用 iframe 偷换这项承诺。
3. **升级行为：推荐不可变旧包＋显式状态迁移，失败保留旧现场。** 自动保存与升级成功分别判定，不自动丢状态；这比承诺任何未来实现都能直接读取旧运行堆更符合课程可迁移目标。
