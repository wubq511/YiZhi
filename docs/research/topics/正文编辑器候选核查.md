# 正文编辑器候选核查

核查日期：2026-10-27（Asia/Shanghai）。状态：设计讨论用的一手源码研究；不是技术选型决定或应用重写授权。

## 结论与适用范围

**建议优先讨论“Tiptap 开源核心＋ProseMirror 范围事务／history＋自定义 MathLive NodeView”这一组合；直接集成 ProseMirror 作为精简备选。** Tiptap 是 ProseMirror 的封装与扩展体系，不是第三个同级编辑引擎；其 UndoRedo 直接调用 ProseMirror history。推荐依据是已有开源 ID 扩展及定制入口，不能解释为性能或 IME 优胜。[TBased] [TUndo] [TID]

**Lexical 保留为对照候选，当前不优先。** 它具备结构化 JSON、自定义节点和跨段选区；真正不匹配的是默认 history 恢复 EditorState 快照，不能仅靠跳过外部更新入栈，就保证 Undo 保留 Agent 对其他段落的更新。若采用，须另行证明或实现满足要求的历史方案，不能只换标签。[LKey] [LSelection] [LHistory]

沿用既定前提：Electron＋TS/Node Worker＋SQLite、本地单人；每个知识单元 B 是一个普通正文连续编辑上下文，稳定块 ID，静态阅读、按需编辑；同一会话跨段选区／Undo，公式内部独立上下文。本文不设计编辑到持久化契约，不引入多人协作或云同步。

现场保护是已定产品约束：学生当前段落及实际跨段范围直到离开才解除保护；Agent 可改其他独立段落，保护解除后重核最新输入并自动更新，不设“采纳”。下文只判断底层能力是否足以承接，**三个候选都没有自动实现这套业务保护**。[PState] [PView] [LUpdates]

## 稳定块 ID：持久化字段不等于身份规则

1. **ProseMirror 可把 `blockId` 放进节点 attrs 并经 JSON 往返；schema 不替业务生成唯一 ID。** 原始 split 两侧用 `node.copy()`，未指定 `typesAfter` 时会沿用属性，因此“加一个 ID 属性”不足以避免拆分重复；自定义 split 或后置修复插件都需要明确保留哪侧 ID。[PModel] [PSchema] [PSplit]
2. **Tiptap UniqueID 确有可复用机制。** `attributeName`／`types`／`generateID` 可配置；普通 `appendTransaction` 合并 steps、取 changed ranges，给缺失 ID 补值，并结合逆 mapping 判断新增重复节点；空段拆分还有 ID 转移分支。不是只给 HTML 写一个 data 属性。[TID]
3. **粘贴与移动有区别。** UniqueID 在 paste 标记后递归移除粘贴 slice 的 ID，让追加事务重建；外部／复制拖放走重新生成路径，同编辑器移动有保留身份的分流。不能据此承诺所有平台的剪切、拖放与自定义命令都已通过产品测试。[TID]
4. **UniqueID 不是任意入口的全库唯一索引。** 普通初始化仅找缺失 ID，普通更新主要看变更范围；不能推导它会清洗加载 JSON 中所有已有重复值，或拦截绕过 DOM paste 的程序插入。配置 `filterTransaction` 跳过 Agent 事务也会跳过对应 ID 修复，必须核对；`updateDocument=false` 则禁用这套自动修改。[TID]
5. **Lexical 不得拿 `__key` 当业务 blockId。** NodeKey 不序列化，重载会重建；NodeState 可以另存业务字段，或用自定义节点实现 import／exportJSON。两者是不同身份层。[LKey] [LState] [LParse]
6. **Lexical 有部分 ID 生命周期积木，但不能夸大。** 固定源码 `resetOnCopyNode` 可使 `$copyNode` 重置指定 NodeState；正常状态克隆仍保留其状态。剪贴板 JSON 路径调用 `$parseSerializedNode`／`importJSON`，不是 `$copyNode`，所以仍须覆盖粘贴、拆分、合并、导入的唯一性检查，不能声称该选项单独包办。[LStateSrc] [LCopy] [LClipboard] [LParse]

业务待定项仅列边界：拆分后哪块继承原 ID、合并后哪个 ID 存活、移动与复制如何区分、已有重复 JSON 如何处理。这是三条路径都要明确的身份语义，不在本次替主 agent 设计存储契约。[PSplit] [TID] [LCopy]

## 事务、选区与外部更新的实际限度

- ProseMirror 当前源码的 `Transaction.selection` 随已有 steps 映射；显式 `setSelection` 可以覆盖。history 的普通 `addToHistory=false` 分支仍维护 done／undone 的 maps，故可讨论“Agent 改独立段落且不清空整单元 Undo”；这只证明机制可承接，不能证明所有旧动作的语义无损。[PState] [PHistory]
- Tiptap UndoRedo 本质上返回 `history(this.options)`；不会自动获得额外的 Agent 冲突合并、输入现场锁或最新依据重核。`setContent` 官方定义为替换整篇；`emitUpdate=false` 只是事件控制，不是事务隔离。[TUndo] [TSetContent]
- Lexical 默认 history 的条目为 `{editor, editorState}`；Undo／Redo 调用该条目的 `setEditorState(..., {tag: HISTORIC_TAG})`。`HISTORIC_TAG` 在 history 监听中丢弃本次候选，并未把外部变化重放到旧快照；`HISTORY_MERGE_TAG` 也只改变分组。[LHistory]
- **源码推论、未执行实验：** 学生编辑 A 段后 Agent 改 C 段，即使 Agent 更新跳过入栈，后续 Undo 若恢复一个 Agent 更新前的 EditorState，C 段更新仍可能消失。保存旧栈数组不等于满足本产品要求；解决它需要额外历史机制，而不是清空整个 B 或宣称 tag 已解决。[LHistory]
- Lexical `SKIP_DOM_SELECTION_TAG` 可阻止本次 DOM selection 更新／抢焦点，但不是内容锁、composition 锁或历史重映射。PM 的位置映射同样不是业务冲突整合；两者都不能替代“保护直到离开，再读最新内容自动整合”。[LUpdates] [PState] [PView]

ProseMirror 重叠替换导致旧 step／bookmark 失效、旧基线事务及 IME 的更细边界，沿用既有《编辑事务与并发现场机制核查.md》；本次不重复广扫 history，不把已有证据扩大成新产品验收。

## MathLive 嵌入：有接口，没有免适配保证

- PM NodeView 提供 `dom`、可选 `contentDOM`、`update`、`setSelection`、`stopEvent`、`ignoreMutation`、`destroy`。候选做法是用自管公式节点承载 `<math-field>`，正文看到节点边界，公式内部归 MathLive；并选择性隔离事件／mutation，而非无差别吞掉所有事件。[PView] [MAPI]
- Tiptap `addNodeView` 是开源自定义节点入口，可直接写 JS NodeView；不需要购买厂商 Pro 扩展来承载自定义 DOM。但此入口本身不是经过 MathLive 验收的官方适配器。[TNode] [TLic]
- Lexical DecoratorNode 的 `decorate()` 与 `createDOM()` 宿主可承载 MathLive；框架层负责把装饰内容挂载到宿主。固定源码默认 inline、keyboard-selectable；`isIsolated=true` 会阻断光标遍历／扩选等行为，**不能为了公式内部独立上下文就盲目打开它**，否则可能损害正文跨公式选取。[LDecorator] [LDecorSrc]
- MathLive 提供 `input`／`change`、值读写、selection／undo 状态事件及 `focus`／`blur`；`move-out`／`focus-out` 给出方向并允许自定义退出。其文档明确举出“公式嵌在可编辑段落，方向键退出到正文”的适配场景，说明外层焦点衔接仍要实现。[MDoc] [MAPI]
- 公式内部 Undo 与正文 Undo 的快捷键路由、公式节点被删除／恢复、公式值回写的分组、静态显示切入编辑时的选区恢复都仍未验证。`silenceNotifications` 用来避免输入事件回环，不能据此推导选区、内部历史或 IME 一定不受程序写值影响。[MDoc] [MAPI] [PView] [LDecorSrc]
- **未保证事项：** 中文／拼音组合输入、Shadow DOM 事件重定向、跨段跨公式拖选、虚拟键盘焦点及外部更新时 DOM 复用。本次未安装依赖、运行 Electron 或执行 IME 测试，不能给任何候选“已验收中文输入”的结论。[MDoc] [PView] [LUpdates]

## 下一轮真正需要验证的缺口（本次不执行）

1. **首要淘汰条件：外部更新后的 Undo／Redo。** 单 B、多段、跨段学生操作，Agent 改其他段及其结构后连续撤销／重做；确认 Agent 内容留存、redo 不被无故清除、选区合法。PM／Tiptap 是机制候选；Lexical 默认快照历史先证明能过此关。[PHistory] [TUndo] [LHistory]
2. **ID 生命周期。** Enter 在段首／段中／空段、Backspace 合并、跨段替换、复制／剪切粘贴、内部移动／复制拖放、程序插入及带重复 ID 的初始 JSON；确认身份符合约定且不出现同 ID 两块。[PSplit] [TID] [LCopy] [LClipboard]
3. **实际输入现场。** Electron 的目标 OS＋中文 IME 下，当前段及跨段选区持续受保护；其他独立段落更新不抢焦点，离开后先核对最后输入再更新。公式进出、composition 未提交时切换及 Shadow DOM 事件均包含在内，不能以普通英文输入替代。[PView] [LUpdates] [MDoc]
4. **阅读／编辑切换。** 静态阅读按需挂载 B 编辑器时复用稳定业务 ID；会话内跨段编辑保持同一历史上下文，MathLive 内部上下文与正文快捷键路由正确。无任何实测性能排名，也未声称三条路径在长文或大量公式下的性能结论。[TID] [LKey] [MDoc]

建议进入下一轮讨论的顺序是：先以 ProseMirror 机制为共同底座比较“直接接入”与“Tiptap 开源扩展组合”的维护成本，再用上述缺口决定是否进入原型验证；Lexical 只有历史共存方案明确后再提高优先级。该顺序是基于源码差异的研究建议，尚未选定技术。[TBased] [TID] [LHistory]
