# 数字逻辑复习：扩展开源产品与知识抽取框架调研

核查日期：2026-10-24（北京时间）；GitHub 数据为本次读取快照。范围：Next AI Draw.io、Drawnix、AFFiNE、DeepTutor、LightRAG、cognee 六项，补充此前现成产品与 Agent 工具调研。本报告对这六项仅做官方文档、GitHub API 与源码核查，未安装、部署、运行 demo 或测试本课程 PDF；未查询 X。

**扩展调查改变了推荐顺序。** 如果目标是“快速得到可以手改的复习图”，应把 **Next AI Draw.io** 加入第一梯队；如果目标是“根据材料安排学习、设置前置目标并检查掌握情况”，**DeepTutor 是本组最值得验证的完整学习产品**。cognee 更适合搭建可定制的关系抽取后端，LightRAG 更适合文档检索问答。不能再笼统地说这些工具都只能画导图，但也没有本课程证据支持“上传 PDF 就得到正确的教学依赖图”。[Next AI Draw.io][N1]、[DeepTutor 数据模型][T2]、[建路径工具][T4]、[cognee][C1]、[LightRAG][L1]

## 1. Next AI Draw.io：明显缩短“材料 → 可编辑图”的路径

它不是只给 LLM 增加一个绘图 API，而是包含 Web、桌面和 MCP 入口的成品。AI 生成真实 draw.io XML，用户可双击改字、拖节点、调整样式，也能选择部分图形再让 AI 修改；版本记录、比较、恢复和导出都在产品流程内。对课程依赖图和解题流程，这比“生成一张无法改节点的图片”更匹配。[官方 README][N1]

**PDF 能力必须限定。** 当前 `lib/pdf-utils.ts` 使用 `unpdf.extractText(..., { mergePages: true })` 提取并合并文本。这条路径没有 OCR 或逐页视觉解析，也没有返回逐页引用结构。因此“支持上传 PDF”不代表能读出扫描页、电路连线、卡诺图和图片公式；图像上传重绘是另一条能力，不能混算成 PDF 全页多模态理解。对于已提取的课程文字，仍可先明确概念、方向和关系名称，再让它成图。[PDF 源码][N2]、[输入说明][N1]

**部署与成本：** 有托管入口、桌面包及自托管说明，可配置模型供应商或 Ollama；AI 成本取决于所选模型，Apache-2.0 不代表第三方推理免费。官方提示小模型可能生成损坏的 XML，所以还需核对图形结构与内容。[模型与安装说明][N1]、[许可][N3]

**判断：** 本次可编辑成图的新增优先候选。若内容已审核，仍可保留 Mermaid/CSV 作为内容原件；Next AI Draw.io 提供更方便的图形编辑层，这个搭配尚未在本课程实测。

## 2. Drawnix：适合接住已有的 Markdown 与 Mermaid

官方明确支持思维导图、流程图、自由画笔、Markdown 转导图、Mermaid 转流程图，以及撤销重做、PNG/`.drawnix` 导出。它是建立在 Plait 上的工具产品，不应与底层绘图框架混为一谈。[官方功能与项目定位][D1]

**真正补足的是编辑体验。** 可以把审核过的主题大纲转成导图，或把解题步骤的 Mermaid 转为白板流程图。官方功能表没有证明它会从 PDF 自动抽取概念及关系；Markdown 标题层级仍只是主题层级。JSON 原件支持回到 Drawnix 编辑，PNG 仅用于展示，未验证跨工具转换会完整保留关系与布局。[功能、保存与导出][D1]

**部署与成本：** MIT；提供在线应用、Node 开发启动及 Docker 镜像说明。这条基础工作流不要求配置 LLM。对近期复习，它比完整知识库部署更轻，但若已使用 draw.io，单靠“另一个白板”还不足以要求迁移。[开发与 Docker][D1]、[许可][D2]

## 3. AFFiNE：成品程度高，但不能笼统写成“全栈 MIT”

AFFiNE 将文档和 Edgeless 画布放在同一工作区；官方 AI 导图流程是输入笔记/大纲、生成分支、在白板继续编辑并关联来源笔记。这比孤立导图更适合长期课程笔记，但官方描述仍以主题组织为主，没有证明会验证“必须先学”的关系。[AI Mind Map 官方说明][A2]

导出有明确区分：Markdown/HTML 适合文本，snapshot 用于返回 AFFiNE，图像/PDF 用于展示；不同视图的菜单可能不同。源码也列出这些导出路径。**Markdown 导出不能作为空间画布的完整备份。** 目前所核实的功能不足以证明“课程 PDF → 逐页可追溯概念 → 前置边”的整条自动流水线。[导出指南][A5]、[导出源码][A7]

**许可核查纠正：** 根 LICENSE 将 `packages/backend` 和 `packages/common/native` 指向服务器许可证，其余相关部分为 MIT；服务器 LICENSE 含 EE 商业条款，并明确 CE 分发部分及其列举的客户端内容适用 MPL-2.0。README 中简化的 CE/MIT 说法不足以描述整仓库，应标为 **MIT / MPL-2.0 / EE 按组件与分发范围混合**，不能把整套服务概括为 MIT，也不能反过来说所有自托管使用都必须买 EE。[根 LICENSE][A3]、[服务器 LICENSE][A4]、[README][A1]

**部署与成本：** 本地编辑器、云同步、AI 和自托管是不同选择。服务器文档要求 PostgreSQL 与 Redis，并给出基础 2 GB RAM、较大文档 4 GB 的建议；AI 另涉模型和配置。若只是本机整理期中内容，不必为了“本地”先部署服务器。[官方入门][A5]、[自托管要求][A6]

## 4. DeepTutor：最接近学习目标，且确有前置关系结构

当前版本已包含知识库、辅导、出题、Mastery Path、阅读和可视化。它的学习模型区分 `memory / concept / procedure / design`，辅导流程使用掌握度门槛；可视化生成模型覆盖 SVG、Chart.js、Mermaid、独立 HTML、Manim 动画/故事板。**教学系统状态与生成的解释图是两类产物，不能因为两者在同一产品里，就认为图中的边自动绑定教学前置状态。**[产品与部署][T1]、[路径工具][T4]、[掌握流程][T9]、[可视化模型][T7]

源码提供了比宣传页更强的证据：

- `KnowledgePoint.prerequisite_ids` 明确表示必需学习目标，不是展示顺序；`topic_source_ids` 保存课程来源关联。[数据模型，第 80—94 行][T2]
- 关系校验拒绝未知前置目标、自依赖和环；支持多个前置引用。[校验实现，第 78—125 行][T3]
- `mastery_build` 接受 `prerequisite_refs`，可以引用同次创建目标及已存在目标；`mastery_revise` 支持修订。因而不能将它归入“只会生成目录”的一类。[工具 schema][T4]

**同时存在一条重要限制：** 默认课程生成 prompt 的返回结构只要求目标名称和类型；对应 `topic_generation.py` 构造 `KnowledgePoint` 时没有填充 `prerequisite_ids`。Agent 建路径工具虽然能写前置字段，但“模型可调用”不等于每次都会自动生成正确依赖。无环校验只证明结构合法，不证明“A 是 B 的必要前置”在学科上成立；`topic_source_ids` 本身也是目标级来源，不是每条边的 PDF 页码与原文证据。[生成 prompt][T5]、[生成实现，第 432—438 行][T6]、[模型注释][T2]

**编辑、展示与迁移：** 当前所读学习界面是模块/目标大纲，可经对话工具设计与修订；未确认自由拖拽的前置关系编辑器，也未确认学习前置图一键导出 GraphML/JSON Canvas。生成 SVG/Mermaid/HTML 可以形成可保存的解释素材，但不能据此声称学习状态图已经支持同样的通用导出。[大纲组件][T8]、[路径工具][T4]、[可视化输出类型][T7]

**部署与判断：** 有完整应用的 Docker 路径及本地安装方式，仍要配置模型，知识库所选 RAG/解析方案也影响成本。当前根许可证是 Apache-2.0。它应进入“完整学习产品”的首轮验证名单，而不是等到所有白板工具都失败后再考虑；但若当下只要三张可手改的图，Next AI Draw.io 路径更短。[README][T1]、[LICENSE][T10]

## 5. LightRAG：抽取与检索有用，默认图不能当教学 DAG

LightRAG 能从文档构建实体—关系索引，用于多种检索问答模式；管理 WebUI 有文档与知识图谱入口。新 `/workspace` 是只提供聊天的终端用户入口，不能把该页面当作图谱编辑器。[产品说明][L1]、[v1.5.7 发布说明](https://github.com/HKUDS/LightRAG/releases/tag/v1.5.7)

关键是**图的语义与方向**：默认抽取 prompt 将关系作为无向关系处理，除非明确另有说明；默认 NetworkX 存储实际初始化为 `nx.Graph()`。所以即使边上有描述、对象名称叫 source/target，也不能保证“先修 A → 后学 B”的方向被当作教学约束保留。它默认在做相关实体和关系的检索组织，并没有自动解决教学顺序。[抽取 prompt][L2]、[NetworkX 实现][L3]

可维护性比纯图片好：API 有实体/关系创建、修改和实体合并；关系带 `source_id` 与 `file_path` 等来源字段。SDK 导出 CSV、Excel、Markdown、TXT，默认 NetworkX 存 GraphML。**chunk ID 或文件路径不等于 PDF 页码引用，也不等于关系事实已审核。** 若想借它做前置图，建议导出候选，再在独立的有向关系表中分类审核；只改 prompt、保留默认无向存储不足以保证目标。[图 API][L4]、[导出实现][L5]、[图存储][L3]

**部署与判断：** 有 pip/服务/WebUI/Docker，通常要配置抽取模型与 embedding，复杂 PDF 还涉及解析路径。默认文件持久化存储适合小规模测试，不必为了六份课件先加独立图数据库；不过搭整套检索系统仍比直接绘图更重。MIT，适合后续资料库扩展，不是本次知识前置图的首选成品。[安装与存储说明][L1]、[许可][L6]

## 6. cognee：关系语义更可定制，适合后端试验

cognee 当前定位是 AI 记忆平台，文本变成实体、关系和可搜索片段；其关系模型有 `source_node_id`、`target_node_id`、`relationship_name`。这让自定义“前置”“等价”“实现”“解题步骤”等关系有承载位置，但默认生成的是通用知识/记忆网络，**程序代码的 dependency 边也不能迁移解释为课程 prerequisite 边**。[README][C1]、[关系 schema][C2]

OWL 支持可对齐实体与类型、补入类层级和对象关系；默认 `annotate` 保留未匹配实体，`strict` 才过滤。官方只支持特定 OWL 构件，不能把“支持本体”理解成任意教学规则推理器。自定义关系 schema/ontology 是迁移到数字逻辑的起点，关系方向、必要性和证据仍须审核。[官方 Ontology Quickstart][C3]

**产物与导出：** `visualize_graph()` 输出可拖动、缩放、查看边属性的独立 HTML；默认展示有界子图，未必显示全部知识。SDK 的 `export` 提供 Pydantic 快照、JSON、GraphML、Cypher、COGX。COGX 是恢复数据集的迁移路径；HTML 中拖动节点只是浏览操作，本次未确认它是可持久编辑语义的白板。结构化导出对未来接入 Cytoscape.js 等前端有利，但需要写转换逻辑。[可视化文档][C4]、[导出 SDK][C5]

**部署与成本：** 当前 README 的 `cognee[gliner]` 路径可用本地 GLiNER 与 embedding 构图，无需 API key，但首次会下载模型；README 明确该内置 extractor 是小模型管线 demo，不能据此保证中文专业课准确率。生成式回答、其他提取路径仍取决于 LLM。UI 启动需 Node/npm，其 MCP 服务需 Docker；官方最小 Docker 方案用本地数据库并默认要求 OpenAI key，不能把 Python 免 key 路径的条件直接套给该 Compose 示例。[本地 quickstart 与 UI][C1]、[Docker 示例][C6]

**判断：** 在“未来要自建可验证的跨课程关系系统”这一目标下，值得排在通用 RAG 方案前面做后端验证；在“这周完成期中复习图”的目标下，工程投入很可能超过收益。这是任务匹配判断，不是性能测评。

- Drawnix 最新 release 相对较早，但默认分支仍有 2026-09 提交；“发布少一些”不等于项目已停止维护。其余项目近期提交/发布频繁，也不能据此推断已通过本课程适配测试。

## 为什么选 cognee，而没有把 Graphiti 列为第七项

Graphiti 确实相关：官方定义是带时间有效性和来源 episode 的实体/事实网络，也支持自定义类型。它强调“事实如何随时间变化”，并要求使用者提供图数据库、LLM 和 embedding、搭建周边服务。对固定的 01—06 课程资料，这种时间语义不是主要需求。cognee 此轮更值得展开，是因为已有文档输入、可视化、结构化导出与本体对齐的完整官方证据；这不构成 Graphiti 抽取质量较差的结论。[Graphiti 官方 README][G1]、[cognee 导出][C5]

## 对原推荐的具体修订与三条实用路线

1. **近期交付几张复习图：已核对的课程文字/关系表 → Next AI Draw.io → 人工改边并保留 `.drawio`。** 把它加到原来 draw.io / Mermaid 方案前面承担初稿生成；Drawnix 可作为 Markdown/Mermaid 后续图形编辑器。尚未验证的关系不能因为排版漂亮就升格为前置知识。[N1][N1]、[D1][D1]
2. **希望材料、辅导、练习和学习顺序在一个产品里：优先验证 DeepTutor。** 重点观察 Agent 是否实际填入 `prerequisite_ids`、跨模块多前置是否正确，以及哪些依据只关联到目标、哪些能回到原页。它已具备真正前置关系结构，值得改变“只比较笔记白板”的原候选集；默认生成缺口和本课程效果尚待验证。[T2][T2]、[T3][T3]、[T4][T4]、[T6][T6]
3. **未来跨课程长期建设：cognee 抽取候选 → 明确定义关系类型与来源 → 人工审核 → 自定义有向图前端。** 如果主要诉求只是从大量资料问答，LightRAG 更直接；若近期只有六份课件，继续用可审查的 Markdown/CSV 关系表即可，不必先搭后端。[C2][C2]、[C3][C3]、[C5][C5]、[L1][L1]

因此，原先 markmap / Mermaid / Cytoscape.js 的价值仍在可控表达和定制交互，但它们不再是唯一应优先尝试的路线：**Next AI Draw.io 补齐 AI 初稿与原生编辑，DeepTutor 补齐真正的学习目标及前置关系模型。** 本轮最值得后续实测的就是这两项。原“没有可靠的一键自动教学依赖图证据”的结论保留，含义应精确为“没有本课程端到端正确性证据”，不能再解释成“所有候选都没有前置关系能力”。
