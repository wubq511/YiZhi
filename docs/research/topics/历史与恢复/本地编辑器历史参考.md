# 本地编辑器历史参考：Obsidian 与 VS Code

核查日期：**2026-10-27（Asia/Shanghai）**。范围：官方帮助与官方工程资料的只读检索；没有登录账户、读取私有笔记、安装同步服务或运行产品恢复操作。本文只新增这一份研究文档，未修改存储实验。

本报告是参考证据；哪些能力值得用于首期，统一按[历史管理与恢复设计](../../../architecture/历史管理与恢复设计.md)中的真实场景、性能、存储和复杂度取舍，不将下表全部变成实施清单。

后续范围修订：[ADR-0008](../../../adr/0008-product-development-boundary.md) 已取消当前产品内容交换；下文关于交换的设想保留为研究背景，课程复制、完整备份和历史保护仍按现役合同执行。

## 结论及证据边界

**值得借鉴的是“自动保存与历史列表解耦、先查看/比较再恢复、草稿恢复另有保障”；不能直接照搬的是整文件覆盖、设备外置历史和固定的时间/条数默认值。** 用户已接受“正式修改历史＋可恢复草稿”，所有内容仍自动保存；历史分组、保留和清理策略不应变成手动保存门槛。我们的正式正文和个人笔记都须有恢复前保护，不能因为产品提供 Restore 按钮，就假定它已经保护了当前版本和活动输入。

本文采用三类证据：

- **帮助明确的产品行为**：下面对照表中的记录时机、保留设置、可见操作和已说明的存储位置。
- **版本限定的公开代码行为**：VS Code `1.105.1` 标签的恢复与历史服务代码，用来补充帮助没有写清的行为；这不是对所有版本的承诺。本次也只读查看了 `main` 的恢复路径，但引用以固定标签为准。[恢复命令代码][V3]
- **我们的设计判断/未证实事项**：分别标明。没有从 UI 的“全文”“差异”“历史”推断 Obsidian 内部数据库、增量链、去重、压缩、写盘原子性或快照算法；也不从 VS Code 调用文件接口推断底层文件系统的物理复制方式。

## 机制对照

Obsidian 的 **Sync history** 侧栏用于浏览最近已同步的变更，不等于可恢复的 **Version history**；设置与已删除项目不显示在该侧栏，另有版本入口。[O2] 因此，不能由“活动列表没显示”推断“版本已丢失”。

### 自动记录、粒度和清理

| 维度 | Obsidian File Recovery | Obsidian Sync version history | VS Code Local History |
| --- | --- | --- | --- |
| 自动记录时机 | 对变化文件按间隔记录；默认相邻快照**至少相隔 5 分钟**。不是逐键历史，也不是自动保存的承诺间隔。[O1] | 检查已选择同步文件的更新并形成历史条目；本次官方帮助**未给出固定采样/合并秒数**，不能写成“每次按键/每次本地保存均有远端版本”。[O2] | 依设置随编辑器保存生成历史条目；默认有 10 秒 `mergeWindow`，不等于每次保存永久新增一条。[V1] |
| 历史对象 | 帮助称保存完整文件内容；支持 `.md`、`.canvas`。[O1] | 以文件为可选版本对象，笔记、附件及设置有相应恢复入口。[O2] | 条目代表文件当时全文，可附保存来源等语义信息。[V1] |
| 保留基线 | 默认 7 天，可配置快照间隔及保留期。[O1] | 笔记 Standard 1 个月、Plus 12 个月；附件旧版 2 周，不能把笔记期限套给附件。[O2] | 默认每文件 50 条；文件大小默认上限 256 KB，还可禁用或配置排除规则；当前帮助没有宣称固定保留天数。[V1] |
| 自动清理/合并 | 超保留期移除；只有变化文件才占新增快照空间，不等于仅存文本差分。[O1] | 超期删旧版，历史计入账户配额；换新 remote vault 会重置历史。[O2][O3] | 固定标签代码：同保存来源且落在配置窗口内，允许替换最近条目；保留数裁剪优先移除较旧条目。不是“每隔 10 秒精确保留一版”。[V4] |
| 手动清理 | Clear history 需要确认，官方说明全部快照删除不可逆。[O1] | 配额文档给出删除大文件后 prune、新建远端库等路径；没有据此推定存在任意单版本删除功能。[O3] | 支持删除单条；官方发布说明还列出全局 `Delete All` 和手工命名条目命令。手工命名不是使用历史的前提。[V1][V2] |

这里的“完整内容”描述可取回的逻辑版本。它不能证明每条历史都在物理磁盘保存了一份未经压缩的全量副本，也不能反向证明内部使用差分。Obsidian 帮助同时说“完整内容”和“只记录变化文件”，二者并不矛盾。[O1]

### 预览、比较、恢复与当前保护

| 维度 | File Recovery | Sync version history | VS Code Local History |
| --- | --- | --- | --- |
| 查看/比较 | 按文件找快照，支持 `Show changes`。[O1] | 选左侧版本、右侧查看内容；官方 Sync 产品页说明可查看修订差异。不能由此推定所有附件/设置都支持相同文本 diff。[O2][O8] | Timeline 内可比较当前文件、前一条历史。[V1] |
| 取回方式 | `Copy` 可供另建笔记，或 `Restore` 恢复整个文件。[O1] | Restore 替换笔记当前内容；删除文件恢复到原路径；另有批量恢复，但该批量入口不能逐项审阅。[O2] | 恢复条目内容；删除文件可经 `Find Entry to Restore` 找回。[V1] |
| 恢复前一定留当前版吗 | **帮助未明确保证。** 不能把此前周期快照当成“点击恢复前一定留档”。[O1] | **帮助未明确保证。** “替换为选中版本”不证明此前最新本地内容必已进入远端历史。[O2] | 固定标签的恢复函数先确认，明确提示丢弃未保存修改；随后撤掉 dirty 状态、替换文件、重载，再追加标记为 `File Restored` 的历史。[V3] |
| 恢复操作可否撤回 | 所读帮助未承诺专用 Undo restore；另取已存在的快照只能恢复那些确已记录的内容。[O1] | 所读帮助未承诺专用 Undo restore；再次选历史恢复与可靠保存恢复前状态不是同一合同。[O2] | 该恢复代码没有在覆盖前单独追加当前状态，也未建立“一个可撤回编辑操作”的保证；恢复后追加的是**恢复后的内容**。不能承诺 Ctrl/Cmd+Z 找回被覆盖的未保存输入。[V3] |

**判断**：从这些资料能确认“有版本可选”“可替换当前文件”，但不能统一写成“恢复永远可撤回且不会丢当前”。没有明文保证的部分记为未知，不用社区经验填补。VS Code 的具体放弃输入行为来自公开源码，不是假设已在本机 UI 验收。

## 本地离线、迁移与备份

| 问题 | 官方证据及对可迁移性的含义 |
| --- | --- |
| File Recovery 存在哪里 | 存在 vault 外的全局设置位置，关联笔记绝对路径；快照只在当前设备，不随 Sync 同步。帮助提示不通过 vault switcher 移动库后，旧快照可能不可访问。因此不能承诺“复制 vault 文件夹就带走本地恢复历史”。[O1] |
| Obsidian 的正文能否离线读写 | 正文是本地 vault 中的 Markdown 文件；配置在 `.obsidian`，全局数据另处保存。普通笔记文件可搬运，与历史迁移是两件事。[O4] |
| Sync 断网后如何工作 | 本地 vault 仍可用，离线修改排队，联网且 Obsidian 打开后同步。[O5] **帮助未承诺断网时可浏览/恢复全部远端历史，未说明所有离线中间态都会补传为独立历史条目。** |
| Sync 历史能否随目录搬走 | 远端 vault 与本地目录是不同对象。[O5] 配额文档明确新建远端库会重置历史；本次资料没有提供“所有 Sync 旧版本一并导入新库”的开放迁移合同。[O3] 复制当前文件不能被描述成完整版本历史导出。 |
| 服务到期影响什么 | 官方 FAQ 说明到期后远端数据含历史保留 1 个月，本地 vault 不受影响；退款时远端立即删除。[O6] 本地当前内容可读不等于远端历史仍可用。 |
| VS Code Local History 是否位于项目内 | 官方 1.66 发布说明区分本地/远端用户数据位置；固定标签源码也按远端环境优先、否则本地环境选择历史根目录。[V2][V4] 本地桌面使用不要求同步服务；远端开发的“Local History”不一定在本机。复制工作目录不能被当成历史备份。 |
| 版本历史是否就是备份 | Obsidian 官方明确区分：Sync 传播设备间变化；备份是在另一位置保留可恢复副本，并建议单向备份。File Recovery 有限，Sync 带版本历史也不等于备份。[O7] 本文没有把本地历史称为可抗磁盘损坏的独立备份。 |

### VS Code 补充：Local History 与 Hot Exit 是两条保障

官方 Basic editing 将保存与未保存输入恢复分开：默认显式保存，可启用按延时/焦点变化自动保存；未保存输入另有 Hot Exit/备份机制，在退出及适用窗口关闭条件下可恢复。[V5] Local History 的“编辑器保存后条目”不能替代未保存输入保护。

这是“正式修改历史＋可恢复草稿”的有用参照，但我们不沿用 VS Code 默认手动保存，也不把其窗口触发条件照搬为任务生命周期。我们的所有输入继续自动保存；关闭学习界面任务继续，退出程序停止，是独立桌面执行合同。

## 对本项目的借鉴与不适用点

以下是基于用户已确认边界的**设计建议，尚未实现或验收**，不作为 Obsidian/VS Code 内部机制的描述。

### 1．自动保存持续进行，历史可以按语义组织

正文通过校验并正式修改时，记录可定位的语义变更组及其来源；个人笔记也有自己的正式修改历史。草稿自动保存会话、基线、序号与实际输入，包括尚未完成的公式。UI 分清“输入已保留”“正式内容已更新”，不要求按保存按钮，也不引入逐组预览采纳。

借鉴的是“保存动作”和“历史展示条目”不必一一对应。可以把一次学生编辑或 Agent 小组提交组织成可读历史；对草稿中间态是否合并、多久保留另订策略。**合并展示不应抹掉正式提交回执、恢复关联或尚未替代的可恢复输入。** 不能直接采用 5 分钟作为草稿允许丢失窗口，也不能直接把 7 天、50 条或 256 KB 当成我们的产品上限。

### 2．默认局部恢复，恢复本身也形成新修改

建议恢复入口先显示对象、时间、修改来源及与当前版本的差异，允许只复制旧内容作为新对象。真正恢复时生成新修订，保留被替代的当前修订及恢复来源；不要删除后续历史、把整个数据库物理倒回旧时点。这样“恢复到旧内容”与“抹掉后来发生的一切”可以分开。

恢复命令通过正常提交门禁核对当前版本；比较界面打开后又有新编辑，不能仍按旧预览无条件覆盖。恢复与其保护记录在共同提交边界成立，成功回执应指向新修订。撤回恢复也生成受当前版本约束的逆变更，保留恢复后的后续编辑；实质冲突明确保留双方，不声称任何时候都能无冲突一键反悔。

### 3．正文恢复和个人笔记恢复分别保护

| 场景 | 建议行为 |
| --- | --- |
| 恢复某块正文，学生后来加过笔记 | 只恢复选定正文变更；保留后来笔记、原引用与原语境，布局也不顺带回退 |
| 笔记指向的内容被改写/删除 | 只有可证明的对应才更新定位，否则保留原版本并标待重新关联；不把笔记移动到另一段同名文字 |
| 恢复个人笔记旧版 | 先保留当前笔记版本和正在编辑的草稿，再形成笔记新修订；不覆盖无关正文或其他笔记 |
| 恢复时有有效学生输入 | 输入先持久保留为独立草稿；核对其基线后重新整合，不借恢复丢弃或静默提交草稿 |
| 需要整课恢复 | 与局部历史入口分开，明确正文/个人内容/草稿/任务的范围；使旧执行资格失效，保留必要执行事实，不顺带恢复旧 attempt 的提交权 |

File Recovery 的 Copy 思路适合“取回一段旧内容”。整文件 Restore 以及 VS Code 源码中放弃 dirty 输入的路径，**不适合作为我们保护正式正文和个人笔记的默认合同**。确认弹窗也不能替代保留当前数据。

### 4．历史属于课程可移植数据，备份另外定义

课程复制或开放交换应显式包含约定保留的修订、个人笔记/原锚点、可恢复草稿、恢复关联与所依赖的不可变资源，使用稳定对象身份和相对资源引用。外置全局缓存可以服务性能，但不能成为课程搬家后唯一找得回历史的地方。Mac/Windows 路径变化不应改变历史对象身份。

版本历史解决“恢复某对象旧内容”；独立一致备份解决“当前课程库丢失/损坏后恢复整课”；同步解决设备传播。三者可组合，不能用相同的“已保存”状态替代。这里不新增安装同步服务或接入真实账户的需求。

### 5．保留和清理先说明语义，不仓促给数字

可借鉴按时间、条数、大小控制增长，但正式历史、恢复前保护版、可恢复草稿和派生缓存应分别表达。清理至少不能留下“回执仍宣称可恢复、历史正文或笔记原语境/资源已经被删”的状态；被个人引用或恢复链依赖的版本需要相应保留/归档规则。

本次不决定永久逐键留存，也不承诺无限历史。具体期限、容量、归档和清理提示应由真实增长与恢复目标决定；“清空历史”与“清缓存”不能混为一项。未作决定前，不因借鉴某个编辑器而自动删掉现有历史。

## 尚不能从官方资料确认的事项

| 未确认事项 | 本文处理 |
| --- | --- |
| Obsidian 两套历史的物理存储/增量/压缩/去重算法 | 不从帮助中的 snapshot、全文或 diff 猜测；未以第三方插件或论坛补齐 |
| Sync 的准确历史采样频率、离线中间版是否逐条保留、全部历史是否可离线恢复 | 所读官方资料没有明确合同，记为未确认 |
| Obsidian 恢复前一定保留当前版、专用 Undo restore 的持久保证 | 帮助未说明，不宣称有或没有，只说明本次无法确认 |
| 三种历史的跨对象事务、断电持久化、个人锚点语义恢复 | 未做实验，产品帮助不足以证明；不能替代我们自己的合同验证 |
| VS Code 所有现行版本的恢复实现、历史迁移完整性 | 当前帮助与固定标签工程证据分别注明；没有安装/操作版本验收，也不推广固定标签代码到所有版本 |
