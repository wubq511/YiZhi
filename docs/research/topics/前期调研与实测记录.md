## 结论与推荐

**适合这个目标的是“带类型关系的概念图 + 前置依赖视图 + 解题流程”，章节目录树作为导航。** 概念图回答“有什么联系”，依赖图回答“先会什么”，流程图回答“题目怎么做”。关系类型必须明确：前置、等价表示、可选解法、实现关系和资料引用不能混为一类。[概念图方法来源：IHMC / Novak 与 Cañas](https://cmap.ihmc.us/docs/theory-of-concept-maps)

**前期演示阶段采用 Agent + Archify 做可探索的局部知识图，Diagram Design 做静态对照。** Archify 已经实际生成 MUX 样例，并验证其原生上游追溯。其工程术语和通用边模型仍需课程化；这些实测结果现在用于自有复习系统的设计比较。

按问题选择下一步，而不是安装全部候选：

| 想解决的问题 | 优先候选 | 为什么 | 本轮验证程度 |

## 已做出的实际样例

所有样例内容来自本轮选取并核对的课程知识，**不是每个工具独立自动从 PDF 抽取的评测**。相同内容便于比较表达方式；仅展示 01—06 中的局部内容。

### Archify：真实交互产物

[打开 MUX 交互知识图](../../../experiments/archify/archify-mux.html) · [可修改 JSON](../../../experiments/archify/archify-mux.json) · [实际界面截图](../../../experiments/archify/archify-mux-preview.png)

点击“用 MUX 实现函数”，再点“上游”，可看到 **3 个上游节点、3 条连接、最深 2 跳**。这是 Archify 原生能力，本次没有另写一个仿制界面。图中只放前置边，因而该查询可解释成前置追溯；把等价、相关或可选解法混入后，就不能继续这样解释。

实测也发现了适配成本：虽然图例已写成“前置知识 / 学习目标”，节点详情仍保留“前端 / 架构组件”等原生工程术语。其 source 模型偏向源码路径与行号；本样例把课件名、PDF 页序放在节点和说明中，没有冒充一键 PDF 引用跳转。

使用官方 `v3.2.0` 包内代码，提交 [`25cf370`](https://github.com/tt-a1i/archify/commit/25cf37080fc8b1dbe758a4efc3935b55f3327083)。`deliver` 与严格来源检查通过，9/9 图形检查、0 错误、0 警告，凭证在 [delivery.json](../../../experiments/archify/archify-mux.delivery.json)。浏览器通过当前环境的 CUA 实际检查并点选上游；**未运行 Archify 自带的 `browser-check/finalize` 浏览器流程**，因此不宣称其整套 finalize 门禁通过。

### Diagram Design：真实 Skill 产物

[打开静态 MUX 知识图](../../../experiments/diagram-design/diagram-design-mux.html) · [实际界面截图](../../../experiments/diagram-design/diagram-design-mux-preview.png)

按官方 Skill 的 architecture 布局规则、默认配色和模板制作，同样保留四个概念及三条关系。其 dependency 模板偏软件包依赖与环分析；这里选用 architecture 的带标签连线语法表达概念依赖，没有照搬无教学意义的包依赖徽标。中文字体采用系统回退，拉丁字使用 Web 字体。

### 新增同题对比：visual-explainer / fireworks / Excalidraw

[打开三种效果的统一对比页](../../../experiments/mux-skill-comparison/index.html) · [版本、产物与验证记录](../../../experiments/mux-skill-comparison/README.md)

三份样例已使用同一份 MUX 输入实际生成。visual-explainer 可切换 x/y/z，实时联动选中端、通路和输出，浏览器 8/8 核对通过；fireworks 提供静态 SVG/PNG 与原生缩放查看器，官方五项检查通过；Excalidraw 提供真实可编辑场景，已实际拖动节点、确认连线跟随、保存 JSON 并撤销。

## 从其他领域迁移什么

1. **软件架构与构建系统：**明确关系方向和类型，支持上游/下游与局部图；但软件实现依赖不等于学习前置。
2. **个人知识管理与论文阅读：**稳定概念 ID、来源原文和 PDF 页序，定义、例题、错因围绕同一卡片维护。
3. **网络分析：**借用邻域、路径和子图查询；不要把中心性当作考试重点。
4. **交互教程：**将抽象关系与具体输入输出、步骤和练习绑定；只有用户实际作答或标注后才记录掌握度。

最小底稿为：概念 `id / label / chapter / source_refs`；关系 `source / target / type / reason / source_refs / review_status`。只让已审核的 `requires` 边进入前置查询；可替代路线应表达条件，不能把所有入边自动看作同时必需。

**适合当前期中任务的推进方式：**先用这些同题样例选择最有帮助的表达，再将 01—06 按主题生成图并用真实题目检验。需要进一步自动化时，再专项试 Graphify 的关系抽取或 DeepTutor 的学习路径；暂不需要为六份课件搭完整图数据库。
