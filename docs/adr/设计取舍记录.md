## 1. 为什么先确定知识层级，再讨论卡片和显隐

最初容易把“概念、方法、例题、验证”等学习用途直接当成视图分层，或先问应准备多少正文。Robert 两次纠正了这个出发点：先沿用课程已经审核的 A 主题／B 单元粒度；正常完整复习所需内容应先备齐，再讨论此刻显示多少。由此放弃了“只有摘要，遇到不会再问 Agent 补齐”的路线，也没有把六类学习用途变成每单元必须凑齐的六张卡片。

六类用途——概念与结论、结构与关系、方法与步骤、例题与练习、验证与探索、对比与易错——仍可用于检查材料是否充分。它们不是新的知识层级，也不要求每类成为独立节点。必要示意可以是图、例子或推导，不能因为表达形式就一律折叠。单元内部的归属也不自动推出第三类知识实体或固定第三档缩放；后来接受的三级显示深度是阅读组织，不是重拆知识。

当时通过统一查询接口核对的三个样本，说明了不能只套统一摘要模板的原因：

| 真实单元 | 当时已有信息 | 必须解决的阅读问题 |
| --- | --- | --- |
| `KU-055` MUX 功能与 2:1／4:1 表达式 | 摘要、选择公式、条件与来源 | 选择示意、公式和条件须共同支持理解，不能只列公式 |
| `KU-035` 2–4 变量卡诺图化简 | 圈组摘要、规则、条件、例题定位 | 可执行步骤与必要圈组示意须支持学生独立操作 |
| `KU-063` 74LS138 端口、有效电平与使能 | 使能条件、有效电平、易错提醒、来源；74HC138 为别名 | 端口、控制条件和功能规则不能收起到只剩器件名称 |

这些是当时对需求差异的核对，不是当场已经补齐图示和题解的证明。后来的真实内容原型与旧版整课验收分别记录在[阅读原型](../../experiments/content-depth-prototype/README.md)和[旧版运行基线与验收](../development/旧版运行基线与验收.md)。

每课一张长期画板、单份知识主位置和引用返回，共同服务空间记忆与连续阅读；因此放弃分区卡片首页、逐层进入的页面、期中／期末各一张视图和到处复制完整正文的方向。2026-10-25 原型试用中，Robert 特别要求：从正文缩远后，必须先有足够宽的区间看清主题内全部 B 和关系，再退到 A；不能刚离开正文就把所有单元替换为主题。图、条件、解释和结果要邻近，目录与画板阅读顺序一致，并列关系不能被排版成前置链。后来“差不多可以”的反馈是对原型方向的基本认可，不是所有设备、完整产品或学习效果的验收。

## 2. 为什么手绘、端正和有色必须同时成立

Robert 先要求看实际效果，再从 A／B／C 中选择 A 的字体、符号与视觉，而非仅凭风格名称决定。随后两次纠偏值得长期保留：端正排版不等于将笔触改成机械直线；系统默认浅色也不等于把学习内容全部去色。

接受的样例中，文字、公式、标签和整体框体端正、不作装饰旋转；框线、电路、箭头和标记保留自然起伏与复描。白色无装饰点阵画布、白／浅灰控件、淡紫交互态只约束系统底色。MUX 样例用蓝色关联输入条件、青绿色贯穿选中信号／输出／验证、暖黄色表示个人笔记；颜色服务信息连续性，不冒充掌握状态或重要性，也不能只靠颜色传意。直线整体方向仍稳定，波浪线需可辨，高亮不能遮挡正文和数学符号。

正式基准与操作边界见[样式与公式原型](../../experiments/style-math-prototype/README.md)、[接受的画板](../../experiments/style-math-prototype/preview-current.png)和[公式编辑状态](../../experiments/style-math-prototype/preview-editor.png)。该样例的公式修改只在页面内，不自动重算电路或真值表，不是课程持久化或共享计算定义已经成立。更早的 Excalidraw 原生 MUX 示例有 **35 个元素 `roughness=0`、22 个文本 `fontFamily=3`**，只证明原生编辑与导出，不能当作后来接受的手绘样式。

可视化公式编辑的出发点是降低学生的语法学习门槛；LaTeX 可作为内部表示，不能成为操作前提。Archify 的阅读结构、Excalidraw 的画板体验和视觉、Heptabase／NodeGraph 的来源追溯、visual-explainer 的局部交互，是不同维度的参照；偏好体验不自动授权采用某套引擎或原生数据格式。后续不再要求用户重复选择 A／B／C。

## 3. 为什么直接修改仍要区分意图、来源更新和个人主动权

早期草图曾有预览、采纳和分区总览。用户反馈后，这些退出正常修改路径：明确要求修改就原位生效并可撤回，保存由系统负责。这里减少的是操作门槛，不是允许 Agent 把任意疑问解释为改写授权。“我没听懂”先进入问答；明确要求“把另一种解释记下来”才保存补充；纠错则必须修正错误主内容，不能只在旁边写一条正确说明而留下错误正文。一次自然语言请求可以包含多种意图，分类服务系统判断，不要求学生逐项选择内部操作。

自动根据新资料改写画板的建议被 Robert 明确否决。先询问是否根据新版发起任务，是对更新意图的确认；已授权任务的有效修改仍直接保存，不恢复为逐块采纳。暂不更新时允许 Agent 查新版，但旧画板、旧引用与旧依据保留，新旧差异说明清楚。其目的在于让学生决定何时改变学习基线，而非让资料库永远停在旧版。现役合同见[PRODUCT 的资料与变更规则](../../PRODUCT.md#agent-与变更)及[总稿第 7 节](../architecture/系统设计定稿.md#7-来源内容生产与搜索)。

个人内容保护也有明确动机：学生的思考不能因 Agent 改写、撤回或知识拆合一起消失。笔记即使由 Agent 协助编辑，仍是个人记录；无法证明新位置时保留原引用和语境，不能复制到所有新单元假装完成迁移。手画箭头可能只是记忆联想，不能自动升格成知识事实；早期“等价”等关系举例也不是新增关系类型许可，公式内部已充分表达的内容无需凑边。正式关系仍需具体价值、方向与来源。

“已掌握”是学生判断，不是看过答案、Agent 完成任务或星级高的推论。Robert 特别要求实质纠错后由 Agent **主动询问是否、以及改成哪个状态**；仅提示内容变了不够，未确认继续保留原状态。这里的确认只针对个人掌握状态，不能阻塞已经授权的正文修改。

同时修改即使顺利整合，也须在结果中说明位置和处理，如保留了学生刚改的选择端说明，再据此补充推导。不能用“无冲突所以无需告知”省略这条要求。任务目标绑定提交时选择，后续浏览不偷偷换目标；停止保留已提交内容，撤回另行执行。这些规则解释了为什么任务、内容、个人记录和视口不能绑成一个可整体替换的快照。

## 4. 为什么手势采用固定语义，而不猜设备

鼠标与触控板都是高频输入，用户希望随时混用，不能要求手动选设备模式。讨论核查发现：`pointerType` 通常不能区分共享鼠标指针的触控板与鼠标；`deltaMode` 只说明像素／行／页单位；捏合也可能发出带 `ctrlKey` 的 wheel。增量精度和频率至多是线索，不能成为可靠设备识别。

2026-10-27 的成熟产品规则对照提供了选择理由，不是硬件实测：

| 参照 | 当时核查的行为 | 本产品取舍 |
| --- | --- | --- |
| FigJam | 滚轮平移，Shift 横移，macOS ⌘／Windows Ctrl 加滚轮缩放；双指平移、捏合缩放；Space 临时手形 | 阅读多于排版，平移优先可统一混用语义，代价是鼠标缩放需要修饰键或控件 |
| Miro | 自动设备模式；鼠标滚轮缩放、右键拖动平移；混用时官方建议 Trackpad 模式 | 自动切换不是唯一答案；桌面按住拖动也不能与触摸屏计时长按混为一谈 |
| tldraw | 可配置滚轮语义；移动阈值与长按计时分别管理，当时默认 4px 与 500ms | 按距离识别拖动、按时间识别长按；这些数值未被采纳为本产品参数 |

统一后的动作以[总稿手势表](../architecture/系统设计定稿.md#2-工作区阅读与空间交互)为准。默认空白拖动无需等 500ms，触控板点按拖移／三指拖移沿用操作系统事件；正文拖动选文，实验控件保有整次拖动，对象通过明确移动区域操作。输入框空格仍输入，右键单击仍保留上下文菜单；没有因此新增桌面计时长按或触摸屏承诺。具体惯性、平台快捷键和事件适配属于实机验证，不是再次选择产品语义。

跟随控制的推理类似：学生操作不只是暂停发送下一次定位，还要取消在途动画、清掉排队定位、让旧回调失效。同次任务的后续输出、切对象、松手或短暂无操作都不是恢复许可；移动鼠标指针本身也不是接管。操作文字、公式和实验时应保护现场，但不能把它们都误当成持续的手动导航。返回按钮找的是 **Agent 当前**工作对象，而非学生离开时的旧对象。局部布局的锚点补偿只是保持阅读位置，不意味着重新获得跟随控制权。

## 5. 体验问题实际查到了什么，为什么不能简单归因于框架

Robert 报告过频繁的平移／缩放卡顿，以及间歇性抽动、闪烁。2026-10-27 在旧版 `http://127.0.0.1:8769/` 的 `KU-027` 阅读状态，记录 **26,988 个 DOM 元素、1,070 个段落、250 个 SVG**，页面显示 **20 主题、84 单元**。这是挂载规模快照，不是 FPS 测试。

同一窗口点击“主题总览”显示 **3%**，再点一次“放大”显示 **86%**，直接进入单元阅读。对应[旧版 app.js](../../legacy/review-board/web/app.js) 的 `zoom()` 越阈值调用 `focusUnit()`，证明了一类缩放跳变；未证明它解释全部卡顿和闪烁。[当日审计记录](../../legacy/review-board/验收/audit-2026-10-27/results.json)明确没有真实硬件 FPS、启动时间或负载基准。本次整理没有重现页面或重新测量这些历史数值。

当时源码核查还发现以下放大工作量或耦合边界，均不能直接当作耗时占比结论：

| 历史实现事实 | 推导出的必要分工 |
| --- | --- |
| `renderBoard()` 挂全课，离屏正文不卸载；显示层级切换重新布局 | 数据完整存在、正文生命周期和连续相机分别管理 |
| `refreshContent()` 读整课并重建画板，再恢复阅读状态 | 稳定身份驱动局部更新，选区、输入和展开现场独立保留 |
| 回答变化替换消息区域；回答 delta 约每 **150ms** 保存整份 conversation，`_put()` 还读全量状态 | 对话增量、草稿保留、正式提交分别调度，避免复制全部历史 |
| 知识提交整份 JSON 校验并 checkpoint；跨 JSON／SQLite 已有 journal | 保留恢复语义，但不因已有实现就锁定长期存储组织 |
| Agent 与内容协调器调用存储私有事务／操作表 | 公开行为级的提交回执、操作查询与输出追加接口，不能称当前存储可无成本替换 |
| `/events?after=` 是有序 JSON 批次，默认最多 **200 条**并带 `hasMore` | 有已保存事件游标可参考；它不是 SSE，换传输也不会自动获得去重或恢复 |
| 当时 `steer` 主要通知学生已修改内容 | 不等于通用引导／排队已经贯通，也不等于提交依据已更新 |

可追溯源码为[服务](../../legacy/review-board/reviewboard/service.py)、[运行时](../../legacy/review-board/reviewboard/agent_runtime.py)、[存储](../../legacy/review-board/reviewboard/storage.py)、[内容协调器](../../legacy/review-board/reviewboard/content_commands.py)及[接口](../../legacy/review-board/接口.md)。这些是选择独立调度与统一行为边界的理由；前端快不能证明后端更优，静态源码核查也不是运行验收。

## 6. 为什么选择 DOM 内容层，仍保留底座比较和源码研究

工作区路线已由 [ADR-0005](0005-react-flow-learning-workspace.md)确定。更细的适配理由是：完整讲解、长正文、公式、原生选文和实验控件是主要负载，空间节点服务它们。React Flow 提供可直接使用的 DOM／React 内容入口；代价是自行补齐基础绘图、批注、局部让位和输入协调，所需能力不能依赖 Pro 示例。库的 `nodrag/nopan/nowheel` 只是事件机制，`onlyRenderVisibleElements` 有额外筛选开销，也不替应用保留编辑现场，是否启用仍要按实现测量。

| 已比较路径 | 未采用为本轮路线的具体原因与保留判断 |
| --- | --- |
| Excalidraw 嵌入＋富内容扩展 | 可复用更多成熟绘图工具，`renderEmbeddable/customData/onChange` 和场景 API 确有入口；当时所查公开 API 未见与任意形状注册同等的命中几何／生命周期能力，完整内容内部状态控制不如所选路线直接。未核实其离屏嵌入状态，不能说它无法扩展或必然要 fork |
| 自建 DOM＋SVG／Canvas 空间底座 | 可直接围绕学习内容设计，但相机、空间索引、选择、标注、关系和历史都要自建；换渲染层不会自动解决当前问题 |
| tldraw SDK | 自定义内容、相机与命中接口适配较强，但当时核查的生产许可要求有效 trial／commercial／获批 hobby 许可，hobby 有水印，即使密钥可离线验证也不符合宽松开源且无需额外运行授权的硬约束。排除依据是许可，不是性能或接口不可用 |

Robert 明确要求即使不采用 tldraw，也继续读其源码。依赖采用与实现研究须分别判断。固定研究版本为 `7b7e23946c3d3f28391cf568edc07d2bb0d7c3d3`，保留的实现启发如下；这是当时源码阅读结果，不是当前上游版本或本产品已实现的声明：

| 已读机制 | 对独立设计有用的推理与限制 |
| --- | --- |
| `DefaultCanvas` 外层变换、`Shape` 几何／样式比较、`InnerShape` 内容缓存 | 相机、位置、正文分别做最小更新，不随平移重建学习内容 |
| `ContentElementSlot` 的 DOM 交还与复用生命周期 | 稳定 ID 或 React key 还不够，要检查真实 DOM 是否重建／迁移，编辑器和实验现场须独立于排序与位置 |
| 集中裁剪、只改可见性发生变化的容器 `display` | 减少分散订阅不等于整体 O(1)；仍遍历容器。`display:none` 不代表卸载，也不停止实验计算 |
| `stopCameraAnimation` 与 `stopFollowingUser` 分开 | 取消动画和撤销持续跟随许可是两个动作，不必因此引入多人协作模型 |

固定源码可从[对应提交](https://github.com/tldraw/tldraw/tree/7b7e23946c3d3f28391cf568edc07d2bb0d7c3d3/packages/editor/src/lib)按 `components/default-components/DefaultCanvas.tsx`、`components/Shape.tsx`、`hooks/useShapeCulling.tsx`、`editor/Editor.ts`、`hooks/useCanvasEvents.ts`、`hooks/useGestureEvents.ts`、`hooks/useDocumentEvents.ts` 追溯。源码机制提供参考，不改变本产品由课程核心维护知识、个人内容和历史的边界。

## 7. 完整负载实验究竟支持了哪一层决定

### 固定尺寸：收益主要在启动与缩远长帧

2026-10-27 的[固定负载记录](../../experiments/architecture-spike/验证记录.md)使用课程 **84 单元、1,215 正文块**，含 **50 公式块、200 表格块、82 图示块、7 交互块**，复制并分配新身份形成 500 单元合成负载。环境为 Apple M5、16 GiB、Chrome **156.0.8078.48 headless**，1440×1000、DPR 1；每种场景最终测量一次，缓存可能已暖。它比较同一 React Flow 样例的挂载策略，不是旧版与新版正式应用的端到端对照。

| 500 单元合成负载 | 全量挂载 | 壳体常驻、正文按需挂载 |
| --- | ---: | ---: |
| 首屏就绪 | 1,675.8ms | 163.5ms |
| 首屏 DOM 元素，不含 Shadow DOM | 137,431 | 6,157 |
| 阅读＋模拟修改 rAF P95 | 16.7ms | 16.7ms |
| 概览＋模拟修改最大 rAF 间隔 | 250.1ms | 33.3ms |

两种策略常规阅读移动都较平稳；不能概括为移动性能提升十倍、总内存必然下降或换框架即可消除全部闪烁。首屏计时含库、样本、首批正文、字体、图片与两帧就绪，不含正式 CourseService；堆内存受 GC 影响，后段按需策略不始终更低。完整原始值保存在 [results.json](../../experiments/architecture-spike/results.json)，固定实验绑定的旧源码／bundle hash 见验证记录，后来的动态补丁不构成对旧性能数字的重新验收。

**27 项**资源、页面和交互检查覆盖跟随动画中断、后续输出不抢回、返回最新目标、选文保护、草稿／公式光标、离屏状态恢复、移动后定位；另有 **20 次**交替新上下文启动成功。中文测试是已填入中文和合成 composition，重载恢复用样例 localStorage，交互以按钮为主。真实 IME、复杂拖动／持续计算、长聊天、真实 Agent 和正式持久化未由它证明。早期缺原页图片的数据不采用；补齐路由和解码检查后的一次就绪超时未再复现，但该超时未独立归因，20 次成功不等于跨环境可靠性验收。

### 动态尺寸：功能通过仍有 100ms 回调空档

[动态布局记录](../../experiments/architecture-spike/动态布局验证.md)的 **26 项**组合检查证明固定宽度、向下投影场景下的真实高度反馈、连锁让位、拖动和最新手动基线恢复。后补单次持续增长＋相机实验实际 **7,012.5ms、140 次更新、19.964Hz**；rAF **P95 16.7ms、最大 100.0ms**，long task 为 0。不能把 P95 写成全程无卡顿，也不能将这次空档直接归因于 O(n²) 解算独占主线程；具体时刻与调用栈未采集，记录未区分调度和呈现原因。

动态实验中的 DOM 原生激活不冒充物理鼠标点击。功能通过不证明任意布局、可变宽度、关系线绕行、持久片段锚点或正式课程恢复；旧“局部让位未测”已被有界补测推进，但不能扩大为全部布局已验收。500 是用户确认的增长规划目标，非硬上限；为未经需求支持的 1,000 单元继续扩大基准不是当时目标。

## 8. 为什么桌面、宿主、核心和存储分开决定

Robert 允许重评全部内部实现，但要求保留课程、个人笔记、历史与产品行为；现有 Python、JSON 或工具兼容成本不是长期约束。仅核查现有后端不足以决定它优于替代路线，因此研究先定义运行寿命、一次修改的一致性与恢复，再判断语言、进程和传输。早期“先接旧课程 API”的建议相应修正为先稳定核心命令／提交／恢复合同，旧服务作对照而非强制依赖。

桌面形态解决课程打开、窗口、后台任务入口和明确退出的整条路径。用户没有必须用浏览器或无法安装的场景，说明取舍后才接受独立桌面；不能从他要求解释推荐理由推定已经接受。外部浏览器＋本地服务同样可实现核心能力，桌面不天然更快。宿主、核心语言／承载、存储各有独立确认，详见 ADR [0001](0001-independent-desktop-delivery.md)、[0002](0002-electron-desktop-host.md)、[0003](0003-typescript-node-worker-core.md)、[0004](0004-sqlite-course-storage.md)。macOS 先打磨与 Windows 推广发布前必做均已确定，不能长期依赖 macOS 专属核心能力。

### Electron 接受的是明确成本，而非“最轻宿主”

[同页面资源实验](../../experiments/desktop-resource-spike/README.md)修正焦点／默认节流条件后，固定完成 **3 对／6 次运行**；M5／16 GiB、1000×700 CSS px、DPR 2、可见且聚焦，相同 500 article／3 个重正文，约 8 秒动态阶段各 16 次段落增长。Electron **40.10.6** 的动态 footprint 中位数范围为 **609.74–615.48 MiB**，系统 WK 为 **391.07–397.69 MiB**；rAF P99 分别 **17.6–17.7ms** 与 **91–92ms**，WK 每轮 **16 个 >50ms** 间隔。两端 P95 都约 18ms，会掩盖这段长尾。

这些是确认归属进程组的内核 footprint 与回调节奏，不是独占整机 RAM、呈现帧、物理输入延迟或完整产品排名。WK 回调较少，其更低 CPU 不证明同等效果下更高效；未做 profiler，不能宣称系统 WebView 不可修复。Swift／WK 最小宿主也不是完整 Tauri 产品。阅读阶段的内存关系还会反转，不能拿空壳体积代替真实负载成本。

初轮失焦数据完整保留在 [results.json](../../experiments/desktop-resource-spike/results.json)，`failures=[]` 不等于公平性成立；有效补测在 [results-v2.json](../../experiments/desktop-resource-spike/results-v2.json)，二者不能拼成六对有效统计。实验只按需挂载 DOM，仍将完整 fixture 复制为 500 份常驻内存，**没有实现从核心按阅读范围读取正文**。正式的四项轻量化约束因此仍是实施要求，不是已完成收益。重新选型需要新的实际效果／成本证据，本轮不并行建第二套宿主。

### Worker 与 SQLite 分别减少什么成本

“关窗继续”只要求任务拥有者比学习窗口活得久，不要求独立核心进程；“固定 Chromium”也不是实现复杂编辑效果的唯一途径。这两条是第一性原理重推时明确纠正的论证。普通核心用宿主拥有的一个 Worker，复用已交付的 Node，将同步校验和存储移离宿主事件线程；长解析或确需原生故障隔离的工具才按需另起受管进程，Python 可按工具收益引入。

[核心承载实验](../../experiments/core-placement-spike/README.md)的 **18 场景／4,320 次保存**使用真实 Electron **40.10.6**／Node **24.15.0**／SQLite **3.51.3**。utility 比 Worker 多约 **11 MiB footprint**，短事务下宿主定时器接近空载噪声，没有稳定的独立进程响应收益；这不证明 Worker 比主线程更快。Worker 仍与宿主共享原生崩溃边界，普通 JS 异常与原生崩溃不能混称。测量没有学习 renderer；主动 terminate／退出重开也不是断电或 native crash 注入。该 runtime 的 `eventLoopUtilization` 全部为零而不可用，不能解释为零阻塞。

SQLite 的理由独立于语言偏好：例如同时修正公式和例题，当前值、必要历史、版本与成功回执须共同成立，避免再自行维护多份权威文件间的恢复协议。同库不等于每次重写整课，结构化载荷也不等于每个富文本属性都建一列。单 JSON、JSON＋数据库、不可变正文文件＋事务性引用、自建追加日志均被比较过；文件正文方案可以成立，但用户已确认画板／接口写入与开放交换足够，没有直接文件创作收益抵消大量小正文的发布／回收成本。详见[存储推导](../research/architecture/第一性原理与轻量化架构.md#3-从一次修改推导存储而不是从数据库名称出发)。

大资源仍需先完整发布再登记引用，SQLite 不包办文件落盘、语义正确、冲突或备份。格式升级、开放交换、一致备份与 Worker 消息／退出恢复都是接受的成本；不能另加一套同时可写的 JSON 来换取“开放”名义。旧 journal 是可参考实现，不是长期必须维护的形态。HTTP／SSE 也是历史候选，桌面内部传输已定受限 IPC，不能继续标成未选协议。

## 9. 为什么采用受约束交互，而不把生成 UI 演示当课程系统

用户允许新交互学习内容，但要求工具、skills 或明确机制引导生成。2026-10-27 的三类参考各提供部分启发：

| 当时核查的参考 | 可借鉴机制 | 未解决的本产品问题 |
| --- | --- | --- |
| OpenAI Intelligent UI 公开说明 | 受约束组件组合、流式界面及生成中编译 | 公告未公开可直接照搬的协议实现 |
| Thesys Open Intelligent UI | OpenUI Lang 1.0 的组件／状态／表达式／动作、schema 注册、流式解析与 HtmlView 扩展 | 演示 localStorage 不满足课程文件夹备份迁移；解析器性能另验 |
| CopilotKit OpenIntelligentUI | skills／工具产出有序 CSS、HTML、JS，渐进预览、最终沙箱和有限宿主回调 | 后续回答为独立快照，没有通用跨轮原位修改旧界面接口；内部控件状态不自动同步给 Agent |

这些是历史公开机制核查，不是依赖采用或性能结论。选定的是常用组件＋特殊扩展两层表达，当前不要求整个画板采用新 DSL。skills 指导何时用交互及如何教学，工具／格式检查写入结构，运行层管理状态与资源；语法合法不等于课程知识正确，稳定身份、来源、笔记、历史与迁移仍由产品负责。

复杂实验的内部逻辑交 Agent，学生操作参数与声明字段，避免首版变成通用程序编辑平台。离屏隐藏、iframe 和 sandbox 都不等于计算已停止或独立 CPU 进程，快照也不是保存运行堆；已确认的分步计算／状态合同见[总稿第 4 节](../architecture/系统设计定稿.md#4-交互实验的内容与运行合同)。操作结束后兼容现场自动迁移、不兼容保留旧现场询问均已定案，不是等待用户选择的分支。

## 10. 为什么历史与编辑要保留三类不同证据

Robert 要求参考 Notion、Figma、Obsidian、VS Code，但强调真实收益、性能、存储和复杂度，尤其不要把 ⌘／Ctrl+Z 与历史回退混为一谈。由此选择当前数据＋一套正式变更记录＋最新草稿，放弃先建分支、永久逐键／逐 token 回放、完整事件溯源平台或多套全文快照的方向。历史列表按需生成和分组，不必复制第三方保存间隔；Notion 的 10 分钟也不是本产品参数。详细语义、测量和成本已经在[历史设计](../architecture/历史管理与恢复设计.md)，无需再复制一份。

需要记住证据之间的区别：

- [存储实验](../../experiments/storage-spike/README.md)的 **136 条断言**支持所测事务、去重、停止竞争、草稿与有限资源迁移；没有实现完整选择性撤回、对象级历史或整课恢复。500 单元下 240 次混合保存、60 次正式提交各改两单元，checkpoint 后约增 **3.08 MB**，不是纯历史、物理写入总量或长期增长率。
- [历史实验](../../experiments/history-spike/README.md)的 **37 项检查**覆盖所测逆操作／恢复语义；同轨迹正文历史载荷 **30.24→1.86 MB**、数据库净增 **30.99→2.95 MB**。约 **93.85%** 的节省分母是该合成轨迹的正文历史载荷，不是整课或 I/O。保存 P95 有波动，中间轮变化块策略更慢，不能宣布整体性能胜出。其“键盘撤销”是调用方给定目标，不是快捷键路由；草稿异常退出不证明历史恢复中途崩溃通过。
- [键盘实验](../../experiments/undo-input-spike/README.md)的 **22 项事实检查包含缺口复现**：macOS 合成按键下 textarea／MathLive 撤销重做有效，拖动对象后画板 ⌘Z 不恢复位置。textarea 不等于正式富文本，localStorage 不等于 CourseService；Windows Ctrl+Z 和物理输入法未验。

这些结果支持“只记录变化对象”以及继续连接真实编辑路径，不支持立即增加压缩链、周期全课快照或重复跑相同基准争取更好数字。默认 140 天且学生可调已明确替代早先不按时间自动删除的推荐；保留当前个人记录不等于其每次旧修改都永久可恢复，隐藏工具载荷也不能变成绕过期限的第二套正文历史。

同一 B 连续编辑与“离开当前段落后自动更新”也已确定。前者源于当前逐块 UI 不能限制学生跨段改写，后者源于停下来思考不是结束输入；草稿保存不等待离开。官方事务核查还纠正了“外部修改就使整单元 Undo 失效”的旧候选：结束分组不等于清空历史，范围事务可映射可用步骤，但合法位置不保证原语义。同处删除、composition 和公式内部仍需核验。

Tiptap、直接 ProseMirror、Lexical 的比较及选择原因已在 [ADR-0006](0006-tiptap-prosemirror-mathlive.md)和[编辑保存设计](../architecture/正文编辑与保存衔接设计.md)；Lexical 的额外成本判断来自默认快照历史源码，不是实测淘汰或无法定制的结论。公式符号／子表达式批注已经纳入首版，MathLive 选区数值及 atom ID 不是跨版本永久身份；不能因尚未组合验证而退回只允许整公式批注。

## 11. 尚缺的是实现证据，不是已定问题的重新确认

当前没有未选择的产品／架构分支。以下是真实交付缺口，按[总稿六阶段验收](../architecture/系统设计定稿.md#9-实施顺序与验收)推进；缓存、批量间隔、具体表字段、库版本和后续解析器按合同实施与测量，不额外建立审批轮。

## 12. 早期原型还留下了哪些具体证据

[独立讨论草图](../../experiments/review-board/README.md)用于比较路径，其验证不是正式应用验收。为避免清理长讨论时把精确范围压成一句“原型通过”，保留以下当时事实：

- Chrome 本地 HTTP 页面验证了整窗布局、区域定位、真实指针拖动、缩放、选择 `I1` 后菜单展开侧栏，侧栏宽度由 **290 调至 390px**，以及直接补充、撤回／重做。添加解释后再写笔记，撤回解释仍保留笔记；刷新恢复依赖浏览器本地存储，不是课程文件。
- 固定 MUX 交互在 **xy=01** 时，**z=0 输出 1、z=1 输出 0**，与该真值表一致；不是任意输入、任意课程或真实模型能力验证。
- **1024px** 预览能阅读全图，**390px** 预览无页面横向溢出、远景显示标题、Agent 面板置于下方；期间未发现浏览器错误，不由此新增移动端承诺。
- 曾修正保存状态回传导致选择菜单立即关闭的问题；聚焦按实际出现内容计算，新增解释连线随内容显示。该草图未覆盖真实 Agent、文件持久化、冲突或完整课程。
- 自动化 Fullscreen API 被浏览器以 `not granted` 拒绝，验证的是备用提示；未直接验收原生浏览器全屏或双击 HTML 的 `file://` 路径。自包含、无外部资源的静态检查不等于这些路径已实测。

这些记录解释了为什么后来要交付可独立打开、全屏操作的原型，而不继续用对话内嵌交互作为交付入口；同时明确早期模拟能力的上限。样式原型、真实内容原型、固定／动态负载、宿主与存储实验应分别保留证据身份，不能合并成一次“系统通过”。
