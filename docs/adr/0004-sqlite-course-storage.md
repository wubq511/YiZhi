# 每课 SQLite 与课程资源文件

2026-10-29 范围修订：下文保留当时的存储选择理由；开放内容交换已由 [ADR-0008](0008-product-development-boundary.md) 从当前产品移除，格式升级改由应用自动完成。SQLite、资源文件与一致备份的决定继续有效。

Robert 明确接受每门课程一个 SQLite 数据库＋课程资源文件。数据库管理结构化正文、个人记录、布局、正式修改历史、最新可恢复草稿及任务／操作回执，知识与个人内容等领域继续逻辑分开。正文按内容对象保存结构化载荷，支持按阅读范围读取；PDF、图片与大型产物保存在课程目录的资源文件中。

依据是一组修改所需的当前内容、撤回材料、版本与成功回执需要共同提交。SQLite 的短事务可减少自建跨权威文件恢复协议；同库不要求每次操作写整课，也不要求把每个富文本属性拆成独立 SQL 列。比较过单 JSON、JSON＋数据库、不可变正文文件＋事务性引用以及自建追加日志；在已确认通过画板／接口写入、开放格式交换足够的前提下，当前没有直接文件创作需求抵消小正文外置的发布和回收成本。完整依据见[第一性原理与轻量化架构](../research/architecture/第一性原理与轻量化架构.md#3-从一次修改推导存储而不是从数据库名称出发)。

接受显式课程格式升级、开放导入导出和一致备份的维护成本。外置资源先完整发布再登记不可变引用，数据库事务不包办文件保存；课程迁移包含一致的数据库及其资源，读写中的 WAL 不能遗漏。开放格式是交换出口，不再增加另一套同时可写的权威 JSON。具体 schema、索引和绑定继续通过实施验证确定；现有 JSON 权威应用仍是当前运行版本，本决定不表示已完成数据迁移或完整恢复验收。
