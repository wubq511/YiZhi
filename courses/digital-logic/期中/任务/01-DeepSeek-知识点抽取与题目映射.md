# DeepSeek 执行规格：课件知识点抽取与题目映射

状态：可交给 DeepSeek 执行；产物仅进入待审查区，主 Agent 审查后再继续后续任务。

## Problem Statement

Robert 正在为数字逻辑期中复习准备知识地图。当前需要先把教师第 01–06 课中的内容抽取为层次合适的知识主题与知识单元，再把六次课后作业和考前组合习题课逐题映射到这些单元。

这项工作时间密集，但真正的风险不是“没有生成文字”，而是漏页、错读公式和电路、按教材扩范围、知识点粒度过粗或过细，以及把解题所需但不直接考查的内容全部当成重点。Robert 希望由 DeepSeek 完成资料处理，主 Agent 随后独立审查并继续评级、价值关系筛选和消费产物生成。

## Solution

DeepSeek 根据教师资料生成一套相互关联、可供主 Agent 直接审查的结构化草稿：

1. **课件知识点草稿 `01-课件知识点.draft.json`**：包含资料来源、知识主题、知识单元、单元内部内容、课件逐页覆盖记录和未决问题。
2. **题目映射草稿 `02-题目知识点映射.draft.json`**：包含题目、小问、习题课参考条目、直接考查与前置支撑映射、逐题覆盖记录和未决问题。
3. **抽取与映射核对报告 `03-抽取与映射核对.draft.md`**：用人类可读方式汇总数量、覆盖、排除、原页核对、跨题引用、异常和未决问题。

产物保存到《交付与验收》规定的待审查区。它们不是权威知识数据，也不是最终复习材料。DeepSeek 不提前进行重要性评级、价值关系建图、画板布局、HTML、查询工具或项目 Skill 开发。

最终交付必须让 Robert 和主 Agent 能回答：

- 每个知识单元来自教师资料的哪一页，为什么按这个粒度拆分？
- 348 页课件是否全部得到处理，混合页面和排除项去了哪里？
- 每道题及每个小问实际直接考查什么，还需要哪些前置支撑？
- 哪些公式、电路和扫描题目已经看过原图，哪些仍存在不确定性？

## User Stories

1. 作为 DeepSeek 执行者，我要先阅读项目已经确认的课程设计、拆分规则和交付约定，以便不重新发明范围、术语和层级。
2. 作为 DeepSeek 执行者，我要以第 01–06 课教师课件为框架，以便不把教材目录误当成考试范围。
3. 作为 DeepSeek 执行者，我要把考前组合习题课作为老师明确指定的参考材料，以便识别其中点名的基本题型、器件和解答例题。
4. 作为 DeepSeek 执行者，我要排除实验与 SystemVerilog/HDL 内容，以便遵守本次期中整理边界。
5. 作为 DeepSeek 执行者，我要保留同页或同模块中的非 HDL 电路原理，以便不因课件含代码而误删考试内容。
6. 作为 DeepSeek 执行者，我要保留二极管、TTL、CMOS 等理论内容，以便不把“无实验”误解为“无器件理论”。
7. 作为 DeepSeek 执行者，我要按“课次—知识主题—知识单元—单元内部内容”组织结果，以便支持后续清单、题目映射和画布消费。
8. 作为 DeepSeek 执行者，我要为每个知识主题写一句核心学习表现，以便后续能按主题层证据评定整体重要性。
9. 作为 DeepSeek 执行者，我要把知识单元拆到可独立考查和判断掌握的程度，以便一个单元能明确回答“需要会什么”。
10. 作为 DeepSeek 执行者，我要区分概念与规律、方法与技能、模块与器件，以便不把不同性质的内容混成一个节点。
11. 作为 DeepSeek 执行者，我要把公式、条件、变体和例题定位保留在单元内部，以便避免按页面或公式机械拆点。
12. 作为 DeepSeek 执行者，我要保留没有直接作业的课件内容，以便不把“没布置作业”误当成“不考”。
13. 作为 DeepSeek 执行者，我要记录精确 PDF 页序，以便主 Agent 能回查每个单元和题目。
14. 作为 DeepSeek 执行者，我要在教材仅用于校准表述时同时记录中文书页和 PDF 页序，以便保持教材引用可核查。
15. 作为 DeepSeek 执行者，我要把个人笔记仅作为可选参考，以便不让学生笔记替代教师资料或成为独立范围证据。
16. 作为 DeepSeek 执行者，我要逐页记录课件去向，以便证明全部 348 页都得到处理而不是只抽取容易识别的页面。
17. 作为 DeepSeek 执行者，我要能表示一页同时包含有效知识与排除内容的情况，以便不粗暴地保留或删除整页。
18. 作为 DeepSeek 执行者，我要查看影响理解的公式、反相线、上下标、真值表、卡诺图、波形图、电路和芯片引脚原图，以便不凭文本提取猜补符号。
19. 作为 DeepSeek 执行者，我要查看扫描版教材题页和只有图像的作业页，以便不因没有文本层而遗漏题目。
20. 作为 DeepSeek 执行者，我要覆盖六次作业和第四次网页补充要求，以便不把补充题排除在映射之外。
21. 作为 DeepSeek 执行者，我要把习题课基本题型清单、器件汇总和解答例题分开记录，以便不把它们混算成同一种作业证据。
22. 作为 DeepSeek 执行者，我要保留每个独立小问及父子关系，以便不把一道综合题粗略映射到一个知识点。
23. 作为 DeepSeek 执行者，我要追踪题目实际引用的前题函数、图号和跨页内容，以便在完整题意下判断映射。
24. 作为 DeepSeek 执行者，我要区分直接考查和前置支撑，以便后续重要性评定不会虚增每个基础知识点的作业权重。
25. 作为 DeepSeek 执行者，我要允许一道题直接考查多个知识单元，以便如实表示综合题而不是强迫单选。
26. 作为 DeepSeek 执行者，我要让同一道题对同一单元的同种映射只出现一次，以便覆盖统计不重复计数。
27. 作为 DeepSeek 执行者，我要标明映射依据来自题干、官方参考答案还是执行者分析，以便不把自己的推理解释冒充教师答案。
28. 作为 DeepSeek 执行者，我要使用稳定且唯一的主题、单元和题目 ID，以便两份草稿能够准确互链。
29. 作为 DeepSeek 执行者，我要输出合法 JSON 和一份核对报告，以便机器消费与人工审查同时进行。
30. 作为 DeepSeek 执行者，我要显式记录无法核实的内容和原因，以便不把不确定内容包装成完整成果。
31. 作为 DeepSeek 执行者，我要只写入待审查区，以便不覆盖权威数据、设计文档或最终产物。
32. 作为 Robert，我要通过核对报告快速发现漏页、排除错误、映射争议和未决问题，以便决定需要重点复核哪些内容。
33. 作为主 Agent，我要在 DeepSeek 提交后独立对照原资料审查草稿，以便修正后再开展评级和关系筛选。
34. 作为后续 Agent，我要读取带稳定 ID 和来源引用的结构化内容，以便无需从 Markdown 或显示名称猜测知识身份。
35. 作为 Robert，我要 DeepSeek 不提前评星、建关系或生成画板，以便后续决策仍基于审查后的完整证据。

## Implementation Decisions

### 1. 先读规则与资料入口

执行前阅读并遵守以下项目文档，具体位置以项目入口为准：

- 《资料说明》：了解课程资料、合并版作业和教材检索入口。
- 《课程知识地图设计》：确定来源、范围、排除项、层级、题型和题目映射规则。
- 《知识点拆分规则》：确定知识主题与知识单元的粒度、类型、合并和停止条件。
- 《知识关系价值与呈现规则》：仅用于理解本任务不生成关系边的原因，不开展关系建图。
- 《数据与消费接口》：理解稳定 ID、来源引用、结构化数据和待审查产物与权威数据的区别。
- 《交付与验收》：确定待审查区、覆盖要求和后续审查接缝。

教材需要补充或校准表述时，遵循项目教材检索与原页核对流程。无需外部网络调研，无需重新 OCR 或重建教材索引。

### 2. 来源优先级与范围

- 第 01–06 课课件决定框架和基础范围。
- 第 01–06 次作业合并版用于题目映射；第四次网页补充要求必须包含。
- 组合习题课包含基本题型、常用器件和解答例题，三类内容分开处理。
- 教材只补充或校准已经处于教师资料范围内的知识，不增加仅因教材存在而出现的新主题。
- 个人笔记不是独立来源证据。
- 排除实验与 SystemVerilog/HDL 的语法、代码阅读、代码编写和代码专属操作；习题课中出现的 HDL 项同样排除。
- 非 HDL 电路原理仍按教师资料保留，包括混合页面中的有效部分和器件理论。

### 3. 产物与边界

只生成以下三份草稿，不修改其他文件：

| 草稿 | 内容 | 不承担的职责 |
| --- | --- | --- |
| `01-课件知识点.draft.json` | 来源、主题、单元、内部内容、逐页覆盖、问题记录 | 最终讲义、星级、关系图 |
| `02-题目知识点映射.draft.json` | 题目、参考条目、映射、逐题覆盖、问题记录 | 完整题解、作业权重、关系图 |
| `03-抽取与映射核对.draft.md` | 数量、覆盖、排除、原页核对、跨题引用、异常与未决问题 | 用汇总文字替代结构化草稿 |

草稿使用 UTF-8 和合法 JSON，不含注释或尾随逗号。输出到约定待审查区，保持 `ready-for-review` 或 `blocked` 的明确状态。

### 4. 知识点草稿结构

顶层包含 `schemaVersion`、`status`、`sources`、`themes`、`units`、`pageCoverage` 和 `issues`。

#### 资料来源

每个来源包含：稳定来源 ID、类型、标题、项目内定位、总页数和版本信息。课件、作业、习题课和教材使用不同来源类型。

#### 知识主题 A

每个主题包含：

- `id`、`lessonId`、`name`。
- `coreOutcome`：一句核心学习表现。
- `sourceRefs`：支持该主题范围的来源位置。

主题应是可评价的知识对象或方法，不只是课件标题的换名。

#### 知识单元 B

每个单元包含：

- `id`、`themeId`、`kind`、`name`。
- `aliases`：必要的常用称呼，可用于后续精确查找。
- `kind`：仅取 `concept`、`method`、`module`，分别对应概念与规律、方法与技能、模块与器件。
- `outcome`：一句可检查的“需要会什么”。
- `summary`：必要的简要说明，不扩写为完整讲义。
- `internals`：定义、公式、条件、变体、例题定位和注意事项。
- `questionTypes`：数制转换、函数化简、逻辑分析、逻辑设计，可多选；确实不适用时标为基础支撑。
- `sourceRefs`：支持该单元的精确来源位置。

单元内部项使用 `definition`、`formula`、`condition`、`variant`、`example`、`caution` 等类别，避免把每项内部内容另拆为独立节点。

### 5. 来源引用与原页核对

每个来源引用包含：

- `sourceId`。
- `pdfPages`：从 1 开始的 PDF 页序，不能照抄可能错误的课件页脚。
- `bookPages`：仅教材引用需要时填写中文书页，并同时保留 PDF 页序。
- `visualStatus`：`verified`、`not-needed` 或 `unverified`。
- `note`：说明所指内容、跨页关系或核对限制。

以下情况必须渲染并实际查看原图，不能只检查文本提取：

- 公式、反相上划线、上下标和特殊逻辑符号影响含义时。
- 真值表、卡诺图、波形图、电路连接、阵列连接和芯片引脚影响理解时。
- 扫描教材题页、只有图像的作业页和文本层明显不可靠的页面。
- 同一页同时出现有效电路内容与应排除代码，需要判断保留范围时。

无法确认的内容标为 `unverified` 并进入 `issues`，不能根据上下文猜成确定内容。临时渲染图在处理完成后删除，草稿只保留核对状态和来源定位。

### 6. 逐页覆盖记录

`pageCoverage` 对第 01–06 课的每一个 PDF 页面都保留一条且仅一条记录。每条包含：

- `sourceId` 和 `page`。
- `disposition`：`mapped`、`background`、`excluded`、`nonContent` 或 `mixed`。
- `unitIds`：该页支持的知识单元，可为空。
- `excludedParts`：页内被排除的内容及原因；没有则为空。
- `visualStatus` 和必要的 `note`。

`mixed` 用于同页既有有效知识又有排除内容的情况。空白、纯过渡和重复封面可标为 `nonContent`，介绍与背景可标为 `background`，均须保留记录。

所有页码必须连续覆盖，不能出现遗漏或重复。不能用关键词搜索代替逐页范围判断。

### 7. 题目与参考条目结构

题目映射草稿顶层包含 `schemaVersion`、`status`、`questions`、`referenceItems`、`mappings`、`questionCoverage` 和 `issues`。

每个题目包含：

- `id`、`sourceId`、可选 `parentId` 和原始 `label`。
- `kind`：普通作业或习题课解答例题。
- `taskSummary`：简述题目要求，不写完整题解。
- `questionTypes`：四种正式题型之一或多个；确需时标基础支撑。
- `sourceRefs`：题干及所有必要引用位置。
- `hasOfficialAnswer`：区分教师答案与执行者分析。

每个能独立要求作答的小问使用独立题目 ID，并通过 `parentId` 保留原题组关系。原题编号重复时，ID 仍须唯一，原始编号与页码共同保留。

习题课基本题型清单与器件汇总使用 `referenceItems`，包含 `id`、`kind`、`label`、`relatedUnitIds` 和 `sourceRefs`。它们不与解答例题混算题目频次。

### 8. 直接考查与前置支撑映射

每条映射包含：

- `questionId` 和 `unitId`。
- `role`：`direct` 或 `support`。
- `basis`：`stem`、`official-solution` 或 `agent-analysis`。
- `note`：说明为什么这样映射，尤其是综合题和支撑项。

判断规则：

- `direct`：题干明确要求，或官方参考解答中必须独立完成的操作。
- `support`：完成题目需要，但不是题目实际考查目标的知识单元。
- 没有官方答案时，可依据题干和必要分析判断，但分析依据必须标为 `agent-analysis`，不得冒充教师答案。
- 一道题可映射多个直接单元和多个支撑单元。
- 同一题目、同一单元、同一角色只保留一条映射；小问各自独立记录。
- 前置支撑不自动等于后续图中的学习前置，本任务也不生成学习前置边。

### 9. 作业与习题课的特殊覆盖要求

- 合并版作业中的文本和附图都要检查；必要时对照原始作业，不能以文本层空白代替题目存在。
- 第四次作业的网页补充要求单独保留来源，但与第四次作业一起完成映射。
- 第五次作业没有可确认的一一对应教材原题，不得根据相似主题自行配题号。
- 第六次作业涉及前题函数与图号时，追踪到实际所需页面，并区分本题保留条件与引用题原有条件。
- 习题课第 2–3 页的基本题型和第 4 页的器件汇总作为参考条目；第 5–18 页的 12 组例题逐题、逐小问映射。
- 习题课答案用于识别实际操作，不把答案里出现的每个公式都升级为直接考查。
- 跨页题目和被引用图页必须列入来源引用，不能只记录题号所在的第一页。

### 10. ID 与一致性

- 主题、单元、题目和参考条目使用不同 ID 命名空间。
- ID 不含课次、星级、名称或页码等容易变化的信息。
- 两份草稿共享同一套主题、单元和来源 ID；题目映射不得引用不存在的单元。
- 同一内容不得因名称不同而重复建单元；需要时添加别名。
- 本任务不分配重要性、关系或视觉元素 ID。
- 合入审查前，这些 ID 仍属草稿 ID；审查中的合并或更正必须记录，不能无声改变两份文件的对应关系。

### 11. 核对报告

核对报告至少包含：

1. 每课页数、 mapped/background/excluded/nonContent/mixed 数量和页码连续性结果。
2. 每课主题数、单元数及单元类型分布。
3. 每次作业和习题课的题目、小问、参考条目、直接映射与支撑映射数量。
4. 原页核对范围及所有 `unverified` 项。
5. 第四次补充要求和习题课三类内容的独立统计。
6. 跨页、跨题引用及其完整性。
7. 排除实验与 HDL 的范围说明；不能只用关键词计数作为排除正确的证明。
8. 重复单元、合并判断和粒度争议的处理记录。
9. 没有直接映射的题目及原因。
10. 所有未决问题、需要主 Agent 重点复核的页面和最终 `ready-for-review` 或 `blocked` 状态。

## Testing Decisions

### 1. 唯一验收接缝：完整草稿包

测试放在“完整草稿包对外是否可信”这一最高接缝，不要求为文档处理再创建生产代码或单元测试框架。检查分为机器可验证的一致性和必须对照原资料的语义审核，两者不能相互替代。

### 2. 结构化与覆盖检查

DeepSeek 在提交前使用现有工具或一次性标准库脚本检查：

- 三份草稿存在，两个 JSON 均可解析，状态明确。
- 所有实体 ID 唯一，所有主题、单元、来源、题目和映射引用有效。
- 六课共 348 页逐页连续覆盖，没有漏页或重复记录。
- 来源页码不超过对应文件页数，教材引用具有所需双页码。
- 所有题目和小问均有覆盖记录；每题至少一个直接映射，或存在明确的未决原因。
- `role`、`basis`、`kind`、`disposition` 和 `visualStatus` 只使用约定取值。
- 同一题目、单元和角色没有重复映射。
- 没有星级、关系边、布局、HTML 或其他后续任务产物混入。
- 待审查区之外没有文件被修改。

### 3. 语义抽查与高风险必查

DeepSeek 自己先完成原页核对，主 Agent 提交后还会独立复核。DeepSeek 的报告中必须特别标出以下高风险项并说明核对结果：

- 反相线、上下标和逻辑表达式容易错读的页面。
- 卡诺图、真值表、波形图和电路连线。
- 低有效输出、使能条件和 74 系列器件引脚。
- 第四次补充题、第五次图像题、第六次跨题引用。
- 习题课答案中实际执行的步骤与仅作为公式出现的步骤。
- 同页 HDL 排除与非 HDL 原理保留。

关键词检索只能用于定位，不能作为内容正确、范围完整或排除正确的证明。

### 4. 完成与阻塞标准

只有全部检查通过、没有未说明的漏页或未核实内容时，才能标记 `ready-for-review`。

若外部工具或原页确实无法读取，DeepSeek 仍须完成所有未受阻部分，并标记 `blocked`，在 `issues` 和核对报告中列出具体文件、页码、影响和所需帮助。不得静默缩小范围，也不得把受阻部分当作已完成。

### 5. 可复用的既有检查方式

参考项目已有的教材完整性校验、双页码定位、原图核对和作业合并版定位方式。本任务没有需要沿用的生产测试模块；后续主 Agent 会在更高层继续检查草稿，并在消费模块中实现可重复执行的接口测试。

## Out of Scope

- 知识主题或知识单元的星级、考试概率、难度和个人掌握状态。
- 学习前置、构造、优化或其他价值关系的正式筛选与建图。
- 权威知识数据的合入、修改或发布。
- 最终三份人类阅读文档、交互 HTML、画板布局和画板图数据。
- Agent 查询工具、构建工具、项目 Skill、Skill 用例与评审页。
- 完整复习讲义、所有题目的完整解答、额外教材章节或外部网络资料。
- 实验内容、SystemVerilog/HDL 内容和旧画板原型迁移。
- 个人笔记编辑、真实 Agent 接入和完整复习系统。

## Further Notes

- 本地规格未发布到 issue tracker，也未应用 issue 标签；这不影响 DeepSeek 按本规格执行。
