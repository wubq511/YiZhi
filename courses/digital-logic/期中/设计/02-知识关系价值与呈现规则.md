# 知识关系价值与呈现规则

更新：2026-10-25  
状态：价值筛选规则已确认；43 个关系实例已审核，不再预先枚举或承诺关系类型。

## 1. 核心原则

本任务不穷举课程中的所有联系，也不先建立一套关系本体。筛选单位是**具体关系实例**，不是抽象关系类型。

每条候选边都必须回答：

> 这条边让学生、Agent 或画板多获得了什么？为什么把这条关系画出来，比放在节点名称、公式或单元详情里更有价值？

无法回答的，不建立关系记录。公式已经表达清楚、节点名称已经写明或只是“两者有关”的内容，不为了丰富画布而连线。

## 2. 每条图关系必须通过的检查

| 检查 | 通过标准 |
| --- | --- |
| 对象正确 | 两端都是实际存在、需要独立呈现的知识单元 B；不是公式、题号或单元内部句子 |
| 信息增量 | 关系提供了端点自身没有直接表达的信息，不重复名称、定义、公式或层级 |
| 画布收益 | 看见连接、路径或结构，能帮助理解、追溯、比较或迁移，而不只是让图更满 |
| 证据明确 | 方向、含义和课程来源清楚，不从章节先后或一般相关性猜测 |
| 非冗余 | 不重复归属、题目映射、已有路径或另一种更准确的记录 |
| 可审计 | 能写出一句具体的 `value`，说明它帮助谁完成什么复习或查询任务 |

关系类型只是对通过检查的实例做归纳。不能先认定某个类型有价值，再批量创建该类型的边。

## 3. 哪些内容可能值得进入画布

以下是**候选实例的寻找方向，不是已批准的类型清单**。

| 候选 | 真实例子 | 可能提供的额外价值 |
| --- | --- | --- |
| 直接学习前置 | 最小项与标准与或式 → 用译码器实现组合逻辑 | 解释“为什么需要先有这些知识”，支持复习顺序与查漏 |
| 构造 / 扩展 | 二选一 MUX → 用二选一 MUX 构造四选一 MUX；3–8 译码器 → 4–16 译码器 | 直接呈现模块组合、级联与规模扩展，空间结构本身有信息 |
| 优化 / 演进 | 行波进位加法器 → 超前进位加法器 | 呈现为什么改变结构、改善的是哪项指标，支持方案比较 |
| 其他跨单元联系 | 待从正式清单中寻找真实实例 | 只有画布收益超过文字表达时才保留，不预设“互逆”“相关”等类型一定有用 |

即使是上述方向，也必须逐边检查。若内容已在同一个单元中，或一张对照表更清楚，就不建边。

## 4. 哪些内容不建成知识关系边

“不建边”只表示不创建关系记录，不表示删除其中的课程知识。

| 内容 | 更合适的呈现位置 | 不建边的理由 |
| --- | --- | --- |
| 互补、反函数、对偶、等价等数学事实 | 相关单元的公式与简要说明 | 公式已经准确表达，再连线通常只是重复 |
| 表示之间的转换 | “表示转换”方法单元的目标与步骤 | 转换是操作内容，不需要把各表示两两连接 |
| 分类、特化、主题归属 | 课次—主题—单元的层级 | 层级已经表达，重复连线会增加噪声 |
| 芯片型号与通用模块的对应 | 模块单元的型号、端口和有效电平说明 | 属单元身份与使用信息 |
| 条件、约束、因果、检测能力 | 单元内部条件、定义和功能边界 | 通常是单元自身需要掌握的内容 |
| 方法变体 | 单元内部变体列表 | 粒度规则已决定是否拆点，不另造一组变体边 |
| 应用场景与例题 | 关联题目、例题或应用说明 | 题目映射已能准确查询，不冒充知识依赖 |
| 直接考查、前置支撑 | 题目到单元的证据映射 | 是复习证据，不是课程概念之间的语义关系 |
| 解题顺序 | 方法步骤或题型流程图 | 操作顺序不是知识关系 |
| 章节顺序、一般“相关” | 不保留为关系 | 没有明确语义和增量 |
| 传递依赖的重复边 | 由查询或图算法按需计算 | 已有 `A → B → C` 时，不为展示路径再手工添加 `A → C` |
| 重复节点名称的关系 | 单元名称与掌握目标 | 例如“用译码器实现函数”已经写明的内容，不再用边复述 |

## 5. 层级之间不重复维护关系

- 课次 → 主题 A → 知识单元 B 用归属字段表达，不画成知识依赖。
- 图关系只在一对实际 B 之间人工审核和记录。
- 主题之间的概览连接若需要，可由 B–B 关系聚合生成，并保留下钻到原始边的入口；不手工维护另一套 A–A 关系。
- 传递前置、祖先、后继和路径由工具计算，不作为人工录入的冗余边。

## 6. 呈现位置的最终判断

| 信息价值 | 呈现位置 |
| --- | --- |
| 连接、路径或结构本身带来额外理解 | 画布中的知识关系 |
| 主要帮助理解当前单元 | 单元详情、公式、对照表或方法步骤 |
| 主要说明老师如何考查 | 题目映射与证据视图 |
| 主要帮助定位原文 | 来源引用 |
| 只是能够陈述“存在关系”，但没有额外用途 | 不保留为关系记录 |

## 7. 工作流程

1. 抽取主题 A、知识单元 B 和单元内部内容。
2. 完成题目映射和来源核对。
3. 对少量有明确用途的 B–B 候选逐条写出 `value`、方向和来源。
4. 删除重复、传递冗余和不如文字表达的关系。
5. 从实际保留的实例归纳关系类型，再决定线型、默认视图和筛选器。
6. 让学生看到的是精选关系，让 Agent 能查询关系依据，让画板只消费有明确价值的数据。

首版不限定“只能有学习前置”，也不承诺“必须有多种线型”。价值决定留存，实际实例决定类型。
