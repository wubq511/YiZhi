# 数据与消费接口

更新：2026-10-25  
状态：权威数据、统一查询与构建接口、图数据、布局和项目 Skill 已实现；15 项接口测试通过，六次 Skill 对照运行已保存，评审页可供人工查看。

## 1. 结论

需要面向 Agent 和未来画板的机器接口，但不需要另写一套与 Markdown 平行维护的课程内容。

采用 **一份权威知识数据 + 一个知识数据模块（Module）+ 多个消费适配器（Adapter）**：

- 人类阅读：生成三份 Markdown 和一个离线 HTML。
- Agent：通过小型查询接口（Interface）按 ID、关键词、题型、星级、题目和关系精确读取 JSON。
- 未来画板：通过图数据适配器读取经过审核的节点、关系、分组和布局引用。
- 校验与构建：在模块内部统一完成，禁止各消费者自行从 Markdown、SVG 或 DOM 猜测知识语义。

人类文档、Agent 结果和画板图数据都来自同一份知识数据，不形成三套手工同步的内容。

## 2. 与既有原型的关系

既有画板原型只用于查看效果，是过程产物；本任务不迁移、不兼容，也不把它们作为新接口的约束。权威模型只按当前的人类、Agent 和未来画板消费需求设计。

## 3. 模块与接缝

知识数据模块是唯一负责解释知识数据的模块。它把索引、关系遍历、来源检查、引用完整性、评级摘要和视图生成隐藏在小型接口后面。

```text
权威知识数据 ─┐
              ├─ 知识数据模块 ─┬─ Markdown 适配器 → 三份文档
视图布局数据 ─┘      │        ├─ HTML 适配器 → 离线知识地图
                     │        ├─ Agent 适配器 → 精确 JSON 查询
                     │        └─ 画板适配器 → 图数据与视觉绑定
                     └─ 结构、引用、语义、构建一致性检查
```

接缝（Seam）位于模块接口，而不是某个图形库。以后更换画板渲染器，只替换画板适配器，不改课程内容、Agent 查询或其他产物。

### 接口职责

| 操作 | 消费者 | 返回与保证 |
| --- | --- | --- |
| `get` | Agent、画板 | 按稳定 ID 返回一个实体；未知 ID 明确报错 |
| `search` | Agent | 按名称、别名、课次、主题、题型、星级等筛选，结果顺序确定 |
| `related` | Agent、画板 | 查询直接相邻关系；按关系类型、方向和深度显式过滤 |
| `path` | Agent | 在指定关系子图中查路径；不把其他关系混入前置追溯 |
| `questions` | Agent、HTML | 按单元和 `direct / support` 查询关联题目 |
| `graph` | HTML、画板 | 返回某视图的已审核节点、关系、分组和布局引用 |
| `check` | 维护者、Agent | 检查源数据及派生产物，错误包含实体 ID 和原因 |
| `build` | 维护者、Agent | 先校验，再以确定顺序生成全部派生产物并复核 |

查询结果使用稳定 JSON。找不到 ID、非法关系类型和无效参数不能与“查询无结果”混淆；错误以非零状态和机器可读原因返回。

当前数据规模下，每次查询在内存中建立索引即可。暂不额外维护 Agent 专用索引文件；若以后实测性能不足，可在模块实现内部增加缓存而不改变接口。

## 4. 权威数据与稳定身份

### 4.1 核心实体

| 实体 | 保存内容 |
| --- | --- |
| 资料来源 | 来源 ID、类型、标题、工作区相对路径、页数与版本信息 |
| 知识主题 A | 稳定 ID、名称、核心学习表现、主题层评级证据与理由 |
| 知识单元 B | 稳定 ID、主题 ID、类型、名称、掌握目标、简要内容、来源、题型与评级 |
| 题目 | 稳定 ID、来源、题号、小问、题型与原文定位 |
| 题目映射 | 题目 ID、单元 ID、`direct / support`、判断依据与说明 |
| 知识关系 | 稳定 ID、起点、终点、类型、`value`、来源与审核状态 |
| 视图布局 | 布局版本、视觉元素 ID、所引用主题／单元／关系、坐标与尺寸 |

### 4.2 ID 规则

- 主题、单元、题目、关系和视觉元素使用不同 ID 命名空间。
- ID 不编码课次、名称、星级或当前坐标，避免内容变化迫使 ID 改变。
- 名称修改不改变 ID；删除或退休的 ID 不再分配给新内容。
- 需要退休的实体保留显式状态和可选替代目标，避免历史笔记与引用失去含义。
- 画布绑定使用视觉元素 ID；语义关系使用知识单元 ID，二者不得混用。

同一知识主位置只保存一份完整正文。其他区域或视图通过单元 ID 引用，不复制完整内容。

### 4.3 只保存一次的内容

以下内容不重复录入，而由模块计算：

- 主题的下属单元列表、单元峰值和星级分布。
- 单元与题目的反向链接。
- 前置祖先、后继、路径与主题概览连接。
- Markdown 中的关联题目和证据汇总。
- HTML 与画板使用的节点、边、分组和筛选数据。
- 派生产物使用的内容摘要哈希与一致性信息。

## 5. 前置语义必须保留 AND / OR

多条 `requires` 入边默认表示每一项都是必要条件。若出现“掌握 A 或 B 之一即可”的可替代学习路线，必须显式记录路线组：

- 每个路线组属于一个目标单元，并声明 `all / any` 模式。
- 未分组的必要前置与路线组之间按“并且”处理。
- `any` 组内部按“或”处理，例如代数化简与卡诺图可作为不同设计路线。
- Agent 的前置结果保留条件结构，不能压平成“所有节点都必需”的列表。
- 条件结构也参与循环、悬空引用和冗余检查。

路线组只在真实课程关系需要时创建，不用它替代价值关系审核。

## 6. Agent 消费方式

Agent 不优先搜索 Markdown 来推断实体身份，也不直接遍历原始 JSON 自行解释关系，而是调用模块接口：

| 需要 | 使用方式 |
| --- | --- |
| 精确读取一个单元、主题、题目或关系 | `get` 加稳定 ID |
| 按中文名称或别名查找 | `search`，返回 ID、名称、类型和匹配字段 |
| 查找某单元的直接前置或全部前置 | `related`，指定 `requires`、方向和深度；需要条件时返回路线组 |
| 判断两个单元间是否存在指定关系路径 | `path`，指定关系类型 |
| 查找直接考查或支撑某单元的题目 | `questions`，指定映射角色 |
| 获取某主题的单元、峰值、分布和主题证据 | `get` 加主题 ID，摘要由模块计算 |
| 修改或重建资料 | 只修改权威数据或布局，再运行 `build`；用 `check` 复核 |

项目 Skill `.agents/skills/digital-logic-midterm-map/SKILL.md` 承载完整操作流程：查询时使用模块接口，修改时读取对应规则，重建后运行校验，并按任务分支指向本文件、关系规则和验收要求。Skill 采用模型可发现方式，在处理期中知识地图的查询、修改、校验或重建任务时触发；教材原文检索仍由 `digital-logic-textbook` 负责。

`期中/AGENTS.md` 只保留两类进入目录就必须知道的信息：使用上述项目 Skill 的入口，以及课程内容与布局各自的权威修改位置。查询参数、字段定义、评级规则、关系规则和不常用的验收细节均留在原文档，由 Skill 按任务分支指引 Agent 查找，不复制到 `AGENTS.md`。

## 7. 画板消费方式

画板适配器读取 `graph` 结果，不从 SVG、HTML 文本或显示标签反向推断知识关系。

- 节点包含知识单元 ID、显示名称、主题和必要摘要。
- 边包含关系 ID、起点、终点、类型、`value` 和审核状态。
- 主题概览连接由 B–B 关系聚合生成，可下钻到原始关系，不另维护一套 A–A 数据。
- 布局独立于课程内容保存，当前主图、辅助图和全部视图共享一份扁平布局；切换视图仅筛选关系，不复制单元正文。
- 视觉元素 ID 与知识单元 ID 分离；渲染器的绑定只引用视觉元素 ID。
- 内容重建保留未受影响的布局，阅读视口、选中状态和个人笔记不写入课程权威数据。
- 当前只提供图数据接口，不在本任务中迁移旧画板或实现笔记、撤回与真实 Agent 接入。

## 8. 校验与防止多套数据漂移

### 结构与身份

- JSON 可解析，必需字段、枚举和 `schemaVersion` 合法。
- 所有 ID 唯一且符合命名空间；退休 ID 不复用。
- 主题、来源、题目、关系、路线组和布局引用完整。

### 课程语义

- 每条关系都有非空 `value`、方向和来源，并通过价值审核。
- `requires` 只进入明确的必要或路线组语义；循环和非法条件组合被报告。
- 题目映射区分 `direct / support`，没有隐式重复计数。
- 主题具有核心学习表现、主题证据与评级理由；单元峰值和分布只由模块计算。
- 来源文件存在，PDF 页序在有效范围内；教材引用保留双页码。
- 排除内容不进入正式单元；需要人工判断的问题显式记录，不静默跳过。

### 派生与查询

- 从权威数据重新构建到临时位置，与交付文件比较；内容哈希或旧收据本身不作为通过依据。
- Markdown、HTML、Agent 查询与画板图中的 ID、数量、评级和关系一致。
- 重复构建的输出顺序稳定，内容修改不会无意重排已有布局。
- 查询检查覆盖精确 ID、中文搜索、未知 ID、关系过滤、AND / OR 前置、题目角色和 JSON 错误输出。
- HTML 另做真实浏览器交互与离线检查，不用 JSON 校验替代页面验收。

这些检查降低不一致和错误解释的风险，但不能替代对课程语义的人工审核，也不声称格式本身能保证“从不出错”。

## 10. 项目 Skill 与用例

### 入口与职责

- 名称：`digital-logic-midterm-map`。
- 查询、修改、校验或重建期中知识地图时调用；教材原文检索仍使用 `digital-logic-textbook`。
- 查询使用模块返回的稳定 JSON；修改只写权威数据或布局，随后构建并校验。
- Skill 保存步骤、分支和完成标准，具体规则按需引用原文档。
- `期中/AGENTS.md` 保持极简，仅列 Skill 入口和两个权威修改位置。

### 已运行的三个用例

| 用例 | 测试提示 | 检查内容 |
| --- | --- | --- |
| 精确查询与证据 | “在期中知识地图中找‘用译码器实现逻辑函数’，给出单元 ID、主题、重要性、课件页码、直接关联题目和直接前置；不要从 Markdown 猜。” | 稳定 ID、来源、题目角色和前置类型正确 |

评测目录为 `.agents/skills/digital-logic-midterm-map-workspace/iteration-1/`；`eval-*/{with_skill,without_skill}/run-1/` 保存原始 `outputs/`、transcript、timing 与 grading。`review.html` 显示输出和 benchmark，`benchmark.md` 说明采样方式与缺失指标。评审页生成工具使用本机 `python3.12`；课程查询与构建工具使用标准库，不增加运行时第三方依赖。

## 11. 当前实现合同

- 权威数据 `schemaVersion=midterm-map-1`，20 个主题、84 个单元、121 个题目实体、202 条映射、43 条关系；单元 `sourceRefs` 与 `pageCoverage` 双向校验。
- 布局为扁平的 `midterm-layout-1`，顶层含 `groups/nodes/edges`，主图、辅助图和全部关系视图共享该布局。当前不生成 `views[]`，消费者不要假定 `views[0]` 存在。
- 图数据由 `graph --view main|auxiliary|all` 返回。主题聚合边由 B–B 关系计算；视觉元素 ID 与语义 ID 分离。
- `related` 的 `conditions` 仅从 `requires` 边生成，`required` 和 `groups` 引用去重且顺序稳定；非前置边保留为关联信息，不进入必要条件。
- `related/path` 遇到未知关系类型返回非零状态和 `invalid_parameter` JSON；合法查询无路径返回 `paths: []`，与未知 ID 的 `not_found` 区分。
- 临时副本通过 `MIDTERM_MAP_FILE`、`MIDTERM_LAYOUT_FILE`、`MIDTERM_OUTPUT_DIR` 指定；破坏性校验不操作正式数据。
- 评测后修正了未知关系类型、重复组引用与非前置条件混入问题，15 项接口测试和完整 `check` 通过；课程权威数据与布局未改变。原始评测 JSON 保留历史结果（可能含 `groups: [G1,G1]`），当前接口返回 `groups: [G1]`。

查询示例：

```bash
python3 期中/工具/知识地图.py get KU-064
python3 期中/工具/知识地图.py related KU-044 --depth -1
python3 期中/工具/知识地图.py questions KU-064 --role direct
python3 期中/工具/知识地图.py graph --view all
python3 期中/工具/知识地图.py check
```

课程范围与图关系仍需要人工判断。图中记录的教学路线不能推广为对其他合法方法的否定；没有记录一条边也不意味着不存在任何前置。

## 12. 阅读正文与资料版本扩展（2026-10-25）

- 单元可增加 `reading`，扩展版本为 `review-reading-1`。`get <KU>` 原样返回正文；缺少 reading 仍表示正文未完成。`revision/status/blocks/coverage` 与递归块 ID、10 类块、角色、载荷、来源引用、题解和 complete 证据均由 `Store.validate` 校验，并计入原有 sourceHash。
- `sources[*].versions` 保存稳定版本 ID、SHA-256、课程相对路径、显示名和页数。既有引用可保留旧格式；显式 `versionId` 必须匹配所属来源。reading 引用必须有版本；教材另需 `bookPages`，课程笔记用真实 `section`。版本文件是否存在由 `check` 检查，实际摘要由来源解析器核对。
- `期中/工具/复习内容.py` 提供内容包与来源迁移入口：

  ```bash
  python3 期中/工具/复习内容.py import --map <课程JSON> --package <package.json> --course-root <课程根>
  python3 期中/工具/复习内容.py pin-sources --map <课程JSON>
  ```

  导入按 `baseEntityHashes` 检查目标单元和共享题目，保留其他实体变化；候选课程整体校验后原子写入。重复内容返回 `unchanged`，冲突不覆盖。来源版本只追加，资源放在 `期中/资源/<packageId>/` 命名空间，缺失或冲突不留下半份正文。
- `Store(data, root=...)` 与正式 `KnowledgeCatalog` 使用课程根解析资料路径；临时副本和迁移不再固定到开发机目录。
- 正文包的作者格式、原页证据和验证记录见 `.scratch/review-board-v1/work/02/README.md`；正式应用 API 见 `复习画板/接口.md`。
