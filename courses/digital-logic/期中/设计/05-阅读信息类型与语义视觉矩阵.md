# 阅读信息类型与语义—视觉矩阵

更新：2026-10-27  
状态：语义盘点与阅读场景基线；尚未进入配色实施  
范围：只读分析权威课程数据、既有产品规则和当前实现；不修改 UI、课程内容、布局或个人状态。

## 1. 核心结论

**学生的阅读体验与知识获取是目标；颜色、字体、标注、手绘线条和空间形式都是承载信息的手段。** 手绘不能只被理解为一种表面风格，端正也不能退化为所有信息都使用同一种灰白卡片。

本阶段不采用“一种知识类型对应一种卡片颜色”的简单方案，而采用四个相互独立的分类层：

1. **知识结构**：主题 A、知识单元 B、单元内部内容，以及概念／方法／器件三类单元。
2. **学习用途**：概念与结论、结构与关系、方法与步骤、例题与练习、验证与探索、对比与易错。
3. **表达与显示**：文字、公式、图、表、步骤、交互等表达形式，以及常驻核心、收纳材料、补充说明三种显示角色。
4. **归属与状态**：正式课程、个人内容、Agent 内容；课程重要性、个人复习状态、正文生命周期和系统反馈。

由此得到四条设计约束：

- **表达形式不等于学习用途。** 一张表可以表达定义、条件、对照或验证结果；不能看到表格就赋予固定含义。
- **显示角色不等于重要性。** `core / material / supplement` 决定当前阅读需要与展开方式，不是五星评级。
- **语义角色独立不等于机械增加色相。** 文字、图标、线型、位置、形状和标签必须共同表达；但不允许再用同一个暖黄含混覆盖个人笔记、重要性和异常。
- **一个对象可以同时携带多种语义。** 一个五星单元可以同时是学生的“薄弱”单元，含正式易错提醒和个人笔记。不能用整卡换色把这些信息压成一种状态。

## 2. 权威依据与现状盘点

- 本次源数据哈希：`8a63f6daeb7962be5ab52a10f070a79b2de16de6ece676982ba4ce9daf928759`。
- `graph --view all` 返回 84 个知识单元和 43 条已审核关系；随后逐单元使用 `get` 汇总正文。
- 84 个单元的 `reading.status` 当前均为 `complete`。正文草稿是系统支持的生命周期状态，不是当前课程中仍存在的未完成单元。

### 2.2 知识结构

| 分类 | 当前事实 | 对阅读呈现的含义 |
| --- | --- | --- |
| 知识主题 A | 20 个主题；有独立核心学习表现、整体重要性和下属单元状态汇总 | 服务定位、全览和主题级复习资源分配；不复制一份可编辑的个人掌握状态 |
| 知识单元 B | 84 个单元：概念 29、方法 35、模块 20 | 是完整阅读、独立考查和个人复习状态的基本对象 |
| 单元内部内容 | 定义、公式、条件、方法变体、例题、来源等 | 留在所属单元中，不全部升级为节点或关系边 |
| 题型 | 数制转换、函数化简、逻辑分析、逻辑设计；“基础支撑”是映射状态 | 用于筛选和证据说明，不另造第五种题型，不要求四种固定颜色 |

**决定：三种 B 类型首先影响正文组织，不给概念、方法、器件分别染一种整卡颜色。** 单元类型由明确的类别标签和内部内容结构表达，避免课程画板变成三组色块。

### 2.3 六种学习用途

既有设计讨论已经确认以下六类用途。它们用于检查学习材料是否充足，不是视图分层，也不要求每个单元凑齐六类。

| 学习用途 | 当前数字逻辑内容示例 | 主要阅读任务 | 适合的表达通道 |
| --- | --- | --- | --- |
| 概念与结论 | MUX 选择规则、有效电平、溢出条件 | 理解“是什么、何时成立、得到什么” | 连续正文、准确公式、定义与结论标签、相邻图示 |
| 结构与关系 | 电路结构、真值表、正式前置与构造关系 | 看清组成、对应和路径 | 空间位置、连线、方向、关系标签、表格和对照 |
| 方法与步骤 | 卡诺图圈组、MUX 数据端求法、组合设计流程 | 能按顺序执行并检查结果 | 有序步骤、判断条件、必要示意、可审查中间结果 |
| 例题与练习 | 完整示范解法、自测、提示与答案 | 先理解示范，再独立检验 | 明确的材料类型、例题完整讲解、练习按需揭示、答案性质 |
| 验证与探索 | 改变 MUX 选择码、检查译码器使能、观察卡诺图跨边相邻 | 改变条件并理解输出为何变化 | 输入控制、当前值、路径与输出、文字结论；不能只有颜色变化 |
| 对比与易错 | 无符号进位与补码溢出、有效电平、适用边界、反例 | 区分相似概念并避免错误迁移 | 对照结构、边界标签、易错说明、反例和必要提醒 |

补充说明、个人笔记、来源引用、重要性和复习状态附着在这些内容上，但不属于这六种学习用途的第七类。

### 2.4 表达形式与显示角色

当前权威正文递归包含 **1214 个块**，包括子块：

| `kind` | 数量 | 主要表达职责 |
| --- | ---: | --- |
| `paragraph` | 194 | 连续解释、定义、说明 |
| `formula` | 50 | 可编辑、准确排版的数学表达 |
| `figure` | 82 | 电路、卡诺图、结构和语义图示 |
| `table` | 200 | 功能表、对照、条件与结果 |
| `steps` | 312 | 有序方法、推导和解题过程 |
| `callout` | 65 | 当前正文中的重点提醒容器；具体学习意图仍需从内容判断 |
| `knowledge-reference` | 53 | 回到另一知识主位置，不是来源引用 |
| `example` | 157 | 展开后直接阅读完整示范解法 |
| `exercise` | 94 | 先作答，再按需查看提示和答案；其中 93 个有提示 |
| `interactive` | 7 | 改变条件、观察路径和输出 |

三种 `role` 的数量为：

- `core`：580，当前理解或操作必需，保持常驻。
- `material`：618，已经备齐、按需原位展开的材料。
- `supplement`：16，主内容之外的补充说明。

**决定：`kind` 决定适合的组件与交互形式，`role` 决定显示深度；二者都不直接决定颜色。** 尤其不能把 `material` 理解为次要内容，也不能把 `supplement` 当成个人笔记。

### 2.5 证据、关系与答案性质

- 正式关系包括 `requires` 30、`constructs` 9、`improves` 3、`inverse` 1；主关系 28、辅助关系 15。
- 多条必要前置默认是 AND；可替代路线必须保留显式 `any` 组。`KU-044` 的真实例子是：**必须有 `KU-029`，并且 `G1` 中的 `KU-033 / KU-035` 二选一**。
- 例题和练习的答案性质包括：`official-solution` 44、`derived-solution` 53、`self-test` 84、`authored-example` 70。
- 来源引用、知识引用、题目映射角色和正式知识关系是不同信息。直接考查／前置支撑不自动等于学习前置。

## 3. 当前视觉语义冲突

以下不是“颜色用得不够多”，而是同一颜色承担了过多不能互相替代的含义。

### 3.1 暖黄与橙色家族

当前或预留样式同时用于：

- 主题与单元的重要性星级；
- 正式正文中的 `callout`；
- 练习提示；
- 个人笔记与个人纸张感；
- 正文草稿状态；
- 保存中与未保存草稿；
- 来源／搜索警告；
- Agent 等待学生决定的提示；
- 个人内容待重新关联、交互语义“需核对”等编辑状态。

在 65 个 `callout` 中，55 个显式使用 `amber`，5 个未提供 `tone` 并由前端回退为暖黄，合计 **60 个实际落为暖黄**；只有 5 个使用蓝色，没有实际绿色 `callout`。这些提醒覆盖：

- 适用边界和能力边界；
- 易错点、反例与相似概念辨析；
- 方法原则与操作警示；
- 原理解释和疑问；
- 来源核对、原页勘误与采用口径。

例如 `KU-006` 的“求补码时还有减法？！”是理解引导，`KU-035` 的“不能只按先圈最大的圈贪心”是方法警示，`KU-067` 是来源勘误。它们不能仅凭同一个 `callout + amber` 被当成同一种信息。

### 3.2 蓝色与绿色

- 蓝色同时出现在输入条件、地址与坐标、知识引用、来源入口、普通学习动作和部分易错提醒中；个人图形标注默认也使用蓝色。
- 绿色同时出现在选中信号、输出与验证、解答与答案、交互输出、按下状态、保存成功以及构造关系中。
- 这些使用有的可以共享一个较大的语义家族，有的必须拆分。下一步应依据共存场景判断，而不是笼统规定“蓝等于条件、绿等于一切正确”。

### 3.3 关系与个人箭头

- 正式主关系主要用灰蓝，构造关系用绿色，辅助关系用紫色系。
- 个人箭头默认蓝色且允许学生选色。
- 因此**颜色不能证明一条箭头是正式知识事实还是个人联想**。正式关系必须有明确入口、类型、方向、价值、来源和审核状态；个人标注保留自由颜色与独立身份。

## 4. 语义—视觉矩阵

本节确定的是**语义角色与视觉通道**，不是最终 HEX 色板。具体色相、明度、浅底和对比度由下一步 `colorize` 在真实页面中确定。

### 4.1 正式知识与学习材料

| 信息语义 | 权威依据或识别方式 | 主视觉通道 | 颜色方向 | 必须同时保留的非颜色线索 |
| --- | --- | --- | --- | --- |
| 普通定义、解释与连续正文 | 正式 `reading`、段落与掌握目标 | 端正排版、舒适行长与行距、白底或极浅中性底 | 石墨墨色与中性色为主 | 完整句子、标题、术语解释 |
| 输入条件、适用前提、控制条件 | 正文内容、功能表、公式和交互配置 | 条件与对应输入相邻，必要时常驻 | 延续蓝色家族候选，收窄其职责 | “条件／输入／使能”标签、变量名、表格结构 |
| 结论、选中路径、输出与验证结果 | 正文结论、交互计算结果、推导结果 | 从条件到结果的路径连续，结果靠近对应操作 | 延续绿色家族候选，不能扩展成所有正向状态 | “结论／输出／验证”标签、数值、公式和文字解释 |
| 方法与执行步骤 | `steps`、方法单元和可检查操作 | 有序编号、判断分支、必要中间结果 | 以中性正文为主，重点步骤局部强调 | 步骤号、动作动词、顺序与判断条件 |
| 学习边界、易错与方法警示 | `callout` 的具体学习意图；当前没有独立机器语义字段 | 原位提醒、明确小标题、必要时对照或反例 | 新建独立“学习警示”角色，与个人暖黄和系统错误分开 | “适用边界／易错／方法提醒”等具体标签 |
| 理解引导、疑问与原理解释 | 正文内容；不能仅按 `callout` 判断 | 作为解释的一部分连续阅读，不伪装成异常 | 中性或解释性颜色，不进入警示色 | 问题句、解释句、与对应概念的距离 |
| 例题与示范解法 | `example`、答案性质、完整子块 | 材料标签与原位展开；完整解法直接可读 | 题干保持中性；结论和验证局部使用结果色 | “例题”标签、题目来源、答案性质、完整步骤 |
| 练习、提示与答案 | `exercise`、提示与答案的独立揭示状态 | 先题目，后提示，再答案；三种状态清楚 | 练习题干中性；提示使用独立“学习辅助”角色；答案沿用结果语义 | “练习／提示／答案与步骤”文字和展开状态 |
| 验证与探索 | `interactive`、输入、当前值、输出 | 控制、路径、数值和结论同步变化 | 控件状态与知识结果分色；不能因按钮按下就自动等于正确结论 | 当前输入值、输出文字、操作反馈和可恢复状态 |
| 对比与来源口径 | 对照表、说明、来源引用及具体正文 | 对照结构为主，来源说明为辅 | 来源核对使用中性的证据角色；影响正确性的内容另加学习警示 | 原页位置、采用口径、差异说明；不只用红／黄表示 |

**关于 `callout` 的限制：** 当前 `kind=callout` 与 `payload.tone` 不能提供足够的学习意图。后续可以在呈现层增加明确语义标签；是否扩展 reading schema 需另行决定，本阶段不修改数据合同，也不根据现有颜色批量猜测新类型。

### 4.2 归属、课程元信息与个人状态

| 信息语义 | 权威依据 | 主视觉通道 | 颜色方向 | 必须同时保留的非颜色线索 |
| --- | --- | --- | --- | --- |
| 正式课程内容 | 权威知识数据、稳定单元与块 ID、来源证据 | 知识主位置和连续正文 | 内容语义色，不加入个人归属色 | 正式标题、来源、稳定身份 |
| 个人笔记 | 独立个人数据、对象或片段锚点 | 个人纸张、笔记标签、原位附着与笔记库 | **保留个人暖黄，但不再给重要性和异常复用** | “个人笔记”标签、作者归属、原引用与关联状态 |
| 个人图形标注 | 独立 annotations、工具类型与学生选色 | 自由手绘线条、形状、高亮和个人覆盖层 | 保留学生选色；不强制全部改成暖黄 | 编辑工具名称、个人内容库、与正式关系不同的入口 |
| 课程重要性 | A／B 独立评级、主题峰值与分布、证据 | 星级、数字、排序和证据入口，位于元信息区 | 新建独立“课程优先级”角色，与暖黄分开 | 一至五星、对象名称、评级理由；不代表难度或掌握 |
| 待复习／薄弱／已掌握 | B 的个人三态；A 只汇总 | 状态选择、筛选和汇总，位于元信息区 | 三个独立复习状态角色；薄弱不是系统错误，已掌握不自动等于内容结论 | 完整状态文字、图标或形状、数量汇总 |
| 知识引用 | `knowledge-reference.targetUnitId` 与 `intent` | 明确的“回看知识主位置”动作和返回路径 | 可延续知识导航色，但与来源入口区分 | 目标单元、引用意图、返回入口 |
| 来源引用与答案性质 | `sourceRefs`、资料版本、页码、`answerNature` | 证据元信息和原文阅读区 | 中性证据色为主，不抢占正文 | 来源名称、版本、页码、答案性质和原页行为 |
| 正文草稿 | `reading.status=draft` | 内容生命周期提示，位于所属正文顶部 | 独立“内容未验收”角色，不等于个人未保存草稿 | “正文草稿，尚未完成证据与阅读验收”完整说明 |

### 4.3 关系、系统与 Agent 反馈

| 信息语义 | 权威依据 | 主视觉通道 | 颜色方向 | 必须同时保留的非颜色线索 |
| --- | --- | --- | --- | --- |
| 正式关系类型 | `requires / constructs / improves / inverse` 及审核状态 | 方向、关系标签、路径和必要的线型 | 颜色只作辅助，不用颜色证明关系类型 | 类型文字、方向、`value`、来源与审核状态 |
| 主关系／辅助关系 | `view=main / auxiliary` | 默认显示、按需展开、筛选和密度控制 | 不用紫色代替“辅助”的完整说明 | “主关系／当前相关／全部关系”控制与数量 |
| AND／OR 前置条件 | `conditions.required`、`requirementGroups.mode` | 分组、括合、路径结构与明确条件文案 | 不只靠不同颜色区分 AND 与 OR | “必须”与“任选其一”等文字、组成员和路线组 ID |
| 个人箭头与正式关系的区别 | annotations 与正式 relation 是不同实体 | 独立创建入口、标签、线型和详情 | 个人可选色与正式关系色不得被当作审核证据 | “个人标注”身份；正式关系完整审核信息 |
| 保存中／已保存 | 真实持久化回执 | 轻量系统状态，不打断阅读 | 进度与成功状态独立于学习蓝绿语义 | “保存中／已保存到课程”文字与真实回执 |
| 未保存草稿 | 浏览器草稿与未确认提交 | 恢复入口和草稿范围说明 | 独立“待保存”状态，不借用个人笔记暖黄 | “发现未保存草稿”、恢复／处理动作 |
| 保存失败／冲突 | 持久化失败、CAS 或版本冲突 | 明确、可操作且不打断保留内容的反馈 | 独立系统错误／冲突色，不与学习警示共用 | 失败原因、重试、保留本地／使用已保存等具体动作 |
| 来源与搜索异常 | 无可靠文本、原页不可用、搜索失败 | 来源区或搜索区内的局部反馈 | 独立系统警告色，不污染对应知识内容 | 能做什么、不能做什么、原页替代路径 |
| Agent 等待学生决定 | `prompts`、资料更新和权限请求 | 侧栏决策卡、动作分组与结果反馈 | 使用独立的“待决策／动作”语义，不沿用个人暖黄 | 决策原因、影响对象、完整按钮文字 |
| 个人内容待重新关联 | 个人锚点状态与原引用 | 保留个人内容身份，再叠加关联状态 | 个人归属与系统警告双通道，不整卡染成错误色 | “待重新关联”说明、原语境、重新关联入口 |
| 交互语义需核对 | 公式或内容修改后无法保证旧交互结论 | 所属交互附近的局部提示 | 系统核对状态，不等于课程易错点 | “需核对”文字、失效原因和后续处理 |

### 4.4 同一对象的视觉分层

为了避免多重语义争夺同一张卡片的背景色，固定以下层次：

1. **正文层**：定义、条件、方法、结论、例题和正式提醒，在内容原位表达。
2. **元信息层**：重要性、复习状态、类型与来源，位于标题、摘要或证据区，不支配整卡底色。
3. **个人层**：笔记和标注保持独立身份，可以附着与覆盖，但不能遮住正文或冒充正式关系。
4. **系统层**：保存、冲突、来源异常和 Agent 决策在相应控件、侧栏或通知区表达，不把整门课或整个知识单元染成异常色。

**注意力优先级：** 阻塞或需要处理的系统问题先被看见；当前阅读任务保持主体；正式学习警示在原位可见；重要性与复习状态可扫描但不持续抢占正文；个人强调由学生控制。颜色剂量应服从这一顺序。

## 5. 代表性阅读场景

以下场景使用真实课程对象。标注为“脚本化状态”的组合仅用于后续视觉验收，**本次没有写入或修改任何真实个人状态**。

### 场景 A：主题全览与复习资源分配

- **真实对象**：`TH-08`“卡诺图基础与化简”，主题整体重要性五星，包含 5 个单元；其中包括 `KU-035`。
- **学生任务**：判断主题是否值得优先投入，查看包含哪些单元及当前复习进展，再进入第一个需要阅读的单元。
- **同屏信息**：主题核心学习表现、A 的整体星级、单元峰值／分布、B 的重要性、B 的三态汇总、主题聚合关系。
- **通过标准**：A 的整体评级不被误解为由 B 平均或峰值计算；主题汇总不是另一份可编辑掌握状态；关系线帮助定位而不遮住标题和摘要；重要性与复习状态无需依赖颜色即可区分。

### 场景 B：概念理解与交互验证

- **真实对象**：`KU-055`“MUX 功能与 2:1/4:1 表达式”，概念单元，重要性五星。
- **真实内容**：定义、两个公式、MUX 交互、例题和练习。
- **学生任务**：先理解选择端与数据端，再改变选择码，观察哪一路被选中及输出为何变化。
- **同屏信息**：输入条件、当前控件值、选中路径、输出结果、公式、例题与练习入口。
- **通过标准**：条件到输出的路径和文字结论可追踪；按钮按下状态不与知识结论混为一色；关闭颜色后仍能凭标签、数值和线型理解；图、公式和解释不需要跨卡片寻找。

### 场景 C：方法学习、正式警示与个人复习并存

- **真实对象**：`KU-035`“2–4 变量卡诺图化简”，方法单元，重要性五星。
- **真实内容**：知识引用、跨边相邻交互、执行步骤、正式提醒“不能只按先圈最大的圈贪心”、完整例题和带提示练习。
- **脚本化状态**：学生把该单元标为“薄弱”，写下个人笔记并对一个圈组加个人高亮。
- **学生任务**：理解必要质蕴含的选择原则，沿步骤操作，随后借助提示自测并记录自己的疑问。
- **通过标准**：课程重要性、个人薄弱状态、正式方法警示、练习提示、个人笔记和个人高亮各自可辨；不出现一整张黄卡同时承担所有含义；个人标注不被当成正式圈组或知识事实。

### 场景 D：器件条件、有效电平与来源核对

- **真实对象**：`KU-063`“74LS138 端口、有效电平与使能”，模块单元，重要性四星。
- **真实内容**：使能表、有效电平提醒、地址公式、译码器交互、例题、练习与课程来源。
- **学生任务**：先判断使能，再判断地址和输出；遇到符号疑问时核对指定版本原页。
- **通过标准**：使能与有效电平等必要条件保持常驻；正式易错提醒不被看成系统报错；来源区异常不影响正文语义；端口、低有效标记、文字和输出共同表达，不依赖颜色记忆。

### 场景 E：正式前置与可替代路线

- **真实对象**：`KU-044`“组合逻辑设计流程”。
- **权威关系**：`KU-029` 是必要前置；`G1` 为 `any`，包含 `KU-033`“代数法化简”和 `KU-035`“2–4 变量卡诺图化简”。关系 `REL-043 / REL-010 / REL-011` 均有明确价值与来源。
- **学生任务**：理解开始设计前必须具备什么，以及两条化简路线为何可以按题目选择。
- **通过标准**：界面明确表达“`KU-029` 必需，且 `KU-033 / KU-035` 任选其一”；不会把两条路线显示成共同必需，也不会只凭两种线色猜测 AND／OR；辅助关系与主关系的显示级别不被当成真实性等级。

### 场景 F：个人内容与系统反馈冲突压力测试

- **承载对象**：沿用 `KU-035` 的正文和个人笔记；这是脚本化压力场景，不是默认界面。
- **脚本化状态**：个人笔记待重新关联，浏览器存在未保存草稿，随后出现保存冲突；同时来源页没有可靠文本，Agent 请求学生决定是否调整“已掌握”状态。
- **学生任务**：保留自己的内容，理解哪些问题需要处理、分别有什么后果，并继续能够阅读正文。
- **通过标准**：个人笔记、未保存草稿、保存冲突、来源限制和 Agent 待决策不会全部变成相同暖黄；每项都有具体文字与下一步动作；系统问题不错误改变课程重要性或掌握状态；个人内容和原引用始终可见。

## 6. 后续设计边界

本阶段已经确定：

- 以六种学习用途组织阅读语义，以十种块和三种显示角色组织表达，不混为一套分类。
- 暖黄需要拆分；个人笔记、课程重要性、学习警示、练习提示、正文草稿、保存状态和 Agent 待决策不再是同一语义角色。
- 颜色不是唯一的信息通道，也不是每种元数据都需要专属整卡底色。
- 手绘、字体、标注、图、表、公式和交互必须围绕学生的阅读任务共同设计。

本阶段没有决定：

- 新色板的 HEX／OKLCH 数值、各色浅底与最终对比度；
- 是否新增 reading 的学习意图字段或只调整呈现层语义标签；
- 字体尺寸、行长、行距和间距的具体修改；
- 任何 UI、课程内容、布局或个人状态变更。

**下一步只进入 `impeccable · colorize`：** 依据第 4 节角色和第 5 节场景，提出可检查的语义色板、颜色剂量和非颜色提示，优先验证场景 B、C、F。`typeset` 与 `layout` 后续分别推进，不在本轮顺带展开。
